# Agent rules: site source

The root [`AGENTS.md`](../AGENTS.md) still applies; this file adds the rules
specific to `src/`, the React side of the site. Reasoning lives in
[`AGENTS_REFERENCE.md`](../AGENTS_REFERENCE.md#project-layout).

## Where things go

| Path             | Holds                                                                 |
| ---------------- | --------------------------------------------------------------------- |
| `components/`    | reusable React/MDX components, one kebab-case folder each             |
| `theme/`         | swizzled Docusaurus internals, plus `MDXComponents.js`                |
| `utils/`         | non-UI helpers shared by more than one component                      |
| `data/`          | `plugins.json` (hand-edited) and `plugins-generated.json` (generated) |
|                  | `youtube-videos.json` (hand-edited) for video structured data         |
| `css/`, `pages/` | global styles, standalone non-docs pages                              |

Anything with UI belongs in `components/`, not `utils/`. Add a plugin to the
list by editing `data/plugins.json`; `plugins-generated.json` is committed but
regenerated by `npm run enrich:plugins` (nightly, via
`.github/workflows/update-plugins-data.yml`), so never hand-edit it.

Embedding a new YouTube video with `<DocsVideo>`? Add its ID to
`data/youtube-videos.json` with the `uploadDate` from YouTube (plus the
`description` and `duration` when you have them). `components/video-youtube`
reads it to add the video's `VideoObject` JSON-LD to `<head>`. Without an
`uploadDate`, the JSON-LD is skipped with a build warning, and a `src` without
a valid 11-character video ID fails the build and the dev server.

`sectionTitles.js` maps a section to its `<title>` suffix. Page frontmatter
never repeats that suffix, and `cypress/e2e/page_titles.cy.ts` asserts it.

## Adding a component

1. Create `components/<kebab-case>/index.tsx` plus a `style.module.css`
   alongside it when it needs styles.
2. Build it from the `@cypress-design/react-*` primitives (`Button`, `Icon`,
   `Select`) rather than hand-rolling a control. Add the package to the **root**
   `package.json` if the one you need isn't installed.
3. Register it in `theme/MDXComponents.js`: add the import **and** add the name
   to the exported object. Miss the second and MDX renders it as literal text.

Interactive chrome needs `data-sanitize`, which is how `plugins/llm` strips it
from the markdown export so an agent doesn't read a button it cannot click. Put
it on the outermost purely-interactive element (see `components/markdown-actions`)
or on just the controls when the surrounding content should still ship (see
`components/copy-prompt`).

## Working in `theme/`

These are **swizzled** copies of Docusaurus components, ejected from
`@docusaurus/theme-classic`. Two consequences worth keeping in mind:

- A Docusaurus upgrade can change the original out from under a copy, so diff
  against upstream before assuming a file is ours alone.
- Keep each one close to the original. Swizzled files are for the smallest
  change that achieves the goal, not a place to refactor.

`utils/markdown-url.ts` is deliberately shared by `components/markdown-actions`
and `theme/DocItem/Layout`, so the `.md` route and the `<link rel="alternate">`
tag cannot drift apart. Change the helper, not one caller.

## Verifying

- `npm run typecheck` covers `src/` and `cypress/` (see `tsconfig.json`).
- `npm run test:search` for `theme/SearchBar/searchRanking.js` and the Algolia
  scripts.
- `npm run build` for anything that affects the LLM export or page metadata.
