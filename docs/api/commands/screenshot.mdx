# screenshot

Take a screenshot of the application under test and, optionally, the
[Cypress Command Log](/app/core-concepts/open-mode#Command-Log).

## Syntax

```javascript
.screenshot()
.screenshot(fileName)
.screenshot(options)
.screenshot(fileName, options)

// ---or---

cy.screenshot()
cy.screenshot(fileName)
cy.screenshot(options)
cy.screenshot(fileName, options)
```

### Usage

<Icon name="check-circle" color="green" /> **Correct Usage**

```javascript
cy.screenshot()
cy.get('.post').screenshot()
cy.window().screenshot()
```

<Icon name="exclamation-triangle" color="red" /> **Incorrect Usage**

```javascript
cy.get('li').screenshot() // Errors when 'li' matches more than one element
```

### Arguments

<Icon name="angle-right" /> **fileName _(String)_**

A name for the image file, relative to the
[screenshots folder](/app/references/configuration#Folders--Files) and the
path to the spec file. When passed a path, Cypress creates the folder structure.
See the [Naming conventions](/api/commands/screenshot#Naming-conventions) below
for more.

<Icon name="angle-right" /> **options _(Object)_**

Pass in an options object to change the default behavior of `.screenshot()`.

| Option                       | Default                                                     | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ---------------------------- | ----------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `log`                        | `true`                                                      | Displays the command in the [Command log](/app/core-concepts/open-mode#Command-Log)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `blackout`                   | `[]`                                                        | Array of string selectors used to match elements that should be blacked out when the screenshot is taken. Does not apply to `runner` captures.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `capture`                    | `'fullPage'`                                                | Which parts of the Cypress Test Runner to capture. This value is ignored for element screenshot captures. Valid values are `viewport`, `fullPage`, or `runner`. When `viewport`, the application under test is captured in the current viewport. When `fullPage`, the application under test is captured in its entirety from top to bottom. When `runner`, the entire browser viewport, including the Cypress Command Log, is captured. For screenshots automatically taken on test failure, capture is always coerced to `runner`. When the Runner UI is hidden, which is the default when [Test Replay](/cloud/features/test-replay) is enabled during `cypress run` and also happens with [`--no-runner-ui`](/app/references/command-line#cypress-run-no-runner-ui), a `runner` screenshot doesn't include the Runner UI and captures only the application under test in the current viewport. |
| `clip`                       | `null`                                                      | Position and dimensions (in pixels) used to crop the final screenshot image. Should have the following shape: `{ x: 0, y: 0, width: 100, height: 100 }`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `disableTimersAndAnimations` | `true`                                                      | When true, prevents JavaScript timers (`setTimeout`, `setInterval`, etc) and CSS animations from running while the screenshot is taken.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `padding`                    | `null`                                                      | Padding used to alter the dimensions of a screenshot of an element. It can either be a number, or an array of up to four numbers [using CSS shorthand notation](https://developer.mozilla.org/en-US/docs/Web/CSS/Shorthand_properties). This property is only applied for element screenshots and is ignored for all other types.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `scale`                      | `false`                                                     | Whether to scale the app to fit into the browser viewport. This is always coerced to `true` when `capture` is `runner`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `timeout`                    | [`responseTimeout`](/app/references/configuration#Timeouts) | Time to wait for `.screenshot()` to resolve before [timing out](#Timeouts)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `overwrite`                  | `false`                                                     | Whether to overwrite duplicate screenshot files with the same file name when saving.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `onBeforeScreenshot`         | `null`                                                      | A callback before a non-failure screenshot is taken. The argument is a jQuery-wrapped element: the element being captured for an element screenshot, or the document's root `<html>` element for other screenshots.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `onAfterScreenshot`          | `null`                                                      | A callback after a non-failure screenshot is taken. The first argument is a jQuery-wrapped element: the element being captured for an element screenshot, or the document's root `<html>` element for other screenshots. The second argument is properties concerning the screenshot, including the `path` it was saved to and the `dimensions` of the saved screenshot.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |

For more details on these options and to set some as defaults across all uses of
`.screenshot()`, see the
[Cypress.Screenshot API doc](/api/cypress-api/screenshot-api).

<HeaderYields />

- `.screenshot()` yields the same subject it was given.
- It is [unsafe](/app/core-concepts/retry-ability#Only-queries-are-retried)
  to chain further commands that rely on the subject after `.screenshot()`.

## Examples

The screenshot will be stored in the `cypress/screenshots` folder by default.
You can change the directory where screenshots are saved in the
[Cypress configuration](/app/references/configuration#Folders--Files).

### No Args

#### Take a screenshot

```javascript
// cypress/e2e/users.cy.js

describe('my tests', () => {
  it('takes a screenshot', () => {
    // screenshot will be saved as
    // cypress/screenshots/users.cy.js/my tests -- takes a screenshot.png
    cy.screenshot()
  })
})
```

### Filename

#### Take a screenshot and save as a specific filename

```javascript
// screenshot will be saved as
// cypress/screenshots/spec.cy.js/clicking-on-nav.png
cy.screenshot('clicking-on-nav')
```

#### Take a screenshot and save in a specific directory

```javascript
// screenshot will be saved as
// cypress/screenshots/spec.cy.js/actions/login/clicking-login.png
cy.screenshot('actions/login/clicking-login')
```

#### Overwrite a baseline screenshot instead of numbering a new copy

By default, a second screenshot with the same name is saved as
`checkout-baseline (1).png`. With `overwrite: true`, it replaces
`checkout-baseline.png`, so the file always holds the latest capture.

```javascript
cy.screenshot('checkout-baseline', { overwrite: true })
```

### Capture

#### Capture the viewport, the full page, or the whole Cypress runner

The `capture` option decides how much of the browser ends up in the image.

```javascript
cy.screenshot('viewport', { capture: 'viewport' })
cy.screenshot('full-page', { capture: 'fullPage' })
cy.screenshot('runner', { capture: 'runner' })
```

`viewport` captures the part of the application under test that's currently
visible, here 800 x 500 pixels:

<DocsImage
  src="/img/api/screenshot/capture-viewport-shows-visible-part-of-app.png"
  alt="Viewport capture showing the top three posts of the Team updates page, cut off at the bottom of the viewport"
/>

`fullPage`, the default, scrolls through the application under test and
captures it from top to bottom:

<DocsImage
  src="/img/api/screenshot/capture-fullpage-shows-entire-app.png"
  alt="Full page capture showing the Team updates page from its header to its last post"
/>

`runner` captures the entire browser window, including the Command Log, with
the three `screenshot` commands from the example:

<DocsImage
  src="/img/api/screenshot/capture-runner-shows-command-log-and-app.png"
  alt="Runner capture showing the Cypress Command Log with three screenshot commands beside the application under test"
/>

### Clip

#### Crop a screenshot to a specific position and size

```javascript
// screenshot will be clipped 20px from the top and left
// to the dimensions 400px x 300px
cy.screenshot({ clip: { x: 20, y: 20, width: 400, height: 300 } })
```

### Blackout

#### Black out dynamic content such as timestamps and avatars

Content that changes between runs, such as relative timestamps or user avatars,
makes screenshots of the same page differ from run to run. `blackout` covers
every element that matches a selector with a black box, keeping the layout
intact:

```javascript
cy.screenshot('dashboard', { blackout: ['.timestamp', '[data-cy=avatar]'] })
```

<DocsImage
  src="/img/api/screenshot/blackout-covers-timestamps-and-avatars.png"
  alt="Team updates page where every avatar and every Posted timestamp is covered by a black box"
/>

`blackout` applies to `viewport` and `fullPage` captures only. A `runner`
capture ignores it.

### Screenshot an element

#### Take a screenshot of the first `.post` element

```javascript
cy.get('.post').first().screenshot()
```

#### Take a screenshot of the first `.post` element with 10px of padding around it

```javascript
cy.get('.post').first().screenshot({ padding: 10 })
```

#### Add different padding to each side of an element screenshot

`padding` accepts [CSS shorthand](https://developer.mozilla.org/en-US/docs/Web/CSS/Shorthand_properties)
as an array of one to four numbers:

```javascript
// 10px above and below, 20px left and right
cy.get('.post')
  .first()
  .screenshot({ padding: [10, 20] })
```

Without padding, the image ends at the element's border:

<DocsImage
  src="/img/api/screenshot/element-screenshot-without-padding.png"
  alt="Element screenshot of a single post card, cropped exactly at its border"
/>

With `padding: [10, 20]`, the image includes 10px of the page above and below
the element and 20px on each side:

<DocsImage
  src="/img/api/screenshot/element-screenshot-with-padding.png"
  alt="The same post card with a narrow band of the gray page background around it, wider on the left and right"
/>

#### Screenshot an element inside `.within()`

Inside [`.within()`](/api/commands/within), `cy.screenshot()` captures the
`.within()` subject, even when chained off `cy`. Pass `capture: 'runner'` to
capture the whole runner instead.

```javascript
cy.get('.post')
  .first()
  .within(() => {
    cy.screenshot('first-post') // captures only the first .post
    cy.screenshot('first-post-runner', { capture: 'runner' }) // ignores .within()
  })
```

#### Chain off the screenshot to click the element captured

```javascript
cy.get('button').first().screenshot().click()
```

### Change the page only for the screenshot with `onBeforeScreenshot`

`onBeforeScreenshot` runs right before the capture and `onAfterScreenshot`
right after it, so a change made in the first and undone in the second never
affects the rest of the test. Here a cookie banner is hidden for the screenshot
and shown again afterward:

```javascript
cy.screenshot('home', {
  onBeforeScreenshot($el) {
    $el.find('.cookie-banner').hide()
  },
  onAfterScreenshot($el) {
    $el.find('.cookie-banner').show()
  },
})
```

Unlike [`blackout`](#Blackout), which covers an element and keeps its space,
hiding an element removes it from the image entirely.

### Override the screenshot defaults for a single screenshot

Defaults set with
[`Cypress.Screenshot.defaults()`](/api/cypress-api/screenshot-api), usually in
a support file, apply to every `cy.screenshot()`:

```javascript title="cypress/support/e2e.js"
Cypress.Screenshot.defaults({
  blackout: ['.timestamp', '[data-cy=avatar]'],
})
```

An option passed to `cy.screenshot()` replaces the default for that screenshot
rather than merging with it:

```javascript
// uses the default blackout list
cy.screenshot('dashboard')
// replaces the default list: only h2 elements are blacked out
cy.screenshot('dashboard-titles', { blackout: ['h2'] })
```

### Take a screenshot at several viewport sizes

To check a responsive layout, loop over
[`cy.viewport()`](/api/commands/viewport) presets and name each screenshot
after its size. This saves `home-iphone-x.png`, `home-ipad-2.png`, and
`home-macbook-15.png`:

```javascript
const sizes = ['iphone-x', 'ipad-2', 'macbook-15']

sizes.forEach((size) => {
  cy.viewport(size)
  cy.screenshot(`home-${size}`)
})
```

### Get screenshot info from the `onAfterScreenshot` callback

```javascript
cy.screenshot('my-screenshot', {
  onAfterScreenshot($el, props) {
    // $el is the jQuery-wrapped <html> element, since no element was chained
    // props has information about the screenshot,
    // including but not limited to the following:
    // {
    //   name: 'my-screenshot',
    //   path: '/Users/janelane/project/cypress/screenshots/spec.cy.js/my-screenshot.png',
    //   size: 15360, // in bytes
    //   dimensions: {
    //     width: 1000,
    //     height: 660,
    //   },
    //   multipart: false,
    //   pixelRatio: 1,
    //   takenAt: '2026-11-01T17:00:00.000Z',
    //   scaled: false,
    //   blackout: [],
    //   duration: 2300, // in milliseconds
    //   testAttemptIndex: 0,
    // }
  },
})
```

## Notes

### Naming conventions

Screenshot naming follows these rules:

- Screenshots are saved inside the
  [screenshots folder](/app/core-concepts/writing-and-organizing-tests#How-asset-file-paths-are-generated).
  Inside that folder, the screenshot is saved inside a folder structure relative
  to the path of the spec file, which is adjusted to remove any common ancestor
  paths shared with all other spec files. Inside this folder, the screenshot
  will be saved with the test name:
  `{screenshotsFolder}/{adjustedSpecPath}/{testName}.png`.
- For a named screenshot, the name is used instead of the suites and test name:
  `{screenshotsFolder}/{adjustedSpecPath}/{name}.png`.
- For any duplicate screenshots (named or not), they will be appended with a
  number: `{screenshotsFolder}/{adjustedSpecPath}/{testName} (1).png`. This
  also applies across several `cypress run` processes that share a project
  folder, so one run never overwrites another run's screenshot.

:::info

This behavior can be changed by passing the `{overwrite: true}` option to
`cy.screenshot()` to explicitly overwrite duplicate screenshots.

:::

- For a failure screenshot, the default naming scheme is used and the name is
  appended with ` (failed)`:
  ```javascript
  {screenshotsFolder}/{adjustedSpecPath}/{testName} (failed).png
  ```
- For a screenshot taken during a
  [test retry](/app/guides/test-retries#Screenshots), the name is appended
  with ` (attempt {n})`, such as `{testName} (attempt 2).png` or
  `{testName} (failed) (attempt 2).png`.
- Characters that aren't valid in a filename are removed from the name, and a
  name too long for the file system is truncated.

For example, given a spec file located at `cypress/e2e/users/login.cy.js`:

```javascript
describe('my tests', () => {
  it('takes a screenshot', () => {
    // NOTE: This file has multiple screenshots
    // each screenshot has a common ancestor path of `/users/`.
    // In this scenario `/users/` is stripped from the path.
    // cypress/screenshots/login.cy.js/my tests -- takes a screenshot.png
    cy.screenshot()
    // cypress/screenshots/login.cy.js/my tests -- takes a screenshot (1).png
    cy.screenshot()
    // cypress/screenshots/login.cy.js/my tests -- takes a screenshot (2).png
    cy.screenshot()

    // cypress/screenshots/login.cy.js/my-screenshot.png
    cy.screenshot('my-screenshot')
    // cypress/screenshots/login.cy.js/my-screenshot (1).png
    cy.screenshot('my-screenshot')
    // cypress/screenshots/login.cy.js/my/nested/screenshot.png
    cy.screenshot('my/nested/screenshot')

    // if this test fails, the screenshot will be saved to
    // cypress/screenshots/login.cy.js/my tests -- takes a screenshot (failed).png
  })
})
```

:::info

To learn more about how to write and organize tests and how assets are saved,
see
[Writing And Organizing Tests](/app/core-concepts/writing-and-organizing-tests#Generated-assets)

:::

### `after:screenshot` plugin event

You can get details about any given screenshot and manipulate it after it has
been written to disk with the
[`after:screenshot` plugin event](/api/node-events/after-screenshot-api).

### Test Failures

#### Automatic screenshots on test failure

When running through `cypress run` or in
[Continuous Integration](/app/continuous-integration/overview), Cypress
automatically takes a screenshot when a test fails. To turn this off, set
[`screenshotOnRunFailure`](/app/references/configuration#Screenshots) to `false`
in your Cypress configuration or with
[`Cypress.Screenshot.defaults()`](/api/cypress-api/screenshot-api).

### Viewing Screenshots

#### Screenshots in CI

You can see screenshots taken during a CI run in
[Cypress Cloud](https://on.cypress.io/cloud) without any extra work.

Alternatively, to see screenshots in your Continuous Integration UI, most CI
providers document a way to export the screenshots as artifacts and to make them
available. See their appropriate documentation.

### Asynchronous

#### Understanding when the screenshot is taken

Taking a screenshot is an asynchronous action that takes around `100ms` to
complete. By the time the screenshot is taken, _it is possible something in your
application may have changed_. It is important to realize that the screenshot
may not reflect what your application looked like 100% when the command was
issued.

For example - say a command we wrote timed out:
[`cy.get('#element')`](/api/commands/get). This causes your test to fail.
Cypress then automatically takes a screenshot when the test fails, but it is
possible something in your application changed within this `100ms` timeframe.
Hypothetically, your app could render the element you were originally expecting
to be present. When this happens, the screenshot may provide confusing results.
It is unlikely, but theoretically possible.

Another potential problem to be aware of is that our own Command Log is using
React under the hood and only rendering asynchronously during an animation
frame. It is possible you will see screenshots taken before our Command Log is
done rendering. This means you may not see the **error displayed** in the
screenshot. But this is also why we allow taking a video - to show you the
complete failure.

We make our best effort to synchronize taking a screenshot with our renderer,
but the current state of your application under test could have changed in the
meantime and not be an accurate representation of what you want to capture.

### Full page captures and fixed/sticky elements

When passing `fullPage` to the `capture` option, Cypress scrolls the application
under test from top to bottom, takes screenshots at each point and stitches them
together. Due to this, elements that are `position: fixed` or `position: sticky`
will appear multiple times in the final screenshot. To prevent this, in most
cases you can programmatically change the element to be `position: absolute`
before the screenshot and change it back afterwards like shown below:

```javascript
cy.get('.sticky-header').invoke('css', 'position', 'absolute')
cy.screenshot()
cy.get('.sticky-header').invoke('css', 'position', null)
```

In this full-page capture, the page's `position: fixed` cookie banner appears
twice, once at the bottom of each part of the page Cypress captured:

<DocsImage
  src="/img/api/screenshot/fullpage-fixed-banner-repeats.png"
  alt="Full page capture of the Team updates page with the yellow cookie banner appearing twice, once over the middle of the page and once at the bottom"
/>

For an element that the screenshot doesn't need, such as a cookie banner,
[hide it with `onBeforeScreenshot`](#Change-the-page-only-for-the-screenshot-with-onBeforeScreenshot)
instead. The same capture then has no banner at all:

<DocsImage
  src="/img/api/screenshot/fullpage-banner-hidden-by-onbeforescreenshot.png"
  alt="Full page capture of the same Team updates page with no cookie banner"
/>

### Chromium-specific behavior with regard to tabs

Chromium will not capture screenshots when the renderer process for the Cypress
tab is paused. This most often happens if a new tab was opened by clicking on
an anchor with `target="_blank"`. To accommodate capturing screenshots in this
situation, Cypress will attempt to activate the Cypress tab when a screenshot is
captured. We make our best effort to activate the tab via our Chromium extension.
If the extension is disabled, Cypress will force the main tab to the front. This
will cause the browser to steal focus in open mode. To prevent Cypress from
stealing focus, [ensure that the extension is enabled](/app/references/troubleshooting#Allow-the-Cypress-Chrome-extension).

## Rules

<HeaderRequirements />

- `cy.screenshot()` can be chained off of `cy` or off a command that yields a
  single DOM element, the `window`, or the `document`.
- `cy.screenshot()` will throw an error if the subject contains more than one
  element.
- Inside [`.within()`](/api/commands/within), `cy.screenshot()` captures the
  `.within()` subject element, unless `capture` is `'runner'`.

<HeaderAssertions />

- `cy.screenshot()` will only run assertions you have chained once, and will not
  [retry](/app/core-concepts/retry-ability).

<HeaderTimeouts />

- `cy.screenshot()` can time out waiting for the browser to capture and save the
  screenshot, for the duration of its `timeout` option, which defaults to
  [`responseTimeout`](/app/references/configuration#Timeouts).
