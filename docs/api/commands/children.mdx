# children

Get the children of each DOM element within a set of DOM elements.

`.children()` travels a single level down the DOM tree, as opposed to
[`.find()`](/api/commands/find), which searches every descendant.

:::info

The querying behavior of this command matches exactly how
[`.children()`](https://api.jquery.com/children) works in jQuery.

:::

## Syntax

```javascript
.children()
.children(selector)
.children(options)
.children(selector, options)
```

### Usage

<Icon name="check-circle" color="green" /> **Correct Usage**

```javascript
cy.get('nav').children() // Yield children of nav
cy.get('nav').children('.active') // Yield children of nav with class '.active'
```

<Icon name="exclamation-triangle" color="red" /> **Incorrect Usage**

```javascript
cy.children() // Errors, cannot be chained off 'cy'
cy.clock().children() // Errors, 'clock' does not yield DOM elements
```

### Arguments

<Icon name="angle-right" /> **selector _(String selector)_**

A selector used to filter matching DOM elements.

<Icon name="angle-right" /> **options _(Object)_**

Pass in an options object to change the default behavior of `.children()`.

| Option    | Default                                                           | Description                                                                         |
| --------- | ----------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| `log`     | `true`                                                            | Displays the command in the [Command log](/app/core-concepts/open-mode#Command-Log) |
| `timeout` | [`defaultCommandTimeout`](/app/references/configuration#Timeouts) | Time to wait for `.children()` to resolve before [timing out](#Timeouts)            |

<HeaderYields />

- `.children()` yields the new DOM element(s) it found.
- `.children()` is a query, and it is _safe_ to chain further commands.

## Examples

### No Args

#### Get the children of the `.secondary-nav`

```html
<ul>
  <li>About</li>
  <li>
    Services
    <ul class="secondary-nav">
      <li class="services-1">Web Design</li>
      <li class="services-2">Logo Design</li>
      <li class="services-3">
        Print Design
        <ul class="tertiary-nav">
          <li>Signage</li>
          <li>T-Shirt</li>
          <li>Business Cards</li>
        </ul>
      </li>
    </ul>
  </li>
  <li>Contact</li>
</ul>
```

```javascript
// yields [
//  <li class="services-1">Web Design</li>,
//  <li class="services-2">Logo Design</li>,
//  <li class="services-3">Print Design<ul class="tertiary-nav">…</ul></li>
// ]
cy.get('ul.secondary-nav').children()
```

The three `<li>` elements inside `ul.tertiary-nav` are descendants of
`ul.secondary-nav`, not children of it, so they are not part of the result. The
`<li class="services-3">` that contains them is yielded whole, nested list and
all.

### Selector

#### Get the children with class `active`

```html
<div>
  <ul>
    <li class="active">Unit Testing</li>
    <li>Integration Testing</li>
  </ul>
</div>
```

```javascript
// yields [
//  <li class="active">Unit Testing</li>
// ]
cy.get('ul').children('.active')
```

## Notes

### Shadow DOM boundaries and `.children()`

`.children()` stops at a shadow boundary. Called on a shadow host, it yields
the children written inside that host in the page's markup, not the elements
inside its shadow root. This holds whether or not
[`includeShadowDom`](/app/references/configuration#Global) is enabled, since
that option applies to [`cy.get()`](/api/commands/get#Arguments),
[`.find()`](/api/commands/find#Arguments), and
[`cy.contains()`](/api/commands/contains#Arguments). To query inside a shadow
root, traverse into it with [`.shadow()`](/api/commands/shadow) first.

## Rules

<HeaderRequirements />

- `.children()` requires being chained off a command that yields DOM element(s)
  or a document.

<HeaderAssertions />

- `.children()` will automatically [retry](/app/core-concepts/retry-ability)
  until the element(s)
  [exist in the DOM](/app/core-concepts/introduction-to-cypress#Implicit-Assertions).
- `.children()` will automatically [retry](/app/core-concepts/retry-ability)
  until all chained assertions have passed.

<HeaderTimeouts />

- `.children()` can time out waiting for the element(s) to
  [exist in the DOM](/app/core-concepts/introduction-to-cypress#Implicit-Assertions).
- `.children()` can time out waiting for assertions you've added to pass.
