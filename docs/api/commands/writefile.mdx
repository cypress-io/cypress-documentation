# writeFile

`cy.writeFile()` writes text, JSON, or binary data to a file on disk from your
test. Your spec code runs in the browser, which can't reach the file system, so
Cypress hands the contents to its server, which writes the file. It resolves the
path from your project root and creates any missing folders, so file output
stays in your test code, with no [`cy.task()`](/api/commands/task) to register
in your config.

Reach for `cy.writeFile()` when you need to:

- [Turn a live response into a fixture](#Generate-a-fixture-file-and-stub-a-request-with-it)
  and stub requests with it
- Save output your test produces, such as a
  [log file](#Build-a-log-file-one-line-at-a-time), a
  [CSV file](#Write-an-array-as-CSV-or-lines-of-text), or a JSON report
- [Save a binary file](#Save-a-binary-file-from-a-request), such as an image
  from a request or a `<canvas>` element

To read a file back, use [`cy.readFile()`](/api/commands/readfile). For file
operations `cy.writeFile()` doesn't cover, such as deleting a file, use
[`cy.task()`](/api/commands/task).

## Syntax

```javascript
cy.writeFile(filePath, contents)
cy.writeFile(filePath, contents, encoding)
cy.writeFile(filePath, contents, options)
cy.writeFile(filePath, contents, encoding, options)
```

### Usage

<Icon name="check-circle" color="green" /> **Correct Usage**

```javascript
cy.writeFile('menu.json', { lunch: 'soup' })
```

### Arguments

<Icon name="angle-right" /> **filePath _(String)_**

A path to a file, resolved relative to the project root (the directory that
contains the [Cypress configuration file](/app/references/configuration)). An
absolute path also works. Cypress creates any missing directories in the path.

<Icon name="angle-right" /> **contents _(String, Array, Object, or Buffer)_**

The contents to write to the file. Cypress writes a String or a `Buffer` as is,
and converts an Array or Object to JSON indented with 2 spaces.

<Icon name="angle-right" /> **encoding _(String)_**

The encoding Cypress uses to write the file. The following encodings are
supported:

- `'ascii'`
- `'base64'`
- `'binary'`
- `'hex'`
- `'latin1'`
- `'utf8'`
- `'utf-8'`
- `'ucs2'`
- `'ucs-2'`
- `'utf16le'`
- `'utf-16le'`
- `null`

Passing `null` explicitly writes a `Buffer` directly, without first encoding it
as a string.

<Icon name="angle-right" /> **options _(Object)_**

Pass in an options object to change the default behavior of `cy.writeFile()`.

| Option     | Default                                                           | Description                                                                                         |
| ---------- | ----------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `encoding` | `utf8`                                                            | The encoding Cypress uses to write the file                                                         |
| `flag`     | `w`                                                               | File system flag as used with [`fs.writeFile`](https://nodejs.org/api/fs.html#fs_file_system_flags) |
| `log`      | `true`                                                            | Displays the command in the [Command Log](/app/core-concepts/open-mode#Command-Log)                 |
| `timeout`  | [`defaultCommandTimeout`](/app/references/configuration#Timeouts) | Time to wait for `cy.writeFile()` to resolve before [timing out](#Timeouts)                         |

<HeaderYields />

- `cy.writeFile()` yields `null`.

## Examples

### Text

#### Write text to a `.txt` file

If the file or any directory in its path doesn't exist, Cypress creates it. If
the file already exists, Cypress overwrites it.

```javascript
cy.writeFile('path/to/message.txt', 'Hello World')
cy.readFile('path/to/message.txt').then((text) => {
  expect(text).to.equal('Hello World')
})
```

`{projectRoot}/path/to/message.txt` is created with the following contents:

```text
Hello World
```

#### Write an array as CSV or lines of text

An array is written as JSON, not as one line per item. To write a CSV file or
other line-based text, join the array into a string first.

```javascript
const rows = ['name,email', 'Eliza,eliza@example.com']

cy.writeFile('path/to/users.csv', rows.join('\n'))
```

`{projectRoot}/path/to/users.csv` is created with the following contents:

```text
name,email
Eliza,eliza@example.com
```

### JSON

#### Write JSON to a file

Cypress converts arrays and objects to JSON indented with 2 spaces.

```typescript copyTsToJs title="spec.cy.ts"
type User = { name: string; email: string }

const user: User = { name: 'Eliza', email: 'eliza@example.com' }

cy.writeFile('path/to/data.json', user)
cy.readFile<User>('path/to/data.json').then((saved) => {
  expect(saved.name).to.equal('Eliza')
})
```

`{projectRoot}/path/to/data.json` is created with the following contents:

```json
{
  "name": "Eliza",
  "email": "eliza@example.com"
}
```

#### Generate a fixture file and stub a request with it

Save response data under `cypress/fixtures/`, and the file works like any other
fixture. Here [`cy.intercept()`](/api/commands/intercept) serves it as the
response to your app's request.

```javascript
cy.request('https://jsonplaceholder.cypress.io/users').then((response) => {
  cy.writeFile('cypress/fixtures/users.json', response.body)
})

cy.intercept('GET', '/api/users', { fixture: 'users.json' }).as('getUsers')
cy.visit('/users')
cy.wait('@getUsers')
```

Write the file before you add the intercept. `cy.intercept()` reads a fixture
when it registers the route, so writing the file afterwards doesn't change the
response. See
[How Cypress caches fixture data](/api/commands/fixture#How-Cypress-caches-fixture-data).

#### Add properties to an existing JSON file

The `a+` flag appends text, so it can't merge JSON. Read the file, add the new
properties, then write the combined result back. In TypeScript, pass a type
argument to `cy.readFile()` so the yielded object has the file's shape.

```typescript copyTsToJs title="spec.cy.ts"
type User = { name: string; id?: string }

const filename = 'path/to/file.json'

cy.readFile<User>(filename).then((user) => {
  user.id = '1234'
  // write the merged object
  cy.writeFile(filename, user)
})
```

#### Add items to an existing JSON array

```typescript copyTsToJs title="spec.cy.ts"
type Item = { item: string }

const filename = 'path/to/list.json'

cy.readFile<Item[]>(filename).then((list) => {
  list.push({ item: 'example' })
  // write the merged array
  cy.writeFile(filename, list)
})
```

### Encoding

#### Specify the encoding as a string argument

```javascript
cy.writeFile('path/to/ascii.txt', 'Hello World', 'ascii')
```

`{projectRoot}/path/to/ascii.txt` is created with the following contents:

```text
Hello World
```

#### Specify the encoding as part of the options object

```javascript
cy.writeFile('path/to/ascii.txt', 'Hello World', { encoding: 'ascii' })
```

#### Save a binary file from a request

Request the file with `encoding: 'binary'`, then write the response body with
the same encoding so the bytes reach the disk unchanged.

```javascript
cy.request({
  url: 'https://example.cypress.io/assets/img/javascript-logo.png',
  encoding: 'binary',
}).then((response) => {
  cy.writeFile('path/to/logo.png', response.body, 'binary')
})
```

#### Decode a base64 string into a file

With the `base64` encoding, Cypress decodes the string and writes the
resulting bytes. This example saves the image drawn on a `<canvas>` element.

```javascript
cy.get('canvas')
  .invoke('get', 0)
  .invoke('toDataURL', 'image/png')
  .then((dataUrl) => {
    const base64 = dataUrl.split(',')[1]

    cy.writeFile('path/to/chart.png', base64, 'base64')
  })
```

### Flags

#### Build a log file one line at a time

Pass `flag: 'a+'` to add contents to the end of the file instead of
overwriting it. Appending adds the contents exactly as passed, with no
separator, so end each entry with `\n` to keep entries on their own lines. The
first write uses the default `w` flag, so each run starts with an empty log.

```javascript
cy.writeFile('path/to/run.log', 'Test started\n')
cy.writeFile('path/to/run.log', 'Logged in\n', { flag: 'a+' })
cy.writeFile('path/to/run.log', 'Checkout complete\n', { flag: 'a+' })
```

`{projectRoot}/path/to/run.log` contains:

```text
Test started
Logged in
Checkout complete
```

### Buffer

#### Write a buffer directly without encoding as a string

Read a file with a `null` encoding to get a `Buffer`, then write it with a
`null` encoding to copy the bytes unchanged.

```javascript
cy.readFile('path/to/logo.png', null).then((buffer) => {
  // <Buffer 89 50 4e 47 ... >
  cy.writeFile('path/to/logo-copy.png', buffer, null)
})
```

### Options

#### Keep a large response out of the Command Log

The console output for `cy.writeFile()` includes the full contents written.
Pass `log: false` to hide the command when the contents are large or
sensitive.

```javascript
cy.request('https://jsonplaceholder.cypress.io/photos').then((response) => {
  cy.writeFile('cypress/fixtures/photos.json', response.body, { log: false })
})
```

#### Allow more time for a large write

```javascript
const largeText = 'x'.repeat(50 * 1024 * 1024)

cy.writeFile('path/to/large.txt', largeText, { timeout: 15000 })
```

## Notes

### How the `encoding` argument and option combine

When you pass both an `encoding` argument and an `encoding` option, the option
takes precedence. This call writes the string as UTF-8 text, not as decoded
hex:

```javascript
cy.writeFile('path/to/message.txt', '48656c6c6f', 'hex', { encoding: 'utf8' })
```

### How `cy.writeFile()` updates the fixture cache

Writing a file inside the
[`fixturesFolder`](/app/references/configuration#Folders--Files) clears that
file from the [`cy.fixture()`](/api/commands/fixture) cache, so a later
`cy.fixture()` call yields the new contents.

## Rules

<HeaderRequirements />

- `cy.writeFile()` requires being chained off of `cy`.
- `cy.writeFile()` must be invoked from the spec file or support file.
- `cy.writeFile()` requires the file be successfully written to disk. Anything
  preventing this, such as OS permission issues, causes it to fail.

<HeaderAssertions />

- `cy.writeFile()` runs assertions you have chained once, and does not
  [retry](/app/core-concepts/retry-ability).

<HeaderTimeouts />

- `cy.writeFile()` can time out when writing the file takes longer than the
  `timeout` option.
