# clearAllCookies

Clear all browser cookies across every domain.

While [`cy.clearCookies()`](/api/commands/clearcookies) clears cookies for a
single domain, `cy.clearAllCookies()` doesn't read the current URL, so it works
without [`cy.origin()`](/api/commands/origin) even after your app navigates to
another origin.

:::caution

Cypress automatically clears all cookies _before_ each test to prevent state
from being shared across tests when
[test isolation](/app/core-concepts/writing-and-organizing-tests#Test-Isolation)
is enabled. You shouldn't need to use this command unless you're using it to
clear all cookies inside a single test or test isolation is disabled.

:::

## Syntax

```javascript
cy.clearAllCookies()
cy.clearAllCookies(options)
```

### Usage

<Icon name="check-circle" color="green" /> **Correct Usage**

```javascript
cy.clearAllCookies() // Clear all cookies
```

### Arguments

<Icon name="angle-right" /> **options _(Object)_**

Pass in an options object to change the default behavior of
`cy.clearAllCookies()`.

| Option    | Default                                                     | Description                                                                         |
| --------- | ----------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| `log`     | `true`                                                      | Displays the command in the [Command log](/app/core-concepts/open-mode#Command-Log) |
| `timeout` | [`responseTimeout`](/app/references/configuration#Timeouts) | Time to wait for `cy.clearAllCookies()` to resolve before [timing out](#Timeouts)   |

<HeaderYields />

- `cy.clearAllCookies()` yields `null`.

## Examples

### No Args

#### Clear cookies set by multiple domains <E2EOnlyBadge />

In this example, logging in through an identity provider sets cookies on both
the identity provider's domain and your app's domain. `cy.clearAllCookies()`
clears the cookies from both in one command.

```javascript
cy.contains('Log in').click()
cy.origin('https://example.cypress.io', () => {
  cy.get('[type=password]').type('*****')
  cy.contains('Log in').click()
})
cy.url().should('include', 'profile')
cy.getAllCookies().should('have.length', 2)
cy.clearAllCookies()
cy.getAllCookies().should('be.empty')
```

#### Log out in the middle of a test <E2EOnlyBadge />

Clearing every cookie removes your app's session cookie along with any cookies
the identity provider set, so the next request arrives logged out. In this
example, the app redirects unauthenticated visitors to its login page.

```javascript
cy.visit('/dashboard')
cy.clearAllCookies()
cy.reload()
cy.url().should('include', 'login')
```

#### Clear cookies before each test when test isolation is off

With [test isolation](/app/core-concepts/test-isolation) turned off, cookies
from one test carry over to the next. Call `cy.clearAllCookies()` in a
`beforeEach` hook to start every test in the suite without cookies.

```javascript
describe('Account settings', { testIsolation: false }, () => {
  beforeEach(() => {
    cy.clearAllCookies()
  })

  it('shows the login prompt', () => {
    // no cookies from earlier tests are present
  })
})
```

### Options

#### Clear cookies without logging to the Command Log

Pass `{ log: false }` to keep `cy.clearAllCookies()` out of the
[Command Log](/app/core-concepts/open-mode#Command-Log), which is useful when it
runs in a hook before every test.

```javascript
cy.clearAllCookies({ log: false })
```

## Rules

<HeaderRequirements />

- `cy.clearAllCookies()` requires being chained off of `cy`.

<HeaderAssertions />

- `cy.clearAllCookies()` yields `null`, so there's nothing to assert on. To
  confirm the cookies are cleared, assert on
  [`cy.getAllCookies()`](/api/commands/getallcookies) afterward, for example
  `cy.getAllCookies().should('be.empty')`.

<HeaderTimeouts />

- `cy.clearAllCookies()` should never time out.

:::caution

Because `cy.clearAllCookies()` is asynchronous it is technically possible for
there to be a timeout while talking to the internal Cypress automation APIs. But
for practical purposes it should never happen.

:::
