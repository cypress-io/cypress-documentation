# getCookie

Get a browser cookie by its name.

## Syntax

```javascript
cy.getCookie(name)
cy.getCookie(name, options)
```

### Usage

<Icon name="check-circle" color="green" /> **Correct Usage**

```javascript
cy.getCookie('auth_key') // Get cookie with name 'auth_key'
```

<Icon name="exclamation-triangle" color="red" /> **Incorrect Usage**

```javascript
cy.getCookie() // Errors, a cookie name is required
cy.getCookie({ domain: 'example.com' }) // Errors, name must be a string
```

### Arguments

<Icon name="angle-right" /> **name _(String)_**

The name of the cookie to get. Required, and must be a string.

<Icon name="angle-right" /> **options _(Object)_**

Pass in an options object to change the default behavior of `cy.getCookie()`.

| Option    | Default                                                           | Description                                                                         |
| --------- | ----------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| `domain`  | Hostname of the application under test                            | Retrieves the cookie from the specified domain                                      |
| `log`     | `true`                                                            | Displays the command in the [Command log](/app/core-concepts/open-mode#Command-Log) |
| `timeout` | [`defaultCommandTimeout`](/app/references/configuration#Timeouts) | Time to wait for `cy.getCookie()` to resolve before [timing out](#Timeouts)         |

<HeaderYields />

`cy.getCookie()` yields a cookie object with the following properties:

- `domain`: _(String)_
- `expiry`: _(Number)_ _(if specified)_
- `hostOnly`: _(Boolean)_ _(if specified)_
- `httpOnly`: _(Boolean)_
- `name`: _(String)_
- `path`: _(String)_
- `sameSite`: _(String)_ _(if specified)_
- `secure`: _(Boolean)_
- `value`: _(String)_

`cy.getCookie()` is a query, and it is _safe_ to chain further commands. It
re-reads the cookie on each [retry](/app/core-concepts/retry-ability), and the
assertions you chain with [`.should()`](/api/commands/should) drive those
retries. If an assertion fails, because the cookie is `null` or because a
property doesn't match yet, the query reads the cookie again and re-runs the
assertion until it passes or the command times out.

With no assertion chained, `cy.getCookie()` yields whatever it reads on the
first attempt. A [`.then()`](/api/commands/then) callback runs once and isn't
retried, so chain `.should('exist')` before it to wait for a cookie that your
application sets asynchronously.

#### When a cookie matching the name could not be found:

`cy.getCookie()` yields `null`.

## Examples

### Session id

#### Get `session_id` cookie after logging in

In this example, your server sends back a session cookie on login.

```javascript
// assume the user just logged in
cy.contains('Login').click()
cy.url().should('include', 'profile')
// retries until cookie with value=189jd09su
// is found or default command timeout ends
cy.getCookie('session_id')
  .should('have.property', 'value', '189jd09su')
  .then((cookie) => {
    // cookie is an object with "domain", "name" and other properties
  })
```

To check that the cookie exists without comparing any of its properties, assert
`exist`:

```javascript
cy.getCookie('my-session-cookie').should('exist')
```

#### Send the session cookie's value in a request header

To pass the cookie's value to a later command, chain
[`.its('value')`](/api/commands/its) and use the value inside
[`.then()`](/api/commands/then). Cypress runs the callback after `.its()`
finds the value, so `cy.request()` gets the current value rather than one read
when the test queued its commands.

```javascript
cy.getCookie('session_id')
  .its('value')
  .then((token) => {
    cy.request({
      url: '/api/admin',
      headers: {
        'my-token-x': token,
      },
    })
  })
```

#### Check that the session cookie is removed after logout

Assert `not.exist` to confirm a cookie is gone. The query retries until the
assertion passes, so it waits for a logout request that clears the cookie after
a short delay.

```javascript
cy.contains('Log out').click()
cy.getCookie('session_id').should('not.exist')
```

#### Using `cy.getCookie()` to test logging in

:::info

The [Logging In recipes](/app/references/recipes#Logging-In) use
`cy.getCookie()` to test logging in with HTML web forms, XHR web forms, and
single sign-on.

:::

### Cookie properties

#### Assert on one cookie property with `.its()`

[`.its()`](/api/commands/its) yields a single property of the cookie. Because
`.its()` is also a query, the assertion still retries `cy.getCookie()`, so the
test waits for a cookie that hasn't been set yet.

```javascript
cy.getCookie('csrf_token').its('value').should('have.length', 32)
```

#### Check the security attributes of an auth cookie

Assert `include` with the attributes your server must set. The assertion passes
when the cookie has every listed property with the listed value.

```javascript
cy.getCookie('session_id').should('include', {
  httpOnly: true,
  secure: true,
  sameSite: 'strict',
})
```

`sameSite` is `'lax'`, `'strict'`, or `'no_restriction'` (the value for
`SameSite=None`). For a cookie set without a `SameSite` attribute, Firefox
reports `'unspecified'`, and Chromium-based browsers and WebKit leave the
property off.

#### Check that a remember-me cookie expires in the future

`expiry` is the time the cookie expires, in seconds since the Unix epoch. This
example checks that a cookie lasts at least 29 more days:

```javascript
const twentyNineDays = 29 * 24 * 60 * 60

cy.getCookie('remember_me')
  .its('expiry')
  .should('be.greaterThan', Date.now() / 1000 + twentyNineDays)
```

A session cookie, one that the browser deletes when it closes, has no `expiry`
property, so `.its('expiry')` fails for it.

### Domain

#### Get a cookie set on an API subdomain with `domain`

By default, `cy.getCookie()` reads cookies for the hostname of the application
under test. Pass `domain` to read a cookie set for a different domain, such as
an API that your app calls on its own subdomain.

```javascript
cy.getCookie('refresh_token', { domain: 'api.example.com' }).should('exist')
```

### Sessions and origins

#### Validate a cached login with `cy.session()`

[`cy.session()`](/api/commands/session) saves the browser's cookies when its
setup function finishes, so wait for the session cookie at the end of setup.
Without that wait, a cookie that arrives after the login click is left out of
the cached session.

```javascript
cy.session(
  username,
  () => {
    cy.visit('/login')
    cy.get('#username').type(username)
    cy.get('#password').type(password)
    cy.contains('Log in').click()
    cy.getCookie('session_id').should('exist')
  },
  {
    validate() {
      cy.getCookie('session_id').should('exist')
    },
  }
)
```

When `cy.session()` restores a cached session, `validate` confirms the cookie
came back. A cookie that has expired since it was cached isn't restored, so the
assertion fails after the
[`defaultCommandTimeout`](/app/references/configuration#Timeouts) and
`cy.session()` runs setup again. To confirm that your server still accepts the
session, [validate with a request](/api/commands/session#Validating-the-session)
instead.

#### Read a cookie on another origin with `cy.origin()` <E2EOnlyBadge />

`cy.getCookie()` reads cookies for the origin of the page under test. When the
page is on a different origin from the one your test visited first, such as a
single sign-on provider, run `cy.getCookie()` inside
[`cy.origin()`](/api/commands/origin).

```javascript
cy.visit('/')
cy.contains('Log in with SSO').click()

cy.origin('https://auth.example.com', () => {
  cy.get('#username').type('jane')
  cy.get('#password').type('s3cr3t')
  cy.contains('Sign in').click()
  cy.getCookie('sso_session').should('exist')
})
```

## Notes

### Default cookie domain before visiting a page

<CookieDefaultDomain />

### Matching a cookie by domain in WebKit

In WebKit, `cy.getCookie()` first looks for a cookie whose `domain` exactly
matches the requested domain. If none matches, it falls back to a cookie set on
the parent (apex) domain, such as `example.com` when you request
`app.example.com`.

## Rules

<HeaderRequirements />

- `cy.getCookie()` requires being chained off of `cy`.

<HeaderAssertions />

- `cy.getCookie()` automatically [retries](/app/core-concepts/retry-ability)
  until all chained assertions have passed.

<HeaderTimeouts />

- `cy.getCookie()` can time out waiting for assertions you've added to pass.
- `cy.getCookie()` can time out waiting for the browser to return the cookie.
  Both waits use the
  [`defaultCommandTimeout`](/app/references/configuration#Timeouts) (or the
  `timeout` option, when passed).
- If the application under test is on a different origin, `cy.getCookie()`
  retries until the command times out and then fails with a cross-origin error.
  Run it inside [`cy.origin()`](/api/commands/origin) to read cookies on that
  origin.
- If the browser returns an error while reading the cookie, `cy.getCookie()`
  fails right away instead of retrying.
