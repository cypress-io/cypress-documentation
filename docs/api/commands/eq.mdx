# eq

Get a DOM element at a specific index within a set of DOM elements.

:::info

The querying behavior of this command matches exactly how
[`.eq()`](https://api.jquery.com/eq) works in jQuery.

:::

## Syntax

```javascript
.eq(index)
.eq(indexFromEnd)
.eq(index, options)
.eq(indexFromEnd, options)
```

### Usage

<Icon name="check-circle" color="green" /> **Correct Usage**

```javascript
cy.get('tbody>tr').eq(0) // Yield first 'tr' in 'tbody'
cy.get('ul>li').eq(4) // Yield fifth 'li' in 'ul'
```

<Icon name="exclamation-triangle" color="red" /> **Incorrect Usage**

```javascript
cy.eq(0) // Errors, cannot be chained off 'cy'
cy.getCookies().eq(4) // Errors, 'getCookies' does not yield DOM element
```

### Arguments

<Icon name="angle-right" /> **index _(Number)_**

The position of the element to get within the set of elements, counting from
`0`.

<Icon name="angle-right" /> **indexFromEnd _(Number)_**

A negative number that counts back from the end of the set of elements. `-1` is
the last element.

<Icon name="angle-right" /> **options _(Object)_**

Pass in an options object to change the default behavior of `.eq()`.

| Option    | Default                                                           | Description                                                                         |
| --------- | ----------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| `log`     | `true`                                                            | Displays the command in the [Command log](/app/core-concepts/open-mode#Command-Log) |
| `timeout` | [`defaultCommandTimeout`](/app/references/configuration#Timeouts) | Time to wait for `.eq()` to resolve before [timing out](#Timeouts)                  |

<HeaderYields />

- `.eq()` yields the DOM element at the given index within the set it was given.
- `.eq()` is a query, and it is _safe_ to chain further commands.

## Examples

### Index

#### Get the 2nd list item with `.eq()`

```html
<ul>
  <li>tabby</li>
  <li>siamese</li>
  <li>persian</li>
  <li>sphynx</li>
  <li>burmese</li>
</ul>
```

```javascript
cy.get('li').eq(1).should('contain', 'siamese')
```

#### Assert on the 3rd row of a table with `.eq()`

The header row is a `<tr>` too, so it sits at index `0`.

```html
<table>
  <tr>
    <th>Breed</th>
    <th>Origin</th>
  </tr>
  <tr>
    <td>Siamese</td>
    <td>Thailand</td>
  </tr>
  <tr>
    <td>Sphynx</td>
    <td>Canada</td>
  </tr>
  <tr>
    <td>Persian</td>
    <td>Iran</td>
  </tr>
</table>
```

```javascript
cy.get('tr').eq(2).should('contain', 'Canada')
```

### Index From End

#### Get the 2nd-to-last list item with `.eq()`

```html
<ul>
  <li>tabby</li>
  <li>siamese</li>
  <li>persian</li>
  <li>sphynx</li>
  <li>burmese</li>
</ul>
```

```javascript
cy.get('li').eq(-2).should('contain', 'sphynx')
```

### Common workflows with `.eq()`

#### Wait for the element at an index to render with `.eq()`

`cy.get()` and `.eq()` are both queries, so Cypress re-runs them together until
an element exists at the index. Here, the results render one at a time, and
`.eq(2)` waits for the third one.

```html title="index.html"
<ul class="results"></ul>
<!-- results render one at a time, 500 ms apart: Ada, Grace, Katherine, Margaret -->
```

```javascript title="spec.cy.js"
cy.get('.results li').eq(2).should('have.text', 'Katherine')
```

#### Move a table row up and check its position with `.eq()`

`.eq()` yields a single DOM element, so you can keep chaining queries and actions
off it. It also narrows the set to one element before
[`.within()`](/api/commands/within), which throws an error when its subject
contains more than one element. Here, the test checks where each row ends up, so
the index is what's under test.

```html title="index.html"
<table>
  <tbody>
    <tr>
      <td>Ada</td>
      <td><button>Move up</button></td>
    </tr>
    <tr>
      <td>Grace</td>
      <td><button>Move up</button></td>
    </tr>
  </tbody>
</table>
<!-- clicking Move up swaps its row with the row above it -->
```

```javascript title="spec.cy.js"
cy.get('tbody tr')
  .eq(1)
  .within(() => {
    cy.contains('Move up').click()
  })
cy.get('tbody tr').eq(0).should('contain', 'Grace')
cy.get('tbody tr').eq(1).should('contain', 'Ada')
```

#### Click an item after the list finishes loading with `.eq()`

An action such as [`.click()`](/api/commands/click) is not an assertion, so
`cy.get('[data-cy=result]').eq(3).click()` acts on the element at index `3` at
that moment. If the list renders placeholder rows before the real results, the
element it clicks can be a placeholder. Assert on the finished list before
calling `.eq()`, and Cypress retries the query until the assertion passes.

```html title="index.html"
<ul class="results"></ul>
<!--
  10 placeholder <li> elements render first, then 10 <li data-cy="result">
  elements replace them. Clicking a result adds the class "selected".
-->
```

```javascript title="spec.cy.js"
cy.get('[data-cy=result]').should('have.length', 10).eq(3).click()
cy.get('[data-cy=result]').eq(3).should('have.class', 'selected')
```

#### Assert on a table row after sorting it with `.eq()`

`cy.get()` and `.eq()` are both queries, so Cypress re-runs them together until
the chained assertion passes. After the table re-sorts, the assertion checks
whichever row is at the index _now_, which is what you want when testing sort
order.

```html title="index.html"
<table>
  <thead>
    <tr>
      <th>Name</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>Grace</td>
    </tr>
    <tr>
      <td>Ada</td>
    </tr>
  </tbody>
</table>
<!-- clicking the Name header sorts the rows alphabetically -->
```

```javascript title="spec.cy.js"
cy.contains('th', 'Name').click()
cy.get('tbody tr').eq(0).should('have.text', 'Ada')
cy.get('tbody tr').eq(1).should('have.text', 'Grace')
```

## Notes

### When to use `.eq()` instead of a `data-cy` selector

An index is tied to the order of the elements on the page. When that order
changes, such as a new item added at the top of a list, `.eq()` selects a
different element and the test breaks for a reason unrelated to what it checks.
Use `.eq()` when the position itself is what you're testing, such as sort order
or the newest item in a feed. Otherwise, select the element by a `data-cy`
attribute. Learn more in
[selecting elements](/app/core-concepts/best-practices#Selecting-Elements).

```javascript
// position matters: the first row after sorting
cy.get('tbody tr').eq(0).should('have.text', 'Ada')

// position doesn't matter: the row for a specific user
cy.get('[data-cy=user-ada]').should('be.visible')
```

### How `.eq()` compares to `.first()` and `.last()`

`.eq(0)` yields the same element as [`.first()`](/api/commands/first), and
`.eq(-1)` yields the same element as [`.last()`](/api/commands/last).

### When the index is outside the set

When no element exists at the index, `.eq()` yields an empty set. Cypress
retries until an element appears at the index. If none appears before the
timeout, it fails with an error such as
``Expected to find element: `5`, but never found it.`` To assert that the set has
no element at an index, chain `.should('not.exist')`.

```html
<ul>
  <li>tabby</li>
  <li>siamese</li>
  <li>persian</li>
  <li>sphynx</li>
  <li>burmese</li>
</ul>
```

```javascript
cy.get('li').eq(5).should('not.exist')
```

### How `.eq()` compares to the `:nth-child()` selector

`.eq()` counts across the whole set and yields a single element. The CSS
`:nth-child()` selector counts from `1` within _each_ parent, so it can match
several elements when the set spans more than one parent.

```html
<ul class="fruits">
  <li>Apple</li>
  <li>Banana</li>
</ul>
<ul class="veggies">
  <li>Carrot</li>
  <li>Daikon</li>
</ul>
```

```javascript
cy.get('li').eq(1) // yields <li>Banana</li>
cy.get('li:nth-child(2)') // yields <li>Banana</li> and <li>Daikon</li>
```

### Aliasing the result of `.eq()`

An alias stores the query chain, not the element it found. Each time you use the
alias, Cypress re-runs the chain against the current DOM, so an aliased `.eq()`
yields whichever element is at that index _now_. Learn more in
[aliasing DOM elements](/app/core-concepts/variables-and-aliases#Elements).

```html title="index.html"
<input class="new-todo" />
<ul class="todo-list">
  <li>Buy milk</li>
  <li>Walk dog</li>
</ul>
<!-- pressing Enter in .new-todo adds the text as a new <li> at the top of the list -->
```

```javascript title="spec.cy.js"
cy.get('.todo-list li').eq(1).as('second')
cy.get('@second').should('have.text', 'Walk dog')

cy.get('.new-todo').type('Write docs{enter}')
cy.get('@second').should('have.text', 'Buy milk')
```

## Rules

<HeaderRequirements />

- `.eq()` requires being chained off a command that yields DOM element(s) or a
  document.

<HeaderAssertions />

- `.eq()` will automatically [retry](/app/core-concepts/retry-ability) until
  the element(s)
  [exist in the DOM](/app/core-concepts/introduction-to-cypress#Implicit-Assertions).
- `.eq()` will automatically [retry](/app/core-concepts/retry-ability) until
  all chained assertions have passed.

<HeaderTimeouts />

- `.eq()` can time out waiting for the element(s) to
  [exist in the DOM](/app/core-concepts/introduction-to-cypress#Implicit-Assertions).
- `.eq()` can time out waiting for assertions you've added to pass.
