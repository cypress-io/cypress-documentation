# focus

Focus on a DOM element.

It is [unsafe](/app/core-concepts/retry-ability#Only-queries-are-retried) to
chain further commands that rely on the subject after `.focus()`.

## Syntax

```javascript
.focus()
.focus(options)
```

### Usage

<Icon name="check-circle" color="green" /> **Correct Usage**

```javascript
cy.get('input').first().focus() // Focus on the first input
cy.window().focus() // Focus on the window
```

<Icon name="exclamation-triangle" color="red" /> **Incorrect Usage**

```javascript
cy.focus('#search') // Errors, cannot be chained off 'cy'
cy.get('div:first').focus() // Errors, a plain div is not focusable
```

### Arguments

<Icon name="angle-right" /> **options _(Object)_**

Pass in an options object to change the default behavior of `.focus()`.

| Option    | Default                                                           | Description                                                                         |
| --------- | ----------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| `log`     | `true`                                                            | Displays the command in the [Command log](/app/core-concepts/open-mode#Command-Log) |
| `timeout` | [`defaultCommandTimeout`](/app/references/configuration#Timeouts) | Time to wait for `.focus()` to resolve before [timing out](#Timeouts)               |

<HeaderYields />

- `.focus()` yields the same subject it was given.
- It is [unsafe](/app/core-concepts/retry-ability#Only-queries-are-retried)
  to chain further commands that rely on the subject after `.focus()`.

## Examples

### No Args

#### Focus on an input

```javascript
cy.get('input[name="email"]').focus()
```

#### Focus, type, and blur a textarea

```javascript
cy.get('textarea').focus()
cy.get('textarea').type('Nice Product!')
cy.get('textarea').blur()
```

## Notes

### Actionability

#### Focus is not an action command

`.focus()` is not implemented like other action commands, and does not follow
the same rules of
[waiting for actionability](/app/core-concepts/interacting-with-elements).

`.focus()` is a helpful command used as a shortcut. Normally there's no way for
a user to "focus" an element without causing another action or side effect.
Typically the user would have to click or tab to this element.

Oftentimes using `.focus()` directly is more concise and conveys what you're
trying to test.

If you want the other guarantees of waiting for an element to become actionable,
you should use a different command like [`.click()`](/api/commands/click).

### Blur Events

#### Focusing an element blurs the previously focused element

When a different DOM element already has focus, `.focus()` moves focus away
from it, so that element receives `blur` and `focusout` events. The focused
element then receives `focus` and `focusin` events.

Focusing the window or the `body` does not blur the element that currently has
focus.

### Focusable

#### Can only be called on a valid focusable element

`.focus()` accepts an element that matches one of these selectors:

- `a[href]` or `area[href]`
- `input`, `select`, `textarea`, or `button` without the `disabled` attribute
- `iframe`
- any element with a `tabindex` or `contenteditable` attribute

Any other element, such as a plain `div`, fails the command.

The window and the `body` are the two exceptions, and focusing either one leaves
focus where it is: whichever element held it still does, and
`document.activeElement` is unchanged.

- `cy.window().focus()` fires a `focus` event on the window.
- `cy.get('body').focus()` fires no events, unless the `body` is
  `contenteditable`.

### Browser Focus {#Notes-Browser-Focus}

#### Cypress fires focus events when the browser does not

A browser that is not in focus, for example because you are working in the
developer tools or another window, may not fire focus events when an element is
focused. When this happens, Cypress fires the `focus` and `focusin` events
itself, along with `blur` and `focusout` on the previously focused element, so
your application receives the same events either way.

A browser that is not in focus can still behave differently in other ways, such
as throttling timers. Keep the Cypress browser window focused while a test runs
for the most consistent results.

## Rules

<HeaderRequirements />

- `.focus()` requires being chained off a command that yields a DOM element or
  the window.
- `.focus()` requires the subject to contain a single element.
- `.focus()` requires the element to be able to receive focus. The window and
  the `body` are exempt.

<HeaderAssertions />

- `.focus()` will automatically wait for assertions you have chained to pass.

<HeaderTimeouts />

- `.focus()` can time out waiting for assertions you've added to pass.
