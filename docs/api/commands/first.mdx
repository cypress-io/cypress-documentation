# first

Get the first DOM element within a set of DOM elements.

:::info

The querying behavior of this command matches exactly how
[`.first()`](https://api.jquery.com/first) works in jQuery.

:::

## Syntax

```javascript
.first()
.first(options)
```

### Usage

<Icon name="check-circle" color="green" /> **Correct Usage**

```javascript
cy.get('nav a').first() // Yield first link in nav
```

<Icon name="exclamation-triangle" color="red" /> **Incorrect Usage**

```javascript
cy.first() // Errors, cannot be chained off 'cy'
cy.getCookies().first() // Errors, 'getCookies' does not yield DOM element
```

### Arguments

<Icon name="angle-right" /> **options _(Object)_**

Pass in an options object to change the default behavior of `.first()`.

| Option    | Default                                                           | Description                                                                         |
| --------- | ----------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| `log`     | `true`                                                            | Displays the command in the [Command log](/app/core-concepts/open-mode#Command-Log) |
| `timeout` | [`defaultCommandTimeout`](/app/references/configuration#Timeouts) | Time to wait for `.first()` to resolve before [timing out](#Timeouts)               |

<HeaderYields />

- `.first()` yields the first DOM element within the set it was given.
- `.first()` is a query, and it is _safe_ to chain further commands.

## Examples

### No Args

#### Get the first list item in a list

```html
<ul>
  <li class="one">Knick knack on my thumb</li>
  <li class="two">Knick knack on my shoe</li>
  <li class="three">Knick knack on my knee</li>
  <li class="four">Knick knack on my door</li>
</ul>
```

```javascript
// yields <li class="one">Knick knack on my thumb</li>
cy.get('li').first()
```

#### Get the first element across several lists

`.first()` yields one element for the whole set, however many parents the
elements share. The `:first-child` selector yields the first child of every
parent instead.

```html
<ul class="fruits">
  <li>Apple</li>
  <li>Banana</li>
</ul>
<ul class="vegetables">
  <li>Carrot</li>
  <li>Daikon</li>
</ul>
```

```javascript
// yields <li>Apple</li>
cy.get('ul li').first()

// yields [<li>Apple</li>, <li>Carrot</li>]
cy.get('ul li:first-child')
```

### Workflows

#### Scope `.within()` to the first matching element

[`.within()`](/api/commands/within) throws an error when its subject contains
more than one element. Narrow the set with `.first()` before calling it.

```javascript
cy.get('tr')
  .first()
  .within(() => {
    cy.contains('Edit').click()
  })
```

#### Click the first result after the list finishes loading

An action such as [`.click()`](/api/commands/click) is not an assertion, so
`cy.get('[data-cy=result]').first().click()` acts on the first element that
exists at that moment. If the list renders placeholder rows before the real
results, that can be a placeholder. Assert on the finished list before calling
`.first()`, and Cypress retries the query until the assertion passes.

```javascript
cy.get('[data-cy=result]').should('have.length', 10).first().click()
```

#### Assert on the first element while the list re-renders

`cy.get()` and `.first()` are both queries, so Cypress re-runs them together
until the chained assertion passes. If the list re-renders and a new element
takes the first position, the assertion checks the new element rather than the
one that was first when the query started.

```javascript
cy.get('[data-cy=todo]').first().should('have.text', 'Buy milk')
```

## Notes

### `.first()` and `.eq(0)`

`.first()` yields the same element as [`.eq(0)`](/api/commands/eq). jQuery
implements `.first()` as `.eq(0)`. Use `.eq()` to get an element at any other
index, including negative indexes counted back from the end of the set.

### Selecting the first element that matches a selector

`.first()` takes no selector. Cypress passes the call straight to jQuery's
`.first()`, which ignores any arguments, so `cy.get('li').first('.active')`
yields the first `<li>` whether or not it has the class `active`. To get the
first element that matches a selector, narrow the set with
[`.filter()`](/api/commands/filter) before calling `.first()`.

```javascript
cy.get('li').filter('.active').first()
```

## Rules

<HeaderRequirements />

- `.first()` requires being chained off a command that yields DOM element(s) or
  a document.

<HeaderAssertions />

- `.first()` will automatically [retry](/app/core-concepts/retry-ability)
  until the element(s)
  [exist in the DOM](/app/core-concepts/introduction-to-cypress#Implicit-Assertions).
- `.first()` will automatically [retry](/app/core-concepts/retry-ability)
  until all chained assertions have passed.

<HeaderTimeouts />

- `.first()` can time out waiting for the element(s) to
  [exist in the DOM](/app/core-concepts/introduction-to-cypress#Implicit-Assertions).
- `.first()` can time out waiting for assertions you've added to pass.
