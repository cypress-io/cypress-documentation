# its

Get a property's value on the previously yielded subject.

:::info

If you want to call a `function` on the previously yielded subject, use
[`.invoke()`](/api/commands/invoke).

:::

## Syntax

```javascript
.its(propertyName)
.its(propertyName, options)
```

### Usage

<Icon name="check-circle" color="green" /> **Correct Usage**

```javascript
cy.wrap({ width: '50' }).its('width') // Get the 'width' property
cy.window().its('sessionStorage') // Get the 'sessionStorage' property
```

<Icon name="exclamation-triangle" color="red" /> **Incorrect Usage**

```javascript
cy.its('window') // Errors, cannot be chained off 'cy'
cy.clearCookies().its('length') // Errors, 'clearCookies' does not yield Object
```

### Arguments

<Icon name="angle-right" /> **propertyName _(String, Number)_**

Index, name of property, or path to a nested property to get. A path uses dot
notation (`'body.user'`) and can reach into arrays with a numeric segment or
bracket notation (`'items.1'` or `'items[1]'`).

<Icon name="angle-right" /> **options _(Object)_**

Pass in an options object to change the default behavior of `.its()`.

| Option    | Default                                                           | Description                                                                         |
| --------- | ----------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| `log`     | `true`                                                            | Displays the command in the [Command log](/app/core-concepts/open-mode#Command-Log) |
| `timeout` | [`defaultCommandTimeout`](/app/references/configuration#Timeouts) | Time to wait for `.its()` to resolve before [timing out](#Timeouts)                 |

<HeaderYields />

- `.its()` yields the value of the property.
- `.its()` is a query, and it is _safe_ to chain further commands.

## Examples

### Objects

#### Get property

```javascript
cy.wrap({ age: 52 }).its('age').should('eq', 52) // true
```

### Arrays

#### Get index

```javascript
cy.wrap(['Wai Yan', 'Yu']).its(1).should('eq', 'Yu') // true
```

### DOM elements

#### Get the `length` property of a DOM element

```javascript
cy.get('ul li') // this yields us a jquery object
  .its('length') // gets the 'length' property of that jQuery object
  .should('be.gt', 2) // ensure the length is greater than 2
```

#### Wait for a list to finish rendering with `.its('length')`

`.its()` is a query, so Cypress re-runs [`cy.get()`](/api/commands/get) and
`.its()` together until the assertion passes. If the app renders its list items
over time, this waits until all three are on the page.

```javascript
cy.get('#todo-list li').its('length').should('eq', 3)
```

In the Command Log, `.its()` and its assertion stay pending while the list
renders, then pass once the third item appears.

<DocsImage
  src="/img/api/its/its-length-retries-until-list-renders.gif"
  alt="Command Log retrying its .length while the app renders a todo list one item at a time, then passing the assertion expected 3 to equal 3"
/>

#### Get a property of the DOM element inside the jQuery object

Commands like [`cy.get()`](/api/commands/get) yield a jQuery object. Start the
path with an index to reach the DOM element inside it, then read the element's
own properties, such as the browser's
[validity state](https://developer.mozilla.org/en-US/docs/Web/API/ValidityState).

```javascript
cy.get('#email').type('not-an-email')
cy.get('#email').its('0.validity.valid').should('be.false')
```

### Requests

#### Get the `user` object of the response's `body`

```javascript
cy.request('/users/1')
  .its('body.user')
  .then((user) => {
    // do something with the user
  })
```

Alternatively, get the `body` and destructure it:

```javascript
cy.request('/users/1')
  .its('body')
  .then(({ user }) => {
    // do something with the user
  })
```

### Intercepted requests

[`cy.wait()`](/api/commands/wait) on a [`cy.intercept()`](/api/commands/intercept)
alias yields the interception, so `.its()` can reach into its `request` and
`response`.

#### Assert on the status code of an intercepted response

```javascript
cy.intercept('GET', '/comments').as('getComments')
cy.get('#fetch-comments').click()
cy.wait('@getComments').its('response.statusCode').should('eq', 200)
```

#### Assert on the body of an intercepted request

```javascript
cy.intercept('POST', '/comments').as('postComment')
cy.get('#post-comment').click()
cy.wait('@postComment')
  .its('request.body')
  .should('deep.include', { comment: 'hi' })
```

### Strings

#### Get `length` of title

```javascript
cy.title().its('length').should('eq', 24)
```

### Functions

#### Get function as property

```javascript
const fn = () => {
  return 42
}

cy.wrap({ getNum: fn }).its('getNum').should('be.a', 'function')
```

#### Access function properties

You can access functions to then drill into their own properties instead of
invoking them.

```javascript title="app.js"
// a basic Factory constructor
function Factory(arg) {
  this.arg = arg
}

Factory.create = (arg) => {
  return new Factory(arg)
}

// assign it to the window
window.Factory = Factory
```

```javascript title="spec.cy.js"
cy.window() // yields window object
  .its('Factory') // yields Factory function
  .invoke('create', 'arg') // now invoke properties on it
```

### Application state

#### Read app state from a store exposed on `window`

When your app exposes its store on `window`, `.its()` and
[`.invoke()`](/api/commands/invoke) can read that state directly. The whole
chain retries, so the assertion waits for the app to update its state.

```javascript title="app.js"
// expose the store only when the app runs inside Cypress
if (window.Cypress) {
  window.store = store
}
```

```javascript title="spec.cy.js"
cy.window()
  .its('store')
  .invoke('getState')
  .its('cart.items')
  .should('have.length', 2)
```

### Nested properties

You can drill into nested properties by using _dot notation_.

```javascript
const user = {
  contacts: {
    work: {
      name: 'Kamil',
    },
  },
}

cy.wrap(user).its('contacts.work.name').should('eq', 'Kamil') // true
```

Include an array index in the path with a numeric segment or bracket notation.

```javascript
const order = {
  items: [{ name: 'Apple' }, { name: 'Banana' }],
}

cy.wrap(order).its('items[1].name').should('eq', 'Banana') // true
cy.wrap(order).its('items.1.name').should('eq', 'Banana') // true
```

### Existence

#### Wait for some property to exist on `window`

```javascript
cy.window()
  .its('globalProp')
  .then((globalProp) => {
    // do something now that window.globalProp exists
  })
```

#### Assert that a property does not exist on `window`

```javascript
cy.window().its('evilProp').should('not.exist')
```

#### Assert that a property is `null` or `undefined`

`.its()` normally retries until a property has a value. Chain an assertion that
expects `null` or `undefined`, and `.its()` leaves the decision to that
assertion instead.

```javascript
cy.wrap({ deletedAt: null }).its('deletedAt').should('be.null')
cy.wrap({ name: 'Jane' }).its('nickname').should('be.undefined')
```

#### Wait longer for a property with the `timeout` option

Pass `timeout` when a property takes longer to appear than
[`defaultCommandTimeout`](/app/references/configuration#Timeouts) allows, such
as a flag an app sets after a slow startup.

```javascript
cy.window().its('appReady', { timeout: 10000 }).should('be.true')
```

## Notes

### Choosing between `.its()`, `.invoke()`, and `.then()`

All three work with the subject, but they do different jobs:

- `.its()` reads a property. When the property holds a function, `.its()`
  yields the function itself without calling it.
- [`.invoke()`](/api/commands/invoke) calls a function on the subject and
  yields what it returns.
- [`.then()`](/api/commands/then) runs a callback with the subject, for
  logic that doesn't fit a single property read or function call.

`.its()` and `.invoke()` are queries, so Cypress retries them together with the
queries before them until chained assertions pass. `.then()` runs its callback
once and is not [retried](/app/core-concepts/retry-ability#Only-queries-are-retried),
so prefer `.its()` or `.invoke()` whenever you assert on the value they yield.

## Rules

<HeaderRequirements />

- `.its()` requires being chained off a previous command.

<HeaderAssertions />

- `.its()` automatically [retries](/app/core-concepts/retry-ability) until
  the property is not `null` or `undefined`, unless the next assertion is one
  that can pass on those values: `not.exist`, `be.undefined`, `be.null`,
  `not.be.ok`, `eq`, or `not.eq`. In that case, the assertion alone decides
  when `.its()` passes.
- `.its()` automatically [retries](/app/core-concepts/retry-ability) until
  all chained assertions have passed.

<HeaderTimeouts />

- `.its()` can time out waiting for the property to exist.
- `.its()` can time out waiting for assertions you've added to pass.

## Command Log

**_Get `response.body` of an aliased intercept_**

```javascript
cy.intercept('/comments', { fixture: 'comments.json' }).as('getComments')
cy.get('#fetch-comments').click()
cy.wait('@getComments')
  .its('response.body')
  .should('deep.eq', [
    { id: 1, comment: 'hi' },
    { id: 2, comment: 'there' },
  ])
```
