# mount

`cy.mount()` renders a component into the browser for a
[component test](/app/core-concepts/testing-types#What-is-Component-Testing).
Cypress doesn't ship a working implementation of it. Until you register one, a
call to `cy.mount()` fails with:

```text
cy.mount() must be implemented by the user. There are
full instructions for doing so at the following location.
```

You register it as a [custom command](/api/cypress-api/custom-commands) in your
component support file. When you configure Component Testing through the
Cypress App, it scaffolds that support file for you with a `cy.mount()` command
already in place.

We recommend a custom `cy.mount()` command over importing a framework's `mount()`
function into each spec:

- The command is available globally, so specs don't need to import anything to
  mount a component.
- It's one place to set up what most of your components need, like wrapping
  them in a [React context provider](https://react.dev/reference/react/createContext#provider)
  or installing [Vue plugins](https://vuejs.org/guide/reusability/plugins.html).

## Framework `mount()` functions for Cypress Component Testing

Each framework renders components differently, so Cypress provides a
framework-specific `mount()` function for each one. They ship with the
`cypress` package, so there's nothing extra to install:

<Tabs groupId="frameworks">
<TabItem value="React">

```js
import { mount } from 'cypress/react'
```

`mount()` from
[`cypress/react`](https://github.com/cypress-io/cypress/tree/develop/npm/react)
accepts standard JSX, such as `cy.mount(<Stepper />)`.

</TabItem>
<TabItem value="Angular">

```ts
import { mount } from 'cypress/angular'
```

`mount()` from
[`cypress/angular`](https://github.com/cypress-io/cypress/tree/develop/npm/angular)
uses [Angular TestBed](https://angular.dev/api/core/testing/TestBed) internally,
but renders the component in your real browser rather than a simulated DOM.

</TabItem>
<TabItem value="Vue">

```js
import { mount } from 'cypress/vue'
```

`mount()` from
[`cypress/vue`](https://github.com/cypress-io/cypress/tree/develop/npm/vue) uses
[Vue Test Utils](https://test-utils.vuejs.org/) internally, but renders the
component in your real browser rather than a simulated DOM.

</TabItem>
<TabItem value="Svelte">

```js
import { mount } from 'cypress/svelte'
```

`mount()` from
[`cypress/svelte`](https://github.com/cypress-io/cypress/tree/develop/npm/svelte)
mounts the component with Svelte's own `mount()` function, so it takes the
component and an options object such as `{ props: { count: 42 } }`.

</TabItem>
</Tabs>

## The scaffolded `cy.mount()` command

When Cypress scaffolds Component Testing, it writes
`cypress/support/component.js` (or `component.ts` in a TypeScript project) and
registers the framework's `mount()` function directly. For a React project in
TypeScript, it looks like this:

```ts title="cypress/support/component.ts"
import './commands'

import { mount } from 'cypress/react'

// Augment the Cypress namespace to include type definitions for
// your custom command.
// Alternatively, can be defined in cypress/support/component.d.ts
// with a <reference path="./component" /> at the top of your spec.
declare global {
  namespace Cypress {
    interface Chainable {
      mount: typeof mount
    }
  }
}

Cypress.Commands.add('mount', mount)

// Example use:
// cy.mount(<MyComponent />)
```

Other frameworks get the same file with their own import: `cypress/angular`,
`cypress/vue`, or `cypress/svelte`. The JavaScript version leaves out the
`declare global` block.

## Customizing the `cy.mount()` command for your app

To set up what your components need in every test, replace the direct
`Cypress.Commands.add('mount', mount)` registration with a function that wraps
`mount()`. Start from the example for your framework:

Cypress.Commands.add('mount', (component, options) => {
  // Wrap any parent components needed
  // ie: return mount(<MyProvider>{component}</MyProvider>, options)
  return mount(component, options)
})

If you'd rather keep custom commands in `cypress/support/commands.js`, you can
register `cy.mount()` there instead. The scaffolded support file already imports
it with `import './commands'`. Register the command in only one of the two
files. If both register it, the registration that runs last replaces the other
without an error, which is the one in `component.js` for the scaffolded file.

## TypeScript typings for the `cy.mount()` command

In a [TypeScript](/app/tooling/typescript-support) project, the `declare global`
block in the examples above gives `cy.mount()` code completion and type
checking. It can live in the support file, as the scaffold does, or in a
separate declaration file.

To share the typings with code outside the support file, we recommend a
`cypress.d.ts` file in your project root. Import the `mount()` function for your
framework:

```ts title="cypress.d.ts"
import { mount } from 'cypress/react'

declare global {
  namespace Cypress {
    interface Chainable {
      mount: typeof mount
    }
  }
}
```

Replace `cypress/react` with `cypress/angular`, `cypress/vue`, or
`cypress/svelte` for other frameworks.

If your tests have trouble finding the types for the custom command, add
`cypress.d.ts` to the `include` array of each `tsconfig.json` file:

```json title="tsconfig.json"
"include": ["./src", "cypress.d.ts"]
```
