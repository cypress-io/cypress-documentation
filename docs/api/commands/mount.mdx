# mount

`cy.mount()` renders a component in the browser for a component test. Cypress
reserves the command name but doesn't implement it, because each framework
renders components differently. You register `cy.mount()` yourself in your
component support file, using the `mount()` function from your framework's
mounting library. Until you do, calling `cy.mount()` fails with an error that
links to this page:

```text
`cy.mount()` must be implemented by the user. There are
full instructions for doing so at the following location.

https://on.cypress.io/mount
```

When you configure Component Testing through the Cypress App, Cypress scaffolds
the command for you in `cypress/support/component.js` (or
`cypress/support/component.ts`), so most projects start with a working
`cy.mount()`. This guide covers how to customize that command to fit the needs
of your app.

We recommend registering a custom `cy.mount()` command instead of importing the
mount function from the mounting libraries in each spec. Doing so offers a few
advantages:

- You don't need to import the mount function into every test, since the
  `cy.mount()` command is available globally.
- You can set up common scenarios that you usually have to do in each test, like
  wrapping a component in a
  [React context provider](https://react.dev/learn/passing-data-deeply-with-context)
  or adding [Vue plugins](https://vuejs.org/guide/reusability/plugins.html).

## Creating a custom `cy.mount()` command

<ImportMountFunctions />

To use `cy.mount()`, add a [custom command](/api/cypress-api/custom-commands)
with [`Cypress.Commands.add()`](/api/cypress-api/custom-commands) in your
component support file. This is where Cypress scaffolds it, and the file only
loads for component tests, so your end-to-end tests don't bundle a mounting
library they never use. Start from one of these examples:

<Tabs groupId="frameworks">
<TabItem value='React' active>

<Tabs>
<TabItem value="cypress/support/component.js">

```js
import { mount } from 'cypress/react'

Cypress.Commands.add('mount', (component, options) => {
  // Wrap any parent components needed
  // ie: return mount(<MyProvider>{component}</MyProvider>, options)
  return mount(component, options)
})
```

</TabItem>
<TabItem value="cypress/support/component.ts">

```ts
import { mount } from 'cypress/react'

declare global {
  namespace Cypress {
    interface Chainable {
      mount: typeof mount
    }
  }
}

Cypress.Commands.add('mount', (component, options) => {
  // Wrap any parent components needed
  // ie: return mount(<MyProvider>{component}</MyProvider>, options)
  return mount(component, options)
})
```

  // Setup options object
  options.global = options.global || {}
  options.global.stubs = options.global.stubs || {}
  if (!Array.isArray(options.global.stubs)) {
    options.global.stubs['transition'] = false
  }
  options.global.components = options.global.components || {}
  options.global.plugins = options.global.plugins || []

  /* Add any global plugins */

  //   },
  // });

})

## TypeScript typings for a custom `cy.mount()` command

When working in [TypeScript](/app/tooling/typescript-support), your custom
command needs typings for code completion and to avoid TypeScript errors. The
`cypress/support/component.ts` examples above declare them in the support file
itself, which is what Cypress scaffolds.

To make the typings available to any code in your project, you can move the
declaration into a `cypress.d.ts` file in the root directory instead. Use this
example as a starting point:

<Tabs groupId="frameworks">
<TabItem value="React" active>

```ts title="cypress.d.ts"
import { mount } from 'cypress/react'

declare global {
  namespace Cypress {
    interface Chainable {
      mount: typeof mount
    }
  }
}
```

</TabItem>
<TabItem value="Angular">

```ts title="cypress.d.ts"
import { mount } from 'cypress/angular'

declare global {
  namespace Cypress {
    interface Chainable {
      mount: typeof mount
    }
  }
}
```

</TabItem>
<TabItem value="Vue">

```ts title="cypress.d.ts"
import { mount } from 'cypress/vue'

declare global {
  namespace Cypress {
    interface Chainable {
      mount: typeof mount
    }
  }
}
```

</TabItem>
<TabItem value="Svelte">

```ts title="cypress.d.ts"
import { mount } from 'cypress/svelte'

declare global {
  namespace Cypress {
    interface Chainable {
      mount: typeof mount
    }
  }
}
```

</TabItem>
</Tabs>

If your tests have trouble finding the types for the custom commands, manually
include the `cypress.d.ts` file in all your `tsconfig.json` files like so:

```json title="tsconfig.json"
"include": ["./src", "cypress.d.ts"]
```
