# filter

Get the DOM elements that match a specific selector or pass a test function.

:::info

Opposite of [`.not()`](/api/commands/not)

:::

:::info

The querying behavior of this command matches exactly how
[`.filter()`](https://api.jquery.com/filter/) works in jQuery.

:::

## Syntax

```javascript
.filter(selector)
.filter(selector, options)
.filter(fn)
.filter(fn, options)
```

### Usage

<Icon name="check-circle" color="green" /> **Correct Usage**

```javascript
cy.get('td').filter('.users') // Yield all el's with class '.users'
```

<Icon name="exclamation-triangle" color="red" /> **Incorrect Usage**

```javascript
cy.filter('.animated') // Errors, cannot be chained off 'cy'
cy.clock().filter() // Errors, 'clock' does not yield DOM elements
```

### Arguments

<Icon name="angle-right" /> **selector _(String selector)_**

A selector used to filter matching DOM elements.

<Icon name="angle-right" /> **fn _(Function)_**

A function called once for each element in the subject, with the element's
index and the element itself as arguments: `(index, element)`. `.filter()`
yields the elements for which the function returns a truthy value.

<Icon name="angle-right" /> **options _(Object)_**

Pass in an options object to change the default behavior of `.filter()`.

| Option    | Default                                                           | Description                                                                         |
| --------- | ----------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| `log`     | `true`                                                            | Displays the command in the [Command log](/app/core-concepts/open-mode#Command-Log) |
| `timeout` | [`defaultCommandTimeout`](/app/references/configuration#Timeouts) | Time to wait for `.filter()` to resolve before [timing out](#Timeouts)              |

<HeaderYields />

- `.filter()` yields the new DOM element(s) it found.
- `.filter()` is a query, and it is _safe_ to chain further commands.

## Examples

### Selector

#### Filter the current subject to the elements with the class 'active'

```html
<ul>
  <li>Home</li>
  <li class="active">About</li>
  <li>Services</li>
  <li>Pricing</li>
  <li>Contact</li>
</ul>
```

```javascript
// yields <li>About</li>
cy.get('ul').find('>li').filter('.active')
```

#### Filter by attribute

```html
<table>
  <tr data-cy="order-row" data-status="shipped">
    <td>#1001</td>
  </tr>
  <tr data-cy="order-row" data-status="pending">
    <td>#1002</td>
  </tr>
  <tr data-cy="order-row" data-status="shipped">
    <td>#1003</td>
  </tr>
</table>
```

```javascript
// yields the rows for orders #1001 and #1003
cy.get('[data-cy="order-row"]')
  .filter('[data-status="shipped"]')
  .should('have.length', 2)
```

#### Filter by form state

Standard CSS pseudo-classes such as `:checked`, `:disabled`, and `:enabled`
narrow form controls by their current state.

```html
<input type="checkbox" name="email" checked />
<input type="checkbox" name="sms" />
<input type="checkbox" name="push" checked />
```

```javascript
cy.get('input[type="checkbox"]').filter(':checked').should('have.length', 2)
```

#### Filter by visibility

Cypress replaces jQuery's `:visible` and `:hidden` selectors with its own
[visibility rules](/app/core-concepts/interacting-with-elements#Visibility), so
`.filter(':visible')` keeps exactly the elements that `.should('be.visible')`
treats as visible. Cypress also adds a `:focused` selector that matches the
focused element.

```html
<ul class="menu">
  <li>Dashboard</li>
  <li>Reports</li>
  <li style="display: none">Admin</li>
  <li>Settings</li>
</ul>
```

```javascript
cy.get('.menu li').filter(':visible').should('have.length', 3)
```

### Function

#### Filter the current subject with a test function

```html
<ul>
  <li>Home</li>
  <li class="active">About</li>
  <li>Services</li>
</ul>
```

```javascript
// yields <li>Home</li> and <li>Services</li>
cy.get('li').filter((index, el) => !el.classList.contains('active'))
```

```javascript
// yields the even-indexed <li> elements: Home and Services
cy.get('li').filter((index) => index % 2 === 0)
```

Because `.filter()` is a query, Cypress calls the function again on every
[retry](/app/core-concepts/retry-ability). Keep it synchronous and free of side
effects, and don't call other Cypress commands inside it.

Read the element from the function's second argument rather than from `this`.
Arrow functions don't bind `this`, so `el` works in every function style.

#### Filter by a numeric value

A selector can't compare numbers, but a function can.

```html
<ul>
  <li class="price">$45.00</li>
  <li class="price">$120.00</li>
  <li class="price">$310.50</li>
</ul>
```

```javascript
// yields the $120.00 and $310.50 prices
cy.get('.price')
  .filter((index, el) => parseFloat(el.textContent.replace('$', '')) > 100)
  .should('have.length', 2)
```

#### Filter by text, ignoring case

The `:contains` selector is case-sensitive. Compare lowercased text in a
function to match regardless of case.

```html
<ul>
  <li>Services</li>
  <li>Advanced services</li>
  <li>Pricing</li>
</ul>
```

```javascript
cy.get('li')
  .filter((index, el) => el.textContent.toLowerCase().includes('services'))
  .should('have.length', 2)
```

To get a single element by text regardless of case, use
[`.contains()`](/api/commands/contains) with the `matchCase: false` option.

### Contains

#### Filter by text

You can use the [jQuery :contains](https://api.jquery.com/contains-selector/)
selector to perform a case-sensitive text substring match.

```html
<ul>
  <li>Home</li>
  <li>Services</li>
  <li>Advanced Services</li>
  <li>Pricing</li>
  <li>Contact</li>
</ul>
```

Find both list items that contain the word "Services":

```javascript
cy.get('li').filter(':contains("Services")').should('have.length', 2)
```

#### Filter table rows by a cell's text

Combine the [jQuery :has](https://api.jquery.com/has-selector/) selector with
`:contains` to keep only the rows with a matching cell, then act on something
inside that row.

```html
<table>
  <tbody>
    <tr>
      <td>Ana</td>
      <td>Admin</td>
      <td><button class="edit">Edit</button></td>
    </tr>
    <tr>
      <td>Ben</td>
      <td>Viewer</td>
      <td><button class="edit">Edit</button></td>
    </tr>
  </tbody>
</table>
```

```javascript
cy.get('tbody tr')
  .filter(':has(td:contains("Admin"))')
  .find('button.edit')
  .click()
```

#### Non-breaking space

If the HTML contains a
[non-breaking space](https://en.wikipedia.org/wiki/Non-breaking_space) entity
`&nbsp;` and the test uses the
[jQuery :contains](https://api.jquery.com/contains-selector/) selector, then the
test needs to use the Unicode value `\u00a0` instead of `&nbsp;`.

```html
<div data-testid="testattr">
  <span>Hello&nbsp;world</span>
</div>
```

```javascript
cy.get('[data-testid="testattr"]').filter(':contains("Hello\u00a0world")')
```

### Actions and assertions

#### Act on one element from a filtered set

`.filter()` can yield several elements, and action commands such as
[`.click()`](/api/commands/click) fail on more than one element unless you pass
`{ multiple: true }`. Narrow the result to a single element first.

```html
<ul>
  <li><button class="delete">Delete</button> Draft 1</li>
  <li><button class="delete" disabled>Delete</button> Published post</li>
  <li><button class="delete">Delete</button> Draft 2</li>
</ul>
```

```javascript
// clicks the Delete button for Draft 1
cy.get('button.delete').filter(':enabled').first().click()
```

Use [`.first()`](/api/commands/first), [`.last()`](/api/commands/last), or
[`.eq()`](/api/commands/eq) for this rather than jQuery's positional selectors
such as `:first` and `:eq()`, which jQuery deprecated in version 3.4.

#### Assert that no elements match

```html
<ul>
  <li class="notification info">Saved</li>
  <li class="notification info">Synced</li>
</ul>
```

```javascript
// passes once no notification has the 'error' class
cy.get('.notification').filter('.error').should('not.exist')
```

## Notes

### Choosing between .filter(), .find(), and .contains()

These three commands narrow a selection in different ways:

- `.filter()` keeps the elements in the current subject that match. It never
  looks inside them.
- [`.find()`](/api/commands/find) searches the descendants of the current
  subject.
- [`.contains()`](/api/commands/contains) matches by text and yields the deepest
  element that contains it.

```html
<ul>
  <li class="active">About <span class="badge">New</span></li>
  <li>Services</li>
</ul>
```

```javascript
cy.get('li').filter('.active') // yields <li class="active">
cy.get('li').find('.badge') // yields <span class="badge">
cy.get('ul').contains('Services') // yields <li>Services</li>
```

## Rules

<HeaderRequirements />

- `.filter()` requires being chained off a command that yields DOM element(s) or
  a document.

<HeaderAssertions />

- `.filter()` will automatically [retry](/app/core-concepts/retry-ability)
  until the element(s)
  [exist in the DOM](/app/core-concepts/introduction-to-cypress#Implicit-Assertions).
- `.filter()` will automatically [retry](/app/core-concepts/retry-ability)
  until all chained assertions have passed.

<HeaderTimeouts />

- `.filter()` can time out waiting for the element(s) to
  [exist in the DOM](/app/core-concepts/introduction-to-cypress#Implicit-Assertions).
- `.filter()` can time out waiting for assertions you've added to pass.
