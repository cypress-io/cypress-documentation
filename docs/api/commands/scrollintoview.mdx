# scrollIntoView

Scroll an element into view.

It is [unsafe](/app/core-concepts/retry-ability#Only-queries-are-retried) to
chain further commands that rely on the subject after `.scrollIntoView()`.

## Syntax

```javascript
.scrollIntoView()
.scrollIntoView(options)
```

### Usage

<Icon name="check-circle" color="green" /> **Correct Usage**

```javascript
cy.get('footer').scrollIntoView() // Scrolls 'footer' into view
```

<Icon name="exclamation-triangle" color="red" /> **Incorrect Usage**

```javascript
cy.scrollIntoView('footer') // Errors, cannot be chained off 'cy'
cy.window().scrollIntoView() // Errors, 'window' does not yield DOM element
cy.get('li').scrollIntoView() // Errors, 'li' yields more than one element
```

### Arguments

<Icon name="angle-right" /> **options _(Object)_**

Pass in an options object to change the default behavior of `.scrollIntoView()`.

| Option     | Default                                                           | Description                                                                                                                                                                     |
| ---------- | ----------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `duration` | `0`                                                               | Time in ms to animate the scroll over, as a number or a numeric string such as `'500'`                                                                                          |
| `easing`   | `swing`                                                           | Easing animation for the scroll: `swing` or `linear`. Any other value throws an error                                                                                           |
| `log`      | `true`                                                            | Displays the command in the [Command log](/app/core-concepts/open-mode#Command-Log)                                                                                             |
| `offset`   | `{top: 0, left: 0}`                                               | Pixels to scroll past the element's position. A negative value stops short of it, leaving room above or to the left. Either key can be given alone, and the other defaults to 0 |
| `timeout`  | [`defaultCommandTimeout`](/app/references/configuration#Timeouts) | Time to wait for assertions chained after `.scrollIntoView()` to pass before [timing out](#Timeouts)                                                                            |

<HeaderYields />

- `.scrollIntoView()` yields the same subject it was given.
- It is [unsafe](/app/core-concepts/retry-ability#Only-queries-are-retried)
  to chain further commands that rely on the subject after `.scrollIntoView()`.

## Examples

### Scrolling

```javascript
cy.get('button#checkout').scrollIntoView()
```

#### Check that an element is in the viewport

[Visibility](/app/core-concepts/interacting-with-elements#Visibility) doesn't
account for the viewport, so `.should('be.visible')` passes for an element that
is scrolled out of view. To confirm the scroll worked, check the element's
position instead. This checks that its top edge is inside the viewport.

```javascript
cy.get('button#checkout').scrollIntoView()
cy.get('button#checkout')
  .invoke('get', 0)
  .invoke('getBoundingClientRect')
  .its('top')
  .should('be.within', 0, Cypress.config('viewportHeight'))
```

#### Scroll an item inside a scrollable container

When the element sits inside a scrollable container, such as a results list,
`.scrollIntoView()` scrolls that container to reach it. If the container is off
screen, the page scrolls first to bring the container into view.

```javascript
cy.get('[data-cy="results"] li').eq(40).scrollIntoView()
cy.get('[data-cy="results"]').its('0.scrollTop').should('be.greaterThan', 0)
```

### Options

#### Use linear easing animation to scroll

```javascript
cy.get('.next-page').scrollIntoView({ easing: 'linear' })
```

#### Scroll to element over 2000ms

```javascript
cy.get('footer').scrollIntoView({ duration: 2000 })
```

#### Scroll 150px past the top of an element

```js
cy.get('#nav').scrollIntoView({ offset: { top: 150, left: 0 } })
```

#### Leave room for a fixed header

A negative `offset` stops short of the element, so it lands below a fixed
header instead of underneath it.

```js
cy.get('#pricing').scrollIntoView({ offset: { top: -80, left: 0 } })
```

### Workflows

#### Test behavior that a scroll triggers

Sticky headers, "back to top" buttons, and lazy-loaded images change as the
page scrolls. Scroll to a point on the page, then assert on the change.

```javascript
cy.get('footer').scrollIntoView()
cy.get('[data-cy="back-to-top"]').should('have.class', 'is-shown')
```

## Notes

### Skip .scrollIntoView() before action commands

Action commands such as [`.click()`](/api/commands/click) and
[`.type()`](/api/commands/type) scroll the element into view before acting on
it, so a `.scrollIntoView()` in front of them adds nothing. The
[`scrollBehavior`](/app/references/configuration#Actionability) option controls
where the element lands.

```javascript
cy.get('#submit').scrollIntoView().click() // ❌ the scroll is redundant
cy.get('#submit').click() // ✅ .click() scrolls the element into view itself
```

### Where the element lands after scrolling

`.scrollIntoView()` scrolls the element's nearest scrollable ancestor, or the
window when there isn't one, until the element's top-left corner lines up with
the top-left of that container, as far as the container can scroll. Use the
`offset` option to adjust where it lands. When the scrollable ancestor is a
container inside the page, Cypress first scrolls that container into view, then
scrolls the element within it.

## Rules

<HeaderRequirements />

- `.scrollIntoView()` requires being chained off a command that yields a single
  DOM element. It throws an error when the subject contains more than one
  element.

<HeaderAssertions />

- `.scrollIntoView()` runs once and is not retried. Assertions chained after
  `.scrollIntoView()` retry until they pass or time out.
  See
  [Only queries are retried](/app/core-concepts/retry-ability#Only-queries-are-retried).

<HeaderTimeouts />

- `.scrollIntoView()` can time out waiting for assertions you've added to pass.
