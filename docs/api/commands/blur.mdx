# blur

Remove focus from an element and fire its `blur` and `focusout` events. Use it
to test what your app does when a field loses focus.

It is [unsafe](/app/core-concepts/retry-ability#Only-queries-are-retried) to
chain further commands that rely on the subject after `.blur()`.

:::caution

The element must have focus. Call [`.focus()`](/api/commands/focus) or
[`.type()`](/api/commands/type) on it first.

:::

## Syntax

```javascript
.blur()
.blur(options)
```

### Usage

<Icon name="check-circle" color="green" /> **Correct Usage**

```javascript
cy.get('[type="email"]').blur() // Blur the focused email input
cy.get('[tabindex="1"]').blur() // Blur the focused element with tabindex
cy.window().blur() // Blur the window
```

<Icon name="exclamation-triangle" color="red" /> **Incorrect Usage**

```javascript
cy.blur('input') // Errors, cannot be chained off 'cy'
cy.get('li').blur() // Errors, subject contains more than one element
```

### Arguments

<Icon name="angle-right" /> **options _(Object)_**

Pass in an options object to change the default behavior of `.blur()`.

| Option    | Default                                                           | Description                                                                             |
| --------- | ----------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| `log`     | `true`                                                            | Displays the command in the [Command Log](/app/core-concepts/open-mode#Command-Log)     |
| `force`   | `false`                                                           | Forces the action, disables checking if [element is focused](#Requirements)             |
| `timeout` | [`defaultCommandTimeout`](/app/references/configuration#Timeouts) | Time to wait for assertions chained to `.blur()` to pass before [timing out](#Timeouts) |

<HeaderYields />

- `.blur()` yields the same subject it was given.
- It is [unsafe](/app/core-concepts/retry-ability#Only-queries-are-retried)
  to chain further commands that rely on the subject after `.blur()`.

## Examples

### No Args

#### Blur the comment input

```javascript
cy.get('[name="comment"]').type('Nice Product!')
cy.get('[name="comment"]').blur()
```

### Options

#### Blur the first input

Setting `force` to `true` in the options disables checking whether the input
currently has focus.

```javascript
cy.get('input').first().blur({ force: true })
```

### Workflows

#### Show a validation message when a field loses focus

```javascript
cy.get('#email').type('not-an-email')
cy.get('#email').blur()
cy.get('#email-error').should('be.visible')
```

#### Format a value when a field loses focus

```javascript
cy.get('#price').type('19.5')
cy.get('#price').blur()
cy.get('#price').should('have.value', '19.50')
```

#### Autosave a field when it loses focus

Blurring a field you typed into fires its `change` event, so an app that saves
on `change` sends its request when `.blur()` runs. Stub the request with
[`cy.intercept()`](/api/commands/intercept) and wait on it with
[`cy.wait()`](/api/commands/wait).

```javascript
cy.intercept('POST', '/api/notes', { statusCode: 204 }).as('saveNotes')
cy.get('#notes').type('Ships Friday')
cy.get('#notes').blur()
cy.wait('@saveNotes').its('request.body').should('include', 'Ships Friday')
```

#### Confirm the element no longer has focus

```javascript
cy.get('#email').focus()
cy.get('#email').blur()
cy.get('#email').should('not.have.focus')
```

#### Test what your app does when the window loses focus

Blurring the window fires a `blur` event on it, the same event the browser sends
when the user switches to another tab or app.

```javascript
cy.window().blur()
cy.get('#status').should('have.text', 'paused')
```

## Notes

### Actionability

#### Blur is not an action command

`.blur()` doesn't wait for
[actionability](/app/core-concepts/interacting-with-elements) the way action
commands such as [`.click()`](/api/commands/click) do. A user never blurs
an element on its own; they click or tab somewhere else. `.blur()` removes focus
without that other action, so a blur test doesn't depend on it.

### Subjects

#### Blurring the window leaves the focused element alone

`.blur()` accepts the window as its subject, so `cy.window().blur()` fires a
`blur` event on the window. Focus itself does not move: whichever element held
it still does, and `document.activeElement` is unchanged.

#### Blurring the body doesn't fire a blur event

`.blur()` also accepts the `body` without it having focus, but the browser never
fires `blur` on the `body`, so Cypress doesn't simulate one. Focus stays where it
was.

### Events

#### Blurring a field you typed into fires its `change` event

When the element has a value change waiting from [`.type()`](/api/commands/type)
or [`.clear()`](/api/commands/clear), `.blur()` fires the `change` event first,
then `blur`, the same order the browser uses when a user leaves the field.

## Rules

<HeaderRequirements />

- `.blur()` requires being chained off a command that yields a DOM element or
  the window.
- `.blur()` requires the subject to contain a single element.
- `.blur()` requires the element to currently have focus, unless you pass
  `{ force: true }`. The window and the `body` are exempt, since neither reports
  as the focused element.

<HeaderAssertions />

- `.blur()` automatically waits for assertions you've chained to pass.

<HeaderTimeouts />

- `.blur()` can time out waiting for assertions you've added to pass.
