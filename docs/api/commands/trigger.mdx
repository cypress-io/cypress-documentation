# trigger

Trigger any DOM event on an element, the window, or the document: mouse,
keyboard, touch, pointer, drag and drop, or your app's own custom events. Use it
to test a handler that listens for an event no action command, such as
[`.click()`](/api/commands/click) or [`.type()`](/api/commands/type), fires.

## Syntax

```javascript
.trigger(eventName)
.trigger(eventName, position)
.trigger(eventName, options)
.trigger(eventName, x, y)
.trigger(eventName, position, options)
.trigger(eventName, x, y, options)
```

### Usage

<Icon name="check-circle" color="green" /> **Correct Usage**

```javascript
cy.get('a').trigger('mousedown') // Trigger mousedown event on link
```

<Icon name="exclamation-triangle" color="red" /> **Incorrect Usage**

```javascript
cy.trigger('touchstart') // Errors, cannot be chained off 'cy'
cy.clock().trigger('mouseleave') // Errors, 'clock' does not yield DOM elements
```

### Arguments

<Icon name="angle-right" /> **eventName _(String)_**

The name of the `event` to be triggered on the DOM element.

<Icon name="angle-right" /> **position _(String)_**

The position where the event should be triggered. The `center` position is the
default position. Valid positions are `topLeft`, `top`, `topRight`, `left`,
`center`, `right`, `bottomLeft`, `bottom`, and `bottomRight`.

<DocsImage
  src="/img/api/coordinates-diagram.svg"
  alt="Diagram of the nine positions on an element's border box: topLeft, top, and topRight along the top edge; left, center, and right across the middle; and bottomLeft, bottom, and bottomRight along the bottom edge. Edge and corner positions sit just inside the outer edge of the border box, on the border when the element has one, and never in the margin. center is the default."
  noBorder
/>

<Icon name="angle-right" /> **x _(Number)_**

The distance in pixels from element's left to trigger the event.

<Icon name="angle-right" /> **y _(Number)_**

The distance in pixels from element's top to trigger the event.

<Icon name="angle-right" /> **options _(Object)_**

Pass in an options object to change the default behavior of `.trigger()`.

| Option                       | Default                                                                     | Description                                                                                                                                                                                                                                                   |
| ---------------------------- | --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `animationDistanceThreshold` | [`animationDistanceThreshold`](/app/references/configuration#Actionability) | The distance in pixels an element must exceed over time to be [considered animating](/app/core-concepts/interacting-with-elements#Animations).                                                                                                                |
| `bubbles`                    | `true`                                                                      | Whether the event bubbles                                                                                                                                                                                                                                     |
| `cancelable`                 | `true`                                                                      | Whether the event is cancelable                                                                                                                                                                                                                               |
| `eventConstructor`           | `'Event'`                                                                   | The name of the constructor, as a string, that creates the event object (e.g. `'MouseEvent'`, `'KeyboardEvent'`). It must exist on the application's `window`. See [choosing an event constructor](#How-eventConstructor-changes-the-properties-you-can-set). |
| `force`                      | `false`                                                                     | Forces the action, disables [waiting for actionability](#Assertions)                                                                                                                                                                                          |
| `log`                        | `true`                                                                      | Displays the command in the [Command Log](/app/core-concepts/open-mode#Command-Log)                                                                                                                                                                           |
| `scrollBehavior`             | [`scrollBehavior`](/app/references/configuration#Actionability)             | Viewport position to where an element [should be scrolled](/app/core-concepts/interacting-with-elements#Scrolling) before executing the command. Accepts a single alignment, a per-axis `{ block, inline }` object, or `false`.                               |
| `timeout`                    | [`defaultCommandTimeout`](/app/references/configuration#Timeouts)           | Time to wait for `.trigger()` to resolve before [timing out](#Timeouts)                                                                                                                                                                                       |
| `waitForAnimations`          | [`waitForAnimations`](/app/references/configuration#Actionability)          | Whether to wait for elements to [finish animating](/app/core-concepts/interacting-with-elements#Animations) before executing the command.                                                                                                                     |

You can also include arbitrary event properties (e.g. `clientX`, `shiftKey`) and
they are attached to the event.

When the subject is an element, `.trigger()` sets `clientX`, `clientY`, `pageX`,
`pageY`, `screenX`, and `screenY` on the event from the `position` or `x` and `y`
you pass. `screenX` and `screenY` carry the same viewport-relative values as
`clientX` and `clientY`. Any of these properties you pass in options override
the calculated ones.

`clientX` and `clientY` measure from the viewport, while `pageX` and `pageY`
measure from the top of the document, so they differ once the page scrolls.

<HeaderYields />

- `.trigger()` yields the same subject it was given.
- It is [unsafe](/app/core-concepts/retry-ability#Only-queries-are-retried)
  to chain further commands that rely on the subject after `.trigger()`.

## Examples

### Event Name

#### Trigger a `mouseover` on the button

The DOM element must be in an "interactable" state prior to the triggered event
happening (it must be visible and not disabled).

```javascript
cy.get('button').trigger('mouseover') // yields 'button'
```

### Position

#### Trigger a `mousedown` on the top right of a button

```javascript
cy.get('button').trigger('mousedown', 'topRight')
```

Click the `trigger` command in the Command Log to pin its snapshot. A red dot
marks the point where the event fired, here the button's top-right corner.

<DocsImage
  src="/img/api/trigger/command-log-trigger-top-right-snapshot.png"
  alt="Pinned trigger mousedown, topRight command with a red dot on the top-right corner of the highlighted Save button"
/>

### Coordinates

#### Specify explicit coordinates relative to the top left corner

```javascript
cy.get('button').trigger('mouseup', 15, 40)
```

### Options

#### Specify that the event should not bubble

By default, the event bubbles up the DOM tree. Set `bubbles: false` to stop it
at the element.

```javascript
cy.get('button').trigger('mouseover', { bubbles: false })
```

A [`cy.spy()`](/api/commands/spy) added as a listener on the document confirms
the event stopped at the button.

```javascript
const onDocumentMouseover = cy.spy().as('documentMouseover')
cy.document().then((doc) => {
  doc.addEventListener('mouseover', onDocumentMouseover)
})

cy.get('button').trigger('mouseover', { bubbles: false })
cy.get('@documentMouseover').should('not.have.been.called')
```

#### Check that a drop zone accepts drops

A drop zone accepts a drop only when its `dragover` handler cancels the event
with `preventDefault()`. The event is cancelable by default, so a
[`cy.spy()`](/api/commands/spy) listener can check the event's
`defaultPrevented` property after the handlers run.

```javascript
const onDragover = cy.spy().as('dragover')
cy.get('[data-cy=drop-zone]').then(($zone) => {
  $zone[0].addEventListener('dragover', onDragover)
})

cy.get('[data-cy=drop-zone]').trigger('dragover')
cy.get('@dragover').should('have.been.calledWithMatch', {
  defaultPrevented: true,
})
```

With `cancelable: false`, `preventDefault()` has no effect and
`defaultPrevented` stays `false`.

#### Specify the exact `clientX` and `clientY` the event should have

This overrides the default auto-positioning based on the element itself. Useful
for events like `mousemove` where you need the position to be outside the
element itself.

```javascript
cy.get('button').trigger('mousemove', { clientX: 200, clientY: 300 })
```

To check the properties a listener receives, add a
[`cy.spy()`](/api/commands/spy) as the listener and assert on its call.

```javascript
const onMousemove = cy.spy().as('mousemove')
cy.get('button').then(($button) => {
  $button[0].addEventListener('mousemove', onMousemove)
})

cy.get('button').trigger('mousemove', { clientX: 200, clientY: 300 })
cy.get('@mousemove').should('have.been.calledWithMatch', {
  clientX: 200,
  clientY: 300,
})
```

#### Force an event on a hidden element

Custom controls often hide the native input they're built on. Without `force`,
`.trigger()` waits for the input to become visible and fails when it times out.
`force: true` skips the [actionability](#Actionability) checks and the scroll
into view, and dispatches the event right away.

```javascript
cy.get('[data-cy=volume-input]').invoke('val', 60).trigger('change', {
  force: true,
})
cy.get('[data-cy=volume-label]').should('have.text', '60')
```

Forcing lets the test do something a user can't, so keep it for elements like
this one, which receive events but are never visible.

### Mouse Events

#### Show and hide a tooltip on hover

When a JavaScript handler shows the tooltip, trigger the events it listens for
and assert on the result.

```javascript
cy.get('[data-cy=help-icon]').trigger('mouseover')
cy.get('[data-cy=tooltip]').should('be.visible')

cy.get('[data-cy=help-icon]').trigger('mouseout')
cy.get('[data-cy=tooltip]').should('not.be.visible')
```

If the app listens for `mouseenter` and `mouseleave` instead, trigger those
event names. A triggered event doesn't apply CSS `:hover` styles, so a tooltip
shown only by a `:hover` rule stays hidden. See [`.hover()`](/api/commands/hover)
for workarounds.

#### Simulate a "long press" event

Hold the press with `mousedown`, assert on what the long press shows, then
release it with `mouseup`. The assertion retries until the menu appears, so the
test holds the press only as long as the app needs, without a fixed
[`cy.wait()`](/api/commands/wait).

```javascript
cy.get('.target').trigger('mousedown')
cy.get('.long-press-menu').should('be.visible')
cy.get('.target').trigger('mouseup')
```

#### Trigger a `mousedown` from a specific mouse button

```js
// Main button pressed (usually the left button)
cy.get('.target').trigger('mousedown', { button: 0 })
// Auxiliary button pressed (usually the middle button)
cy.get('.target').trigger('mousedown', { button: 1 })
// Secondary button pressed (usually the right button)
cy.get('.target').trigger('mousedown', { button: 2 })
```

#### Drag an element with mouse events

Many drag handlers listen for `mousedown` on the element, then follow
`mousemove` and `mouseup` on the document. The events bubble, so triggering them
on the element reaches document listeners too. Pass the position properties the
handler reads at each step. With the default `Event` constructor, `pageX` and
`pageY` reach the handler exactly as you pass them.

```javascript
cy.get('[data-cy=draggable]').trigger('mousedown', {
  button: 0,
  pageX: 100,
  pageY: 100,
})
cy.get('[data-cy=draggable]').trigger('mousemove', { pageX: 300, pageY: 150 })
cy.get('[data-cy=draggable]').trigger('mouseup')

cy.get('[data-cy=draggable]')
  .should('have.css', 'left', '200px')
  .and('have.css', 'top', '50px')
```

### Keyboard Events

#### Close a dialog with the Escape key

```javascript
cy.get('[data-cy=dialog]').trigger('keydown', { key: 'Escape' })
cy.get('[data-cy=dialog]').should('not.exist')
```

Pass the properties the handler reads, such as `key`, `code`, or `keyCode`. The
event bubbles, so a listener on the document receives it too.

`.trigger()` fires the one event you name on any element.
[`.type()`](/api/commands/type) simulates the full sequence of keyboard events,
but only on elements it can type into, such as inputs, textareas, and elements
with a `tabindex`. Use `.type('{esc}')` when the element accepts typing, and
`.trigger()` when it doesn't.

### Change Events

#### Interact with a range input (slider)

To interact with a range input (slider), set its value, then trigger the event
that signals it changed. This example invokes jQuery's `val()` method to set the
value, then triggers the `change` event.

Some implementations listen for the `input` event instead, which fires as the
user moves the slider.

```javascript
cy.get('input[type=range]').as('range').invoke('val', 25).trigger('change')

cy.get('@range').siblings('p').should('have.text', '25')
```

#### Set a range input in a controlled component (React, Vue, etc.)

Frameworks such as React track an input's value themselves, so setting it with
`.invoke('val', 70)` doesn't reach the component's change handler. Set the value
through the element's native `value` setter, then trigger the event the
framework listens for.

```javascript
cy.get('input[type=range]').then(($range) => {
  const descriptor = Object.getOwnPropertyDescriptor(
    Object.getPrototypeOf($range[0]),
    'value'
  )
  descriptor?.set?.call($range[0], 70)
})
cy.get('input[type=range]').trigger('input')

cy.get('input[type=range]').siblings('p').should('have.text', '70')
```

React's `onChange` listens for the `input` event. If the component listens for
`change` instead, trigger `change`.

### Drag and Drop Events

#### Drag an item to a drop zone with `dataTransfer`

HTML drag and drop handlers pass data through the event's `dataTransfer`
property. Create one
[`DataTransfer`](https://developer.mozilla.org/en-US/docs/Web/API/DataTransfer)
and pass the same object to every event, so the data the `dragstart` handler
sets is there when the `drop` handler reads it.

```javascript
const dataTransfer = new DataTransfer()

cy.get('[data-cy=card]').trigger('dragstart', { dataTransfer })
cy.get('[data-cy=done-column]').trigger('dragenter', { dataTransfer })
cy.get('[data-cy=done-column]').trigger('dragover', { dataTransfer })
cy.get('[data-cy=done-column]').trigger('drop', { dataTransfer })
cy.get('[data-cy=card]').trigger('dragend', { dataTransfer })

cy.get('[data-cy=done-column]').should('contain', 'Write docs')
```

[Check out our example recipe triggering mouse and drag events to test drag and drop](/app/references/recipes#Testing-the-DOM)

:::

### Touch and Pointer Events

#### Swipe a carousel with touch events

Touch handlers read finger positions from the `touches` and `changedTouches`
lists rather than from `clientX`. With the default `Event` constructor, pass
plain objects with the properties the handler reads. On `touchend`, the lifted
finger is in `changedTouches`, and `touches` is empty.

```javascript
cy.get('[data-cy=carousel]').trigger('touchstart', {
  touches: [{ clientX: 300, clientY: 100 }],
})
cy.get('[data-cy=carousel]').trigger('touchmove', {
  touches: [{ clientX: 50, clientY: 100 }],
})
cy.get('[data-cy=carousel]').trigger('touchend', {
  touches: [],
  changedTouches: [{ clientX: 50, clientY: 100 }],
})

cy.get('[data-cy=slide-2]').should('be.visible')
```

#### Drag a slider thumb with pointer events

Many drag and gesture libraries listen for pointer events and ignore pointers
that aren't primary. Pass the same `pointerId` with every event so the library
tracks one pointer from press to release.

```javascript
const pointer = { pointerId: 1, pointerType: 'mouse', isPrimary: true }

cy.get('[data-cy=volume-thumb]').trigger('pointerdown', {
  ...pointer,
  button: 0,
})
cy.get('[data-cy=volume-thumb]').trigger('pointermove', {
  ...pointer,
  clientX: 400,
})
cy.get('[data-cy=volume-thumb]').trigger('pointerup', pointer)

cy.get('[data-cy=volume-value]').should('have.text', '80')
```

### Custom Events

#### Trigger a custom event with a `detail` payload

`.trigger()` fires any event name, including your app's own events. With the
default `Event` constructor, the `detail` you pass is attached as is.

```javascript
cy.get('[data-cy=cart]').trigger('cart:updated', { detail: { count: 3 } })
cy.get('[data-cy=cart-count]').should('have.text', '3')
```

If the handler checks `event instanceof CustomEvent`, add
`eventConstructor: 'CustomEvent'`, which also accepts `detail`.

### Window and Document

#### Trigger an event on the window or document

`.trigger()` also accepts the window or document as its subject. It dispatches
the event right away, without waiting for actionability, and doesn't add any
coordinate properties to the event.

```javascript
cy.window().trigger('beforeprint')
cy.document().trigger('visibilitychange')
```

#### Show an offline banner when the connection drops

```javascript
cy.window().trigger('offline')
cy.get('[data-cy=offline-banner]').should('be.visible')

cy.window().trigger('online')
cy.get('[data-cy=offline-banner]').should('not.be.visible')
```

This runs the app's `offline` and `online` listeners, but `navigator.onLine`
doesn't change. It works when the app reacts to the events rather than reading
`navigator.onLine`.

For `scroll` and `resize`, use [`.scrollTo()`](/api/commands/scrollto) and
[`cy.viewport()`](/api/commands/viewport) instead. They change the scroll
position or window size and fire the real event, so the handler reads values
that match it.

## Notes

### Actionability

#### The element must first reach actionability

`.trigger()` is an "action command" that follows all the rules of
[Actionability](/app/core-concepts/interacting-with-elements).

### Events

#### Choose which event `.trigger()` fires

`.trigger()` is a low-level utility that constructs and dispatches an event for
you. Since it fires any event, Cypress makes no assumptions about how the event
should look. Find out which events the handlers receiving it listen for, which
may be in a third-party library, and pass the properties they read.

#### How `eventConstructor` changes the properties you can set

By default, `.trigger()` fires an
[`Event`](https://developer.mozilla.org/en-US/docs/Web/API/Event). To fire
another class, such as `MouseEvent` or `KeyboardEvent`, pass its name in the
`eventConstructor` option.

```js
cy.get('button').trigger('mouseover', { eventConstructor: 'MouseEvent' })
```

When the constructor is
[`UIEvent`](https://developer.mozilla.org/en-US/docs/Web/API/UIEvent) or one of
its subclasses, such as `MouseEvent` or `KeyboardEvent`, `.trigger()` sets the
event's `view` property to the application's `window`.

With the default `Event` constructor, `.trigger()` attaches every property you
pass to the event as is, including ones like `pageX` and `pageY` that a real
mouse event calculates for itself. Handlers that only read properties, like the
one in [Drag an element with mouse events](#Drag-an-element-with-mouse-events),
work with this default.

When you set `eventConstructor` to a class such as
[`MouseEvent`](https://developer.mozilla.org/en-US/docs/Web/API/MouseEvent), the
browser builds the event, and that class decides which properties you can set.
Properties the constructor accepts, such as `clientX`, `button`, and `shiftKey`,
take your values. Read-only properties the browser calculates, such as `pageX`
and `offsetX`, keep the browser's values, and `.trigger()` drops yours without
an error.

```javascript
// Event (default): pageX is attached as passed
cy.get('.target').trigger('mousedown', { pageX: 600 })

// MouseEvent: clientX is set, and the browser calculates pageX from it
cy.get('.target').trigger('mousedown', {
  eventConstructor: 'MouseEvent',
  clientX: 300,
})
```

This table shows where each mouse property's value comes from:

| Property                                      | Default `Event`                                                  | `MouseEvent`                                     |
| --------------------------------------------- | ---------------------------------------------------------------- | ------------------------------------------------ |
| `clientX`, `clientY`, `screenX`, `screenY`    | Your value                                                       | Your value                                       |
| `button`, `buttons`, `movementX`, `movementY` | Your value                                                       | Your value                                       |
| `shiftKey`, `ctrlKey`, `altKey`, `metaKey`    | Your value                                                       | Your value                                       |
| `pageX`, `pageY`                              | Your value                                                       | Calculated from `clientX`, `clientY`, and scroll |
| `offsetX`, `offsetY`                          | Your value                                                       | Calculated from the element's position           |
| `which`                                       | Your value                                                       | Calculated from `button`                         |
| `x`, `y`                                      | Not attached: `.trigger()` reads them as the position to fire at | Calculated, equal to `clientX` and `clientY`     |

With `KeyboardEvent`, the properties key handlers usually read, `key`, `code`,
`keyCode`, `which`, `repeat`, and the modifier keys, all take your values.

Keep the default unless the handler needs a real instance of the class, for
example when it checks `event instanceof MouseEvent`.

### Differences

#### What's the difference between triggering an event and calling the corresponding Cypress command?

In other words, what's the difference between:

```javascript
cy.get('button').trigger('focus')
cy.get('button').focus()

// ... or ...

cy.get('button').trigger('click')
cy.get('button').click()
```

Both kinds of commands wait for the element to reach actionability first. The
action commands then reproduce the full sequence of events a user's input
produces, along with what the browser does in response. `.trigger()` dispatches
only the event you name.

| You call                            | Events fired                                                                                                                                                          | What happens in the browser                                                                                                                                                           |
| ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `.trigger('click')`                 | `click`                                                                                                                                                               | Focus doesn't move. With the default `Event`, nothing else happens. With `eventConstructor: 'MouseEvent'`, a checkbox toggles and fires `input` and `change`, and a link is followed. |
| `.click()`                          | `pointerover`, `pointerenter`, `mouseover`, `mouseenter`, `pointermove`, `mousemove`, `pointerdown`, `mousedown`, `focus`, `focusin`, `pointerup`, `mouseup`, `click` | Focus moves to the element, a checkbox toggles, and a link is followed.                                                                                                               |
| `.trigger('keydown', { key: 'a' })` | `keydown`                                                                                                                                                             | Focus doesn't move, and no text is inserted, even with `eventConstructor: 'KeyboardEvent'`.                                                                                           |
| `.type('a')`                        | The `.click()` sequence when the element isn't focused yet, then `keydown`, `keypress`, `beforeinput`, `textInput`, `input`, `keyup`                                  | Focus moves to the element, and `a` is inserted.                                                                                                                                      |
| `.trigger('focus')`                 | `focus`                                                                                                                                                               | Focus doesn't move.                                                                                                                                                                   |
| `.focus()`                          | `focus`, `focusin`                                                                                                                                                    | Focus moves to the element.                                                                                                                                                           |

Your listeners run either way. Use the action command when you're testing what a
user does, and `.trigger()` when a handler listens for an event no action
command fires.

## Rules

<HeaderRequirements />

- `.trigger()` requires being chained off a command that yields DOM element(s),
  the window, or the document.
- `.trigger()` requires the element subject to be a single element. It errors
  when the subject contains more than one element.

<HeaderAssertions />

- `.trigger()` automatically waits for the element to reach an
  [actionable state](/app/core-concepts/interacting-with-elements). It skips
  this wait when the subject is the window or the document.
- `.trigger()` automatically [retries](/app/core-concepts/retry-ability)
  until all chained assertions have passed.

<HeaderTimeouts />

- `.trigger()` can time out waiting for the element to reach an
  [actionable state](/app/core-concepts/interacting-with-elements).
- `.trigger()` can time out waiting for assertions you've added to pass.
