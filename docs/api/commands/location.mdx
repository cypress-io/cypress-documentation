# location

Get the global `window.location` object of the page that is currently active.

## Syntax

```javascript
cy.location()
cy.location(key)
cy.location(options)
cy.location(key, options)
```

### Usage

<Icon name="check-circle" color="green" /> **Correct Usage**

```javascript
cy.location() // Get location object
cy.location('host') // Get the host of the location object
cy.location('port') // Get the port of the location object
```

### Arguments

<Icon name="angle-right" /> **key _(String)_**

A key on the location object. Returns this value instead of the full location
object.

<Icon name="angle-right" /> **options _(Object)_**

Pass in an options object to change the default behavior of `cy.location()`.

| Option    | Default                                                           | Description                                                                         |
| --------- | ----------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| `log`     | `true`                                                            | Displays the command in the [Command log](/app/core-concepts/open-mode#Command-Log) |
| `timeout` | [`defaultCommandTimeout`](/app/references/configuration#Timeouts) | Time to wait for `cy.location()` to resolve before [timing out](#Timeouts)          |

<HeaderYields />

`cy.location()` is a query, and it is _safe_ to chain further commands.

#### When not given a `key` argument:

`cy.location()` yields the location object with the following properties:

- `hash`
- `host`
- `hostname`
- `href`
- `origin`
- `pathname`
- `port`
- `protocol`
- `search`
- `searchParams`

Every property is a string except `searchParams`, which is a
[`URLSearchParams`](https://developer.mozilla.org/en-US/docs/Web/API/URLSearchParams)
object.

#### When given a `key` argument:

- `cy.location()` yields the value of that property: a string, or a
  `URLSearchParams` object for `searchParams`
- `cy.location()` fails when the location object has no property named `key`

## Examples

### No Args

#### Make assertions about every location property

```javascript
cy.visit('http://localhost:8000/app/index.html?q=dan#/users/123/edit')

cy.location().should((loc) => {
  expect(loc.hash).to.eq('#/users/123/edit')
  expect(loc.host).to.eq('localhost:8000')
  expect(loc.hostname).to.eq('localhost')
  expect(loc.href).to.eq(
    'http://localhost:8000/app/index.html?q=dan#/users/123/edit'
  )
  expect(loc.origin).to.eq('http://localhost:8000')
  expect(loc.pathname).to.eq('/app/index.html')
  expect(loc.port).to.eq('8000')
  expect(loc.protocol).to.eq('http:')
  expect(loc.search).to.eq('?q=dan')
  expect(loc.searchParams.get('q')).to.eq('dan')
})
```

#### Check location for query params and pathname

Pass a callback to [`.should()`](/api/commands/should) to work with the
location object directly. Cypress retries the callback until every assertion in
it passes.

```javascript
cy.get('#search').type('niklas{enter}')
cy.location().should((loc) => {
  expect(loc.search).to.eq('?search=niklas')
  expect(loc.pathname).to.eq('/users')
})
```

### Key

#### Assert that a redirect works

Grab only the `pathname` and add an assertion.

```javascript
cy.visit('http://localhost:3000/admin')
cy.location('pathname').should('eq', '/login')
```

#### Read a query parameter

`searchParams` yields a `URLSearchParams` object, so you can call its methods
with [`.invoke()`](/api/commands/invoke).

```javascript
cy.visit('http://localhost:3000/users?page=2&sort=name')
cy.location('searchParams').invoke('get', 'sort').should('eq', 'name')
```

## Notes

### Native Location

#### No need to use `window.location`

`cy.location()` reads the current URL of the application under test from the
browser and yields a plain object with the properties listed under
[Yields](#Yields). It isn't the `window.location` object, so it has none of that
object's methods, such as `assign()`, `reload()`, or `toString()`. Read `href`
when you need the full URL as a string.

Changing a property on the real `window.location` object navigates the browser
away. Changing a property on the object `cy.location()` yields has no effect on
navigation.

#### Reading the location after a cross-origin navigation

Cypress reads the URL through the browser's automation protocol instead of the
application's `window`, so `cy.location()` works after your application
navigates to another origin, without wrapping it in
[`cy.origin()`](/api/commands/origin).

## Rules

<HeaderRequirements />

- `cy.location()` requires being chained off of `cy`.

<HeaderAssertions />

- `cy.location()` automatically [retries](/app/core-concepts/retry-ability)
  until all chained assertions have passed

<HeaderTimeouts />

- `cy.location()` can time out waiting for assertions you've added to pass.
