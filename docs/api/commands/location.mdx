# location

Get the URL of the page that is currently active as a location object, or one part of that URL.

## Syntax

```javascript
cy.location()
cy.location(key)
cy.location(options)
cy.location(key, options)
```

### Usage

<Icon name="check-circle" color="green" /> **Correct Usage**

```javascript
cy.location() // Get location object
cy.location('host') // Get the host of the location object
cy.location('port') // Get the port of the location object
```

<Icon name="exclamation-triangle" color="red" /> **Incorrect Usage**

```javascript
cy.get('a').location() // Ignores the link, yields the page's location
cy.location('assign') // Errors, the location object has no assign key
```

`cy.location()` reads the page's URL, not an element's `href`. To check where a
link points, assert on the link's own properties instead:

```javascript
cy.get('a').should('have.prop', 'pathname', '/users')
```

### Arguments

<Icon name="angle-right" /> **key _(String)_**

One of the properties listed under [Yields](#Yields), such as `'pathname'`.
`cy.location()` yields that property's value instead of the full location
object, and fails when the location object has no property named `key`.

<Icon name="angle-right" /> **options _(Object)_**

Pass in an options object to change the default behavior of `cy.location()`.

| Option    | Default                                                           | Description                                                                         |
| --------- | ----------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| `log`     | `true`                                                            | Displays the command in the [Command Log](/app/core-concepts/open-mode#Command-Log) |
| `timeout` | [`defaultCommandTimeout`](/app/references/configuration#Timeouts) | Time to wait for `cy.location()` to resolve before [timing out](#Timeouts)          |

<HeaderYields />

`cy.location()` is a query, and it is _safe_ to chain further commands.

#### When not given a `key` argument

`cy.location()` yields a plain object with these properties. The example values
are for the URL `https://example.com:8080/app/users?tab=1#section`.

| Property       | Type                                                                                  | Example value                                        |
| -------------- | ------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| `hash`         | string                                                                                | `'#section'`                                         |
| `host`         | string                                                                                | `'example.com:8080'`                                 |
| `hostname`     | string                                                                                | `'example.com'`                                      |
| `href`         | string                                                                                | `'https://example.com:8080/app/users?tab=1#section'` |
| `origin`       | string                                                                                | `'https://example.com:8080'`                         |
| `pathname`     | string                                                                                | `'/app/users'`                                       |
| `port`         | string                                                                                | `'8080'`                                             |
| `protocol`     | string                                                                                | `'https:'`                                           |
| `search`       | string                                                                                | `'?tab=1'`                                           |
| `searchParams` | [`URLSearchParams`](https://developer.mozilla.org/en-US/docs/Web/API/URLSearchParams) | `searchParams.get('tab')` returns `'1'`              |

#### When given a `key` argument

- `cy.location()` yields the value of that property: a string, or a
  `URLSearchParams` object for `searchParams`
- `cy.location()` fails when the location object has no property named `key`

## Examples

### Key argument

#### Assert that a redirect works

Grab only the `pathname` and add an assertion.

```javascript
cy.visit('http://localhost:3000/admin')
cy.location('pathname').should('eq', '/login')
```

#### Wait longer for a slow redirect

Pass a `timeout` when a redirect takes longer than
[`defaultCommandTimeout`](/app/references/configuration#Timeouts), such as after
a login request. Cypress retries the assertion until the pathname matches or the
timeout passes.

```javascript
cy.get('[data-cy="login"]').click()
cy.location('pathname', { timeout: 10000 }).should('eq', '/dashboard')
```

#### Match a pathname that contains a generated ID

When your application creates a record and navigates to it, the ID in the URL
isn't known ahead of time. Match the pathname against a regular expression
instead.

```javascript
cy.get('[data-cy="create-user"]').click()
cy.location('pathname').should('match', /^\/users\/\d+$/)
```

#### Save part of the URL for later in the test

Transform the value in [`.then()`](/api/commands/then) and save it with
[`.as()`](/api/commands/as) to use it in a later command.

```javascript
cy.location('pathname')
  .then((pathname) => pathname.split('/').pop())
  .as('userId')

cy.get('@userId').then((userId) => {
  cy.request(`/api/users/${userId}`).its('status').should('eq', 200)
})
```

### No arguments

#### Make assertions about every location property

```javascript
cy.visit('http://localhost:8000/app/index.html?q=dan#/users/123/edit')

cy.location().should((loc) => {
  expect(loc.hash).to.eq('#/users/123/edit')
  expect(loc.host).to.eq('localhost:8000')
  expect(loc.hostname).to.eq('localhost')
  expect(loc.href).to.eq(
    'http://localhost:8000/app/index.html?q=dan#/users/123/edit'
  )
  expect(loc.origin).to.eq('http://localhost:8000')
  expect(loc.pathname).to.eq('/app/index.html')
  expect(loc.port).to.eq('8000')
  expect(loc.protocol).to.eq('http:')
  expect(loc.search).to.eq('?q=dan')
  expect(loc.searchParams.get('q')).to.eq('dan')
})
```

#### Check location for query params and pathname

Pass a callback to [`.should()`](/api/commands/should) to work with the
location object directly. Cypress retries the callback until every assertion in
it passes.

```html title="index.html"
<form action="/users">
  <input id="search" name="search" />
</form>
```

```javascript title="spec.cy.js"
cy.visit('http://localhost:3000/')
cy.get('#search').type('niklas{enter}')
cy.location().should((loc) => {
  expect(loc.search).to.eq('?search=niklas')
  expect(loc.pathname).to.eq('/users')
})
```

### Query parameters

#### Read a query parameter

`searchParams` yields a `URLSearchParams` object, so you can call its methods
with [`.invoke()`](/api/commands/invoke).

```javascript
cy.visit('http://localhost:3000/users?page=2&sort=name')
cy.location('searchParams').invoke('get', 'sort').should('eq', 'name')
```

#### Assert on query parameters in any order

Comparing `search` to a string fails when your application writes the same
parameters in a different order. Asserting on `searchParams` checks each
parameter by name, and `getAll()` reads a parameter that appears more than once.

```javascript
cy.visit('http://localhost:3000/posts?sort=name&tag=cypress&page=2&tag=testing')
cy.location('searchParams').should((params) => {
  expect(params.get('page')).to.eq('2')
  expect(params.get('sort')).to.eq('name')
  expect(params.getAll('tag')).to.deep.eq(['cypress', 'testing'])
})
```

### Cross-origin redirects

#### Assert that sign-in redirects to an identity provider

`cy.location()` reads the URL after your application navigates to another
origin, so you can confirm where a sign-in flow landed before you interact with
that page inside [`cy.origin()`](/api/commands/origin).

```javascript
cy.visit('http://localhost:3000/')
cy.contains('a', 'Sign in').click()

cy.location('origin').should('eq', 'http://auth.example.com')
cy.location('searchParams')
  .invoke('get', 'redirect_uri')
  .should('eq', 'http://localhost:3000/callback')

cy.origin('http://auth.example.com', () => {
  cy.get('input[name="email"]').type('user@example.com')
})
```

## Notes

### `cy.location()` yields a plain object, not `window.location`

`cy.location()` reads the current URL of the application under test from the
browser and yields a plain object with the properties listed under
[Yields](#Yields). It has none of the `window.location` methods, such as
`assign()` or `reload()`. Read `href` when you need the full URL as a string.

Changing a property on the real `window.location` object navigates the browser
away. Changing a property on the object `cy.location()` yields has no effect on
navigation.

Logging the yielded object shows only its URL properties:

```javascript
cy.location().then((loc) => {
  console.log(loc)
})
```

### Cross-origin pages and `cy.location()`

Cypress reads the URL through the browser's automation protocol instead of the
application's `window`, so `cy.location()` works after your application
navigates to another origin, without wrapping it in
[`cy.origin()`](/api/commands/origin). See
[Assert that sign-in redirects to an identity provider](#Assert-that-sign-in-redirects-to-an-identity-provider).

### Choosing between `cy.location()`, `cy.url()`, and `cy.hash()`

All three commands read the same URL from the browser. Use the one that yields
what you're asserting on:

- [`cy.url()`](/api/commands/url) yields the full URL as a string, the same
  value as `cy.location('href')`
- [`cy.hash()`](/api/commands/hash) yields the fragment, the same value as
  `cy.location('hash')`
- `cy.location()` yields any other part of the URL, such as `pathname`, `host`,
  or `searchParams`, or the whole location object

In a hash-based route, a query string after the `#` belongs to the hash, so
`search` and `searchParams` don't include it. See
[Query strings inside a hash route](/api/commands/hash#Query-strings-inside-a-hash-route).

### Pass a key instead of chaining `.its()`

`cy.location('pathname')` and `cy.location().its('pathname')` both retry until
the assertion that follows passes. Passing the key reads more clearly and shows
the key next to `location` in the Command Log.

```javascript
cy.location('pathname').should('eq', '/users')
```

## Rules

<HeaderRequirements />

- `cy.location()` requires being chained off of `cy`.

<HeaderAssertions />

- `cy.location()` automatically [retries](/app/core-concepts/retry-ability)
  until all chained assertions have passed

<HeaderTimeouts />

- `cy.location()` can time out waiting for the browser to report the page's
  URL.
- `cy.location()` can time out waiting for assertions you've added to pass.
