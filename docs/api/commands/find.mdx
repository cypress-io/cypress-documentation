# find

Get the descendant DOM elements that match a selector.

`.find()` searches every level below the subject, as opposed to
[`.children()`](/api/commands/children), which only looks one level down.

:::info

The querying behavior of this command matches how
[`.find()`](https://api.jquery.com/find) works in jQuery. The exception is the
`includeShadowDom` option, which also searches inside shadow roots, something
jQuery does not do.

:::

## Syntax

```javascript
.find(selector)
.find(selector, options)
```

### Usage

<Icon name="check-circle" color="green" /> **Correct Usage**

```javascript
cy.get('.article').find('footer') // Yield 'footer' within '.article'
```

<Icon name="exclamation-triangle" color="red" /> **Incorrect Usage**

```javascript
cy.find('.progress') // Errors, cannot be chained off 'cy'
cy.task('log', 'hello').find('li') // Errors, 'task' does not yield DOM elements
```

### Arguments

<Icon name="angle-right" /> **selector _(String selector)_**

A selector used to match descendant DOM elements.

<Icon name="angle-right" /> **options _(Object)_**

Pass in an options object to change the default behavior of `.find()`.

| Option             | Default                                                                        | Description                                                                                                       |
| ------------------ | ------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| `log`              | `true`                                                                         | Displays the command in the [Command log](/app/core-concepts/open-mode#Command-Log)                               |
| `timeout`          | [`defaultCommandTimeout`](/app/references/configuration#Timeouts)              | Time to wait for `.find()` to resolve before [timing out](#Timeouts)                                              |
| `includeShadowDom` | [`includeShadowDom` config option value](/app/references/configuration#Global) | Whether to also search inside the shadow roots of the subject and its descendants, including nested shadow roots. |

<HeaderYields />

- `.find()` yields the new DOM element(s) it found.
- `.find()` is a query, and it is _safe_ to chain further commands.

## Examples

### Selector

#### Get li's within parent

```html
<ul id="parent">
  <li class="first"></li>
  <li class="second"></li>
</ul>
```

```javascript
// yields [<li class="first"></li>, <li class="second"></li>]
cy.get('#parent').find('li')
```

#### Find direct children with a leading combinator

Start the selector with `>` to match only direct children of the subject. The
result is the same as [`.children('li')`](/api/commands/children).

```html
<ul class="nav">
  <li>Home</li>
  <li>
    Docs
    <ul>
      <li>API</li>
    </ul>
  </li>
</ul>
```

```javascript
// yields [<li>Home</li>, <li>Docs<ul>…</ul></li>]
cy.get('.nav').find('> li')

// yields all 3 li elements, including the nested one
cy.get('.nav').find('li')
```

### Assertions

#### Assert on the number of elements found

When `.find()` is chained off another query such as
[`cy.get()`](/api/commands/get), Cypress reruns the whole chain until the
assertion passes, so the count stays current as the page updates.

```javascript
cy.get('[data-cy=cart]').find('[data-cy=cart-item]').should('have.length', 3)
```

#### Assert that an element no longer exists

Chain `.should('not.exist')` to wait for an element, such as a loading spinner,
to leave the subject.

```javascript
cy.get('[data-cy=results]').find('.spinner').should('not.exist')
```

### Options

#### Wait longer for slow content

Pass `timeout` to give `.find()` more time than
[`defaultCommandTimeout`](/app/references/configuration#Timeouts) to locate its
elements.

```javascript
cy.get('[data-cy=report]').find('table', { timeout: 10000 })
```

#### Find elements inside a shadow root

By default, `.find()` does not search inside shadow roots. Pass
`includeShadowDom: true` to search them, or set the
[`includeShadowDom` configuration option](/app/references/configuration#Global)
to search them in every query.

```html
<checkout-panel>
  #shadow-root
  <button>Checkout</button>
</checkout-panel>
```

```javascript
// yields [<button>Checkout</button>]
cy.get('checkout-panel').find('button', { includeShadowDom: true })
```

## Notes

### `.find()` only searches below the subject

`.find()` matches descendants of the subject, never the subject itself. An
element that matches the selector is left out of the result when it is the
subject.

```html
<div class="card">
  <div class="card">Nested</div>
</div>
```

```javascript
// yields [<div class="card">Nested</div>], not the outer .card
cy.get('.card').first().find('.card')
```

### Subjects with multiple elements

When the subject holds more than one element, `.find()` searches inside each
one and yields a single set, in document order, with any duplicates removed.

```html
<ul>
  <li><a href="/home">Home</a></li>
  <li><a href="/docs">Docs</a></li>
</ul>
```

```javascript
// yields [<a href="/home">Home</a>, <a href="/docs">Docs</a>]
cy.get('li').find('a')
```

### `.find()` compared to `.within()`

Chain `.find()` when you run one query inside an element.
[`.within()`](/api/commands/within) scopes every command in its callback to the
subject, which reads better when you run several commands against the same
region.

```javascript
// One query
cy.get('[data-cy=login-form]').find('[data-cy=submit]').click()

// Several commands in the same region
cy.get('[data-cy=login-form]').within(() => {
  cy.get('[data-cy=email]').type('user@example.com')
  cy.get('[data-cy=password]').type('secret')
  cy.get('[data-cy=submit]').click()
})
```

### Reading a `.find()` timeout error

When `.find()` times out without finding its elements, the error names the
selector and lists the query chain it ran from. The chain shows whether the
problem is the `.find()` selector or an earlier query that yielded a different
element than you expected.

```javascript
cy.get('[data-cy=cart]').find('.total')
```

```text
Expected to find element: `.total`, but never found it. Queried from:

  > cy.get([data-cy=cart]).find(.total)
```

### Shadow DOM boundaries and `.find()`

Without `includeShadowDom`, `.find()` stops at a shadow boundary: it searches
the markup written inside a shadow host, not the host's shadow root. Chained off
an element that is already inside a shadow root, it searches that shadow tree
normally, with or without the option. To search one shadow root only, traverse
into it with [`.shadow()`](/api/commands/shadow) first:

```javascript
cy.get('checkout-panel').shadow().find('button')
```

## Rules

<HeaderRequirements />

- `.find()` requires being chained off a command that yields DOM element(s) or a
  document.

<HeaderAssertions />

- `.find()` will automatically [retry](/app/core-concepts/retry-ability)
  until the element(s)
  [exist in the DOM](/app/core-concepts/introduction-to-cypress#Implicit-Assertions).
- `.find()` will automatically [retry](/app/core-concepts/retry-ability)
  until all chained assertions have passed.

<HeaderTimeouts />

- `.find()` can time out waiting for the element(s) to
  [exist in the DOM](/app/core-concepts/introduction-to-cypress#Implicit-Assertions).
- `.find()` can time out waiting for assertions you've added to pass.
