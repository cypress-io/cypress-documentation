# request

Make an HTTP request.

## Syntax

```javascript
cy.request(url)
cy.request(url, body)
cy.request(method, url)
cy.request(method, url, body)
cy.request(options)
```

### Usage

<Icon name="check-circle" color="green" /> **Correct Usage**

```javascript
cy.request('http://dev.local/seed')
```

### Arguments

<Icon name="angle-right" /> **url _(String)_**

The URL to make the request to.

If you do not provide a fully qualified domain name (FQDN) URL, Cypress resolves
the host for `cy.request()` in this order:

1. If the `baseUrl` property is set in your
   [configuration file](/app/references/configuration), Cypress prefixes the URL
   with it. This applies whether or not you have visited a page, so `baseUrl`
   wins over the origin of a page you visited.

:::cypress-config-example

```ts
{
  e2e: {
    baseUrl: 'http://localhost:1234'
  }
}
```

:::

```javascript
cy.request('seed/admin') // URL is http://localhost:1234/seed/admin
```

2. If no `baseUrl` is set and you have visited a page, Cypress uses the origin of
   the URL used for the `cy.visit()`.

```javascript
cy.visit('http://localhost:8080/app')
cy.request('users/1.json') //  URL is  http://localhost:8080/users/1.json
```

3. If Cypress cannot determine the host, it throws an error.

<Icon name="angle-right" /> **body _(String, Object, FormData, Blob)_**

A request `body` to be sent in the request. When `body` is a JavaScript object
or boolean, Cypress automatically JSON-serializes it and sets the
`Content-Type: application/json` request header, unless you set a `Content-Type`
in `headers`. When `body` is a string, it is
sent as-is with no automatic content-type. When `body` is a `FormData`
instance, Cypress sends it as `multipart/form-data`, which is how you
[upload a file](#Upload-a-file-with-multipartform-data).

<Icon name="angle-right" /> **method _(String)_**

Make a request using a specific method. If no method is defined, Cypress uses
the `GET` method by default.

Supported methods include:

- `GET`
- `POST`
- `PUT`
- `DELETE`
- `PATCH`
- `HEAD`
- `OPTIONS`
- `TRACE`
- `COPY`
- `QUERY`
- `LOCK`
- `MKCOL`
- `MOVE`
- `PURGE`
- `PROPFIND`
- `PROPPATCH`
- `UNLOCK`
- `REPORT`
- `MKACTIVITY`
- `CHECKOUT`
- `MERGE`
- `M-SEARCH`
- `NOTIFY`
- `SUBSCRIBE`
- `UNSUBSCRIBE`
- `SEARCH`
- `CONNECT`

<Icon name="angle-right" /> **options _(Object)_**

Pass in an options object to change the default behavior of `cy.request()`.

| Option                     | Default                                                     | Description                                                                                                                                                                                                                                    |
| -------------------------- | ----------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `log`                      | `true`                                                      | Displays the command in the [Command log](/app/core-concepts/open-mode#Command-Log)                                                                                                                                                            |
| `url`                      | `null`                                                      | The URL to make the request to                                                                                                                                                                                                                 |
| `method`                   | `GET`                                                       | The HTTP method to use in the request                                                                                                                                                                                                          |
| `auth`                     | `null`                                                      | Adds an `Authorization` header for [HTTP Basic Authentication](#HTTP-Basic-Authentication), or a bearer token with `bearer`                                                                                                                    |
| `body`                     | `null`                                                      | Body to send along with the request                                                                                                                                                                                                            |
| `failOnStatusCode`         | `true`                                                      | Whether to fail on response codes other than `2xx` and `3xx`                                                                                                                                                                                   |
| `followRedirect`           | `true`                                                      | Whether to automatically follow redirects                                                                                                                                                                                                      |
| `form`                     | `false`                                                     | Whether to convert the `body` values to URL encoded content and set the `x-www-form-urlencoded` header                                                                                                                                         |
| `encoding`                 | `utf8`                                                      | The encoding to be used when serializing the response body. The following encodings are supported: `ascii`, `base64`, `binary`, `hex`, `latin1`, `utf8`, `utf-8`, `ucs2`, `ucs-2`, `utf16le`, `utf-16le`                                       |
| `gzip`                     | `true`                                                      | Whether to accept the `gzip` encoding                                                                                                                                                                                                          |
| `headers`                  | `null`                                                      | Additional headers to send; accepts an object literal. Cypress also sends them on any redirect it follows, except that it drops `Content-Type` and `Content-Length`, and drops `Authorization` when the redirect changes the hostname.         |
| `qs`                       | `null`                                                      | Query parameters to append to the `url` of the request                                                                                                                                                                                         |
| `retryOnStatusCodeFailure` | `false`                                                     | Whether Cypress should automatically retry status code errors under the hood. Cypress will retry a request up to 4 times if this is set to true. Requires `failOnStatusCode: true`; setting it with `failOnStatusCode: false` throws an error. |
| `retryOnNetworkFailure`    | `true`                                                      | Whether Cypress should automatically retry transient network errors (such as `ECONNREFUSED`, `ECONNRESET`, or `ENOTFOUND`) under the hood. Cypress will retry a request up to 4 times if this is set to true.                                  |
| `timeout`                  | [`responseTimeout`](/app/references/configuration#Timeouts) | Time to wait for `cy.request()` to resolve before [timing out](#Timeouts)                                                                                                                                                                      |

You can also set options for `cy.request()`'s `baseUrl` and `responseTimeout`
globally in the [Cypress configuration](/app/references/configuration).

<HeaderYields />

`cy.request()` yields the `response` as an object literal containing these
properties:

- `status`: the response status code
- `statusText`: the status message, such as `OK` or `Found`
- `isOkStatusCode`: `true` when `status` is `2xx` or `3xx`
- `body`: the response body
- `headers`: the response headers
- `duration`: how long the request took, in milliseconds
- `requestHeaders`: the headers Cypress sent with the request
- `allRequestResponses`: each request and response in the chain, including
  redirects
- `redirects`: each redirect Cypress followed, as `status: url` strings (only
  present when a redirect was followed)
- `redirectedToUrl`: the URL the response redirects to (only present with
  `followRedirect: false`)

The `response.body` is automatically parsed as a JavaScript object when the
response has a `Content-Type` header whose value ends in `json` (such as
`application/json` or `application/vnd.api+json`). When the request `body` is an
object or boolean, Cypress also parses any response body that is valid JSON,
whatever its `Content-Type`. Otherwise, `response.body` is a string.

## Examples

### URL

#### Make a `GET` request

`cy.request()` is great for talking to an external endpoint before your tests to
seed a database.

```javascript
beforeEach(() => {
  cy.request('http://localhost:8080/db/seed')
})
```

#### Issue an HTTP request

Sometimes it's quicker to test the contents of a page rather than
[`cy.visit()`](/api/commands/visit) and wait for the entire page and all of its
resources to load.

```javascript
cy.request('/admin').its('body').should('include', '<h1>Admin</h1>')
```

### Method and URL

#### Send a `DELETE` request

```javascript
cy.request('DELETE', 'http://localhost:8888/users/827')
```

#### Alias the request using [.as()](/api/commands/as)

```javascript
cy.request('https://jsonplaceholder.cypress.io/comments').as('comments')

cy.get('@comments').should((response) => {
  expect(response.body).to.have.length(500)
  expect(response).to.have.property('headers')
  expect(response).to.have.property('duration')
})
```

### Method, URL, and Body

#### Send a `POST` request with a JSON body

```javascript
cy.request('POST', 'http://localhost:8888/users/admin', { name: 'Jane' }).then(
  (response) => {
    // response.body is automatically parsed from JSON when the server responds
    // with a Content-Type ending in "json" (e.g. application/json)
    expect(response.body).to.have.property('name', 'Jane') // true
  }
)
```

### Options

#### Request a page while disabling auto redirect

To test the redirection behavior of a login without a session, `cy.request` can
be used to check the `status` and `redirectedToUrl` property.

The `redirectedToUrl` property is a special Cypress property that normalizes the
URL the browser would normally follow during a redirect.

```javascript
cy.request({
  url: '/dashboard',
  followRedirect: false, // turn off following redirects
}).then((resp) => {
  // redirect status code is 302
  expect(resp.status).to.eq(302)
  expect(resp.redirectedToUrl).to.eq('http://localhost:8082/unauthorized')
})
```

#### Check every redirect `cy.request()` followed

When Cypress follows redirects, `response.redirects` lists each hop as the status
code and the absolute URL it redirected to. Use it to confirm that an old route
lands on the right page, and with the right status code.

```javascript
cy.request('/old-dashboard').then((response) => {
  expect(response.redirects).to.deep.eq([
    '301: http://localhost:8080/dashboard',
  ])
  expect(response.status).to.eq(200)
})
```

#### Test an error response with `failOnStatusCode: false`

By default, a status code other than `2xx` or `3xx` fails the test. Set
`failOnStatusCode: false` to get the response back instead, so you can assert on
the status code and the error your API returns.

```javascript
cy.request({
  url: '/api/users/999',
  failOnStatusCode: false,
}).then((response) => {
  expect(response.status).to.eq(404)
  expect(response.body).to.have.property('error', 'User not found')
})
```

#### Send query parameters with `qs`

The `qs` option builds the query string for you. Cypress merges it with any
query string already in the `url`, rather than replacing it.

```javascript
cy.request({
  url: '/api/users?active=true',
  qs: { page: 2, limit: 10 },
})
// requests /api/users?active=true&page=2&limit=10
```

#### HTTP Basic Authentication

To send a request to an endpoint protected by
[HTTP Basic Authentication](https://developer.mozilla.org/en-US/docs/Web/HTTP/Authentication),
provide the credentials with the `auth` option. Cypress base64-encodes them and
attaches an `Authorization` header to the request.

Read credentials with [`cy.env()`](/api/commands/env) rather than writing them
into the test, so they stay out of your spec files and your Command Log. The
examples on this page read `username`, `password`, and `apiToken`, which you set
as described in
[Environment Variables & Secrets](/app/guides/environment-variables).

```javascript
cy.env(['username', 'password']).then(({ username, password }) => {
  cy.request({
    method: 'POST',
    url: '/api/query',
    auth: {
      username,
      password,
    },
    body: {
      cpId: 709916,
    },
  })
})
```

The `auth` option also accepts `user`/`pass` as aliases for
`username`/`password`. To send a bearer token instead, pass it as `bearer`, and
Cypress sends `Authorization: Bearer <token>`.

```javascript
cy.env(['apiToken']).then(({ apiToken }) => {
  cy.request({
    url: '/api/profile',
    auth: {
      bearer: apiToken,
    },
  })
})
```

:::caution

When a request fails on its status code, the error message prints the headers
and body Cypress sent, credentials included, even with `log: false`. To keep a
secret out of a failure, pass `failOnStatusCode: false` and assert on the status
code yourself, as the
[API login example](#Log-in-through-the-API-and-cache-it-with-cysession) does.

:::

#### Download a PDF file

By passing the `encoding: binary` option, the `response.body` will be serialized
binary content of the file. You can use this to access various file types via
`.request()` like `.pdf`, `.zip`, or `.doc` files.

```javascript
cy.request({
  url: 'http://localhost:8080/some-document.pdf',
  encoding: 'binary',
}).then((response) => {
  cy.writeFile('path/to/save/document.pdf', response.body, 'binary')
})
```

#### Get Data URL of an image

By passing the `encoding: base64` option, the `response.body` will be
base64-encoded content of the image. You can use this to construct a
[Data URI](https://developer.mozilla.org/en-US/docs/Web/HTTP/Basics_of_HTTP/Data_URIs)
for use elsewhere.

```javascript
cy.request({
  url: 'https://docs.cypress.io/img/logo/cypress-logo-circle-dark.png',
  encoding: 'base64',
}).then((response) => {
  const base64Content = response.body
  const mime = response.headers['content-type'] // or 'image/png'
  // see https://developer.mozilla.org/en-US/docs/Web/HTTP/Basics_of_HTTP/Data_URIs
  const imageDataUrl = `data:${mime};base64,${base64Content}`
})
```

#### Upload a file with `multipart/form-data`

To upload a file, build a
[`FormData`](https://developer.mozilla.org/en-US/docs/Web/API/FormData) object
and pass it as the `body`. Cypress encodes each field, sends the file's bytes
unchanged, and sets the `Content-Type: multipart/form-data` header with the
boundary the server needs to parse the parts. Leave `form` unset, since it
applies to URL-encoded forms only.

This is the `cy.request()` equivalent of `curl -F file=@image.png`:

```javascript
// image fixtures are read as base64 by default
cy.env(['apiToken']).then(({ apiToken }) => {
  cy.fixture('image.png').then((image) => {
    const formData = new FormData()

    formData.append(
      'file',
      Cypress.Blob.base64StringToBlob(image, 'image/png'),
      'image.png'
    )

    cy.request({
      method: 'POST',
      url: '/api/action/upload_file',
      headers: {
        Authorization: `Bearer ${apiToken}`,
      },
      body: formData,
    })
      .its('status')
      .should('eq', 200)
  })
})
```

The third argument to `formData.append()` sets the filename the server
receives. Without it, the part is sent with the filename `blob`. Plain string
fields go in the same object, such as `formData.append('description', 'Avatar')`.

#### HTML form submissions using form option

Oftentimes, once you have a proper e2e test around logging in, there's no reason
to continue to `cy.visit()` the login and wait for the entire page to load all
associated resources before running any other commands. Doing so can slow down
our entire test suite.

Using `cy.request()`, we can bypass all of this because it automatically gets
and sets cookies as if the requests had come from the browser.

```javascript
cy.env(['username', 'password']).then(({ username, password }) => {
  cy.request({
    method: 'POST',
    url: '/login_with_form', // baseUrl is prepended to the URL
    form: true, // sends the body URL-encoded with Content-Type: application/x-www-form-urlencoded
    body: {
      username,
      password,
    },
    log: false, // keeps the credentials out of the Command Log
  })
})

// to prove we have a session
cy.getCookie('cypress-session-cookie').should('exist')
```

### API workflows

#### Log in through the API and cache it with `cy.session()`

Logging in with `cy.request()` skips the login page, and wrapping it in
[`cy.session()`](/api/commands/session) runs the login once and restores the
session cookie in later tests. The `validate` function checks that the cached
session still works before each test reuses it.

`log: false` keeps the password out of the Command Log, and
`failOnStatusCode: false` keeps it out of the error message if the login fails.
The assertion then checks only the status code.

```javascript
beforeEach(() => {
  cy.session(
    'api-login',
    () => {
      cy.env(['username', 'password']).then(({ username, password }) => {
        cy.request({
          method: 'POST',
          url: '/api/login',
          body: { username, password },
          log: false,
          failOnStatusCode: false,
        }).then((response) => {
          expect(response.status, 'login status').to.eq(200)
        })
      })
    },
    {
      validate() {
        cy.request('/api/me').its('status').should('eq', 200)
      },
    }
  )
})

it('shows the dashboard to a logged-in user', () => {
  cy.visit('/dashboard')
  cy.contains('h1', 'Dashboard')
})
```

#### Create a record, then use its ID in later requests

Seed the data a test needs, then use what the API returns. Here the `id` from
the `POST` response drives the `GET` and the `DELETE` that cleans up.

```javascript
cy.request('POST', '/api/users', { name: 'Jane' })
  .its('body.id')
  .then((id) => {
    cy.request(`/api/users/${id}`).its('body.name').should('eq', 'Jane')
    cy.request('DELETE', `/api/users/${id}`).its('status').should('eq', 204)
  })
```

#### Assert on the status, headers, and response time

Every response carries its `status`, its `headers`, and the `duration` of the
request in milliseconds, so one request can check all three.

```javascript
cy.request('/api/users').then((response) => {
  expect(response.status).to.eq(200)
  expect(response.headers['content-type']).to.include('application/json')
  expect(response.duration).to.be.lessThan(500)
})
```

#### Type the response body in TypeScript

`cy.request()` takes a type argument for the response body, so `response.body`
is typed in your editor instead of `any`.

```typescript copyTsToJs
interface User {
  id: number
  name: string
}

cy.request<User>('/api/users/1').then((response) => {
  expect(response.body.name).to.eq('Jane')
})
```

#### Poll an endpoint until a job finishes

To wait for work the server does in the background, call `cy.request()` from a
function that calls itself until the response shows the job is done. The
`attempts` count stops the loop, so a job that never finishes fails the test
rather than polling forever.

```javascript
function waitForJob(id, attempts = 10) {
  if (attempts === 0) {
    throw new Error(`Job ${id} did not finish`)
  }

  cy.request(`/api/jobs/${id}`).then(({ body }) => {
    if (body.status !== 'done') {
      cy.wait(500)
      waitForJob(id, attempts - 1)
    }
  })
}

cy.request('POST', '/api/jobs', { type: 'export' })
  .its('body.id')
  .then((id) => {
    waitForJob(id)
  })
```

For a version that yields the finished job so you can assert on it, see
[Poll an asynchronous job](/app/guides/api-testing#Poll-an-asynchronous-job).

## Notes

### JSON request and response bodies

#### Request body serialization

When `body` is a JavaScript **object or boolean** and `form` is not `true`,
Cypress automatically:

1. JSON-serializes the request body.
2. Adds a `Content-Type: application/json` header to the request, unless you
   set a `Content-Type` in `headers`, such as `application/vnd.api+json`.

When `body` is a **string**, it is sent as-is and no `Content-Type` header is
added automatically.

When `body` is a **`FormData`** instance, Cypress:

1. Encodes each field as a part of a `multipart/form-data` body. A `File` or
   `Blob` field keeps its filename and type, and defaults to
   `application/octet-stream` when it has no type.
2. Sets the `Content-Type: multipart/form-data` header with the boundary that
   separates the parts. This replaces a `Content-Type` header you pass in
   `headers`, such as `multipart/form-data` without a boundary, so you don't
   need to set one.

Don't combine a `FormData` body with `form: true` or an
`application/x-www-form-urlencoded` header. Either one sends the body down the
URL-encoded form path, and the request fails with a network-level error.

When `body` is a **`Blob`**, Cypress sends its bytes as-is and no `Content-Type`
header is added automatically. Set one in `headers` if your server expects it.

#### Response body parsing

Cypress always inspects the `Content-Type` header of the response. If that
header's value ends in `json` (for example `application/json` or
`application/vnd.api+json`), `response.body` is automatically parsed into a
JavaScript object.

The request `body` matters too. When it is an object or boolean, the request is
sent as JSON, and Cypress parses any response body that is valid JSON, even when
the server sends it as `text/plain` or with no `Content-Type` at all.

In every other case, `response.body` is a string.

### Debugging

#### Request is not displayed in the Network Tab of Developer Tools

Cypress does not _actually_ make an XHR request from the browser. We are
actually making the HTTP request from Cypress (in Node). So, you won't see the
request inside of your Developer Tools.

### CORS

#### CORS is bypassed

Normally when the browser detects a cross-origin HTTP request, it will send an
`OPTIONS` preflight check to ensure the server allows cross-origin requests, but
`cy.request()` bypasses CORS entirely.

```javascript
// docs.cypress.io sends no CORS headers, and cy.request() still succeeds
cy.request('https://docs.cypress.io').its('status').should('eq', 200)
```

### Cookies

#### Cookies are automatically sent and received

Before sending the HTTP request, we automatically attach cookies that would have
otherwise been attached had the request come from the browser. Additionally, if
a response has a `Set-Cookie` header, these are automatically set back on the
browser cookies.

In other words, `cy.request()` transparently performs all of the underlying
functions as if it came from the browser.

Cookies are pulled from the cookie jar by domain match. A cookie set without
`hostOnly: true` is a domain cookie, so it can be attached to a `cy.request()`
aimed at a _different_ host that domain-matches it (for example a sibling
subdomain on the same registrable domain). If a cookie shows up on a request
unexpectedly, see
[Cookie scope (host-only vs. domain cookies)](/api/commands/setcookie#Cookie-scope-host-only-vs-domain-cookies)
for how to scope it to a single exact host with `hostOnly: true`.

### [`cy.intercept()`](/api/commands/intercept)

#### `cy.request()` sends requests to actual endpoints, bypassing those defined using `cy.intercept()`

The intention of `cy.request()` is to be used for checking endpoints on an
actual, running server without having to start the front end application.

## Rules

<HeaderRequirements />

- `cy.request()` requires being chained off of `cy`.
- `cy.request()` requires that the server sends a response.
- `cy.request()` requires that the response status code be `2xx` or `3xx` when
  `failOnStatusCode` is `true`.

<HeaderAssertions />

- `cy.request()` will only run assertions you have chained once, and will not
  [retry](/app/core-concepts/retry-ability).

<HeaderTimeouts />

- `cy.request()` can time out waiting for the server to respond.
