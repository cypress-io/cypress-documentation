# visit

Load a URL in the application under test. `cy.visit()` waits for the page to
fire its `load` event, then yields the page's `window` object.

:::tip

We recommend setting a `baseUrl` when using `cy.visit()`. See
[Setting a global `baseUrl`](/app/core-concepts/best-practices#Setting-a-Global-baseUrl).

:::

## Syntax

```javascript
cy.visit(url)
cy.visit(url, options)
cy.visit(options)
```

### Usage

<Icon name="check-circle" color="green" /> **Correct Usage**

```javascript
cy.visit('/') // visits the baseUrl
cy.visit('index.html') // visits the local file "index.html" if baseUrl is null
cy.visit('http://localhost:3000') // specify a full URL if baseUrl is null or the host differs from baseUrl
cy.visit({
  url: '/pages/hello.html',
  method: 'GET',
})
```

### Arguments

<Icon name="angle-right" /> **url _(String)_**

The URL to visit.

When `baseUrl` is set, Cypress prefixes the URL with it. Without a `baseUrl`,
provide a fully qualified URL, or Cypress serves the path as a local file. See
[how `cy.visit()` prefixes URLs with `baseUrl`](#How-cyvisit-prefixes-URLs-with-baseUrl).

Visiting a new origin reloads the Cypress window. To visit a different origin
in the same test, use [`cy.origin()`](/api/commands/origin), even when the
origins share a superdomain (unless
[`injectDocumentDomain`](/app/references/configuration#injectDocumentDomain) is
enabled).

<Icon name="angle-right" /> **options _(Object)_**

Pass in an options object to control the behavior of `cy.visit()`.

| Option                     | Default                                                     | Description                                                                                                                                                                                |
| -------------------------- | ----------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `url`                      | `null`                                                      | The URL to visit. Cypress appends it to the `baseUrl` if one is configured. Behaves the same as the `url` argument.                                                                        |
| `method`                   | `GET`                                                       | The HTTP method to use in the visit. Can be `GET` or `POST`.                                                                                                                               |
| `body`                     | `null`                                                      | An optional body to send with a `POST` request. A string is sent unmodified. An object is URL encoded and sent with a `Content-Type: application/x-www-form-urlencoded` header.            |
| `headers`                  | `{}`                                                        | An object that maps HTTP header names to values to send with the request. Cypress sends `headers` only with the initial `cy.visit()` request, not with any later requests.                 |
| `qs`                       | `null`                                                      | Query parameters to append to the `url` of the request. Must be an object.                                                                                                                 |
| `log`                      | `true`                                                      | Displays the command in the [Command Log](/app/core-concepts/open-mode#Command-Log).                                                                                                       |
| `auth`                     | `null`                                                      | Adds Basic Authorization headers.                                                                                                                                                          |
| `failOnStatusCode`         | `true`                                                      | Whether to fail on response codes other than `2xx` and `3xx`.                                                                                                                              |
| `onBeforeLoad`             | none                                                        | Called before your page has loaded all of its resources.                                                                                                                                   |
| `onLoad`                   | none                                                        | Called once your page has fired its load event.                                                                                                                                            |
| `retryOnStatusCodeFailure` | `false`                                                     | Whether Cypress retries the request when the status code is outside `2xx` and `3xx`. When `true`, Cypress retries up to 4 times. Requires `failOnStatusCode` to be `true`.                 |
| `retryOnNetworkFailure`    | `true`                                                      | Whether Cypress retries the request after a transient network error. When `true`, Cypress retries up to 4 times.                                                                           |
| `timeout`                  | [`pageLoadTimeout`](/app/references/configuration#Timeouts) | Time to wait for `cy.visit()` to resolve before [timing out](#Timeouts). The request for the page can still time out sooner, at `responseTimeout` or the operating system's network limit. |

To change `pageLoadTimeout` and `baseUrl` for every `cy.visit()`, set them in
your [Cypress configuration](/app/references/configuration#Global).

<HeaderYields />

- `cy.visit()` yields the `window` object after the page finishes loading.
- It is [unsafe](/app/core-concepts/retry-ability#Only-queries-are-retried)
  to chain further commands that rely on the yielded `window` after
  `cy.visit()`.

This example confirms `window.navigator.language` after visiting the site:

```javascript
cy.visit('/') // yields the window object
  .its('navigator.language') // yields window.navigator.language
  .should('equal', 'en-US') // asserts the expected value
```

To work with the `window` directly, use `.then()`:

```javascript
cy.visit('index.html').then((contentWindow) => {
  // contentWindow is the remote page's window object
})
```

## Examples

### URL

#### Visit a local server running on `http://localhost:8000`

`cy.visit()` resolves when the remote page fires its `load` event.

```javascript
cy.visit('http://localhost:8000')
```

### Options

#### Change the `cy.visit()` page load timeout

The `timeout` option overrides the `pageLoadTimeout` from your
[configuration](/app/references/configuration#Timeouts) for this page load.

```javascript
// Wait 30 seconds for page 'load' event
cy.visit('/index.html', { timeout: 30000 })
```

#### Add basic auth headers to `cy.visit()`

Cypress applies the authorization headers an application needs when it uses
[Basic Authentication](https://developer.mozilla.org/en-US/docs/Web/HTTP/Authentication).

Provide the `username` and `password` in the `auth` object. Cypress then
attaches them at the network level to every later request to the origin you're
testing. Pass `log: false` to keep the credentials out of the Command Log. Without
it, clicking the `visit` row prints the `auth` object, password included, to the
console.

```javascript
cy.visit('https://example.cypress.io/', {
  auth: {
    username: 'wile',
    password: 'coyote',
  },
  log: false,
})
```

You can also provide the username and password directly in the URL. In this
form, the Command Log row shows the full URL, password included, so `log: false`
matters even more: without it, the password appears in screenshots and videos
of the run.

```javascript
// this is the same thing as providing the auth object
cy.visit('https://wile:coyote@example.cypress.io', { log: false })
```

:::info

Cypress attaches the `Authorization` header for you on requests to the origin
you visited. Other origins do not receive it. On the
[legacy network path](/app/guides/native-network-interception#Using-the-legacy-network-path)
the header is attached outside of the browser, so it does **not** appear in the
Dev Tools.

:::

#### Run code before the page loads with `onBeforeLoad`

Cypress calls `onBeforeLoad` as early as possible, before your page has loaded
all of its resources. Your app's scripts haven't run yet, so this is the place
to prepare the page before your app starts.

This example seeds a token in `localStorage` before the app reads it, and stubs
`window.open` so the test can assert on it:

```javascript
cy.visit('/#dashboard', {
  onBeforeLoad(win) {
    // win is the remote page's window object
    win.localStorage.setItem('token', 'abc123')
    cy.stub(win, 'open').as('windowOpen')
  },
})
cy.get('@windowOpen').should('not.have.been.called')
```

:::info

These recipes use the `onBeforeLoad` option to:

- [Bootstrap your App](/app/references/recipes#Server-Communication)
- [Set a token in `localStorage` for login during Single Sign On](/app/references/recipes#Logging-In)
- [Stub `window.fetch`](/app/references/recipes#Stubbing-and-spying)

:::

#### Run code after the page loads with `onLoad`

Cypress calls `onLoad` once your page has fired its `load` event. At this point,
all of the page's scripts, stylesheets, HTML, and other resources are available.

```javascript
cy.visit('/#/users', {
  onLoad: (contentWindow) => {
    // contentWindow is the remote page's window object
    if (contentWindow.angular) {
      // do something
    }
  },
})
```

#### Add query parameters to a `cy.visit()` URL

Pass query parameters as an object in the `qs` option.

```js
// visits <baseUrl>/users?page=1&role=admin
cy.visit('/users', {
  qs: {
    page: '1',
    role: 'admin',
  },
})
```

Cypress merges the parameters in `qs` into any query parameters already on the
`url`.

```js
// visits https://example.cypress.io/users?page=1&admin=true
cy.visit('https://example.cypress.io/users?page=1', {
  qs: { admin: true },
})
```

#### Submit a form with a `cy.visit()` POST request

To send a request that looks like a user submitting an HTML form, use a `POST`
method with a `body` containing the form values:

```javascript
cy.visit({
  url: '/cgi-bin/newsletterSignup',
  method: 'POST',
  body: {
    name: 'Avery Quinlan',
    email: 'avery.quinlan@example.com',
  },
})
```

#### Send custom request headers with `cy.visit()`

Pass `headers` to send extra HTTP headers with the page request, such as a
language preference or a feature flag your server reads. Cypress sends them
only with the initial `cy.visit()` request, not with the requests the page
makes afterward.

```javascript
cy.visit('/', {
  headers: { 'Accept-Language': 'fr-FR' },
})
cy.contains('Bienvenue')
```

#### Visit an error page with `failOnStatusCode: false`

By default, `cy.visit()` fails when the server responds with a status code
outside the `2xx` and `3xx` ranges. To test your 404 or 500 page, set
`failOnStatusCode` to `false` and assert on what the page shows:

```javascript
cy.visit('/does-not-exist', { failOnStatusCode: false })
cy.contains('h1', 'Page not found')
```

#### Retry `cy.visit()` while your server finishes starting

When your server answers with an error status for a few seconds after it
starts, such as a `503` in CI, set `retryOnStatusCodeFailure` to `true`.
Cypress retries the request up to 4 times before failing.

```javascript
cy.visit('/', { retryOnStatusCodeFailure: true })
```

### Workflows

#### Log in once with `cy.session()` and visit in each test

Pair `cy.visit()` with [`cy.session()`](/api/commands/session) to log in once,
cache the session, and restore it before each test. Call `cy.visit()` after
`cy.session()`, since Cypress clears the page each time it restores a session.

```javascript
beforeEach(() => {
  cy.session('user', () => {
    cy.visit('/login')
    cy.get('#username').type('user')
    cy.get('#password').type('s3cret', { log: false })
    cy.get('form').submit()
    cy.location('pathname').should('eq', '/dashboard')
  })
  cy.visit('/dashboard')
})
```

## Notes

### How `cy.visit()` prefixes URLs with `baseUrl`

When `baseUrl` is set, Cypress prefixes the URL with it. Configure `baseUrl` in
the [Cypress configuration](/app/references/configuration) so you don't repeat
the host in every `cy.visit()` command.

:::cypress-config-example

```ts
{
  e2e: {
    baseUrl: 'http://localhost:3000/#/',
  }
}
```

:::

```javascript
cy.visit('dashboard') // Visits http://localhost:3000/#/dashboard
```

To visit a different host while `baseUrl` is set, provide the fully qualified
URL.

```javascript
cy.visit('https://example.cypress.io')
```

### Visit local files with `cy.visit()`

Cypress serves your files itself when you don't provide a host and `baseUrl`
**is not defined**. The path is relative to your project's root folder (the directory that contains the
[Cypress configuration file](/app/references/configuration)), or to the
[`fileServerFolder`](/app/references/configuration#Folders--Files) if you've
configured one. The `file://` protocol is not supported.

Having Cypress serve your files is useful in smaller projects and example apps,
but we don't recommend it for production apps. Run your own server and provide
its URL to Cypress instead.

```javascript
cy.visit('app/index.html')
```

To visit a local file in a single test or group of tests while `baseUrl` is
set, disable `baseUrl` with
[per-test configuration](/app/references/configuration#Test-Configuration).
Given this Cypress configuration:

:::cypress-config-example

```ts
{
  e2e: {
    baseUrl: 'https://example.cypress.io',
  },
}
```

:::

The first test visits the `baseUrl`, while the second test visits the local
file.

```javascript
it('visits base url', () => {
  cy.visit('/')
  cy.contains('h1', 'Kitchen Sink')
})
it('visits local file', { baseUrl: null }, () => {
  cy.visit('index.html')
  cy.contains('local file')
})
```

### How `cy.visit()` follows redirects

`cy.visit()` follows redirects and resolves on the page it ends on:

```javascript
// we aren't logged in, so our web server
// redirected us to /login
cy.visit('/admin')
cy.location('pathname').should('eq', '/login')
```

The Command Log shows each redirect after the URL you visited, with its status
code and where it led:

### When `cy.visit()` adds the `http://` protocol for you

Cypress prepends the `http://` protocol to URLs that start with
`localhost`, `0.0.0.0`, `127.0.0.1`, or `www.`, and to hosts with three or four
dot-separated parts, such as `beta.example.com`. For any other host, such as
`example.com`, provide the protocol. Otherwise Cypress treats the URL as a
relative path.

```javascript
cy.visit('localhost:3000') // Visits http://localhost:3000
cy.visit('0.0.0.0:3000') // Visits http://0.0.0.0:3000
cy.visit('127.0.0.1:3000') // Visits http://127.0.0.1:3000
cy.visit('www.example.com') // Visits http://www.example.com/
```

### How `cy.visit()` handles a URL that changes only the hash

When the URL you visit matches the current page except for the hash, the browser
doesn't make a new request. `cy.visit()` resolves on the `hashchange` event
instead of the `load` event, and `onBeforeLoad` is not called. If the hash is
also the same as the current one, neither `onBeforeLoad` nor `onLoad` is called.

```javascript
cy.visit('http://localhost:3000/#/users')
cy.visit('http://localhost:3000/#/settings') // no page reload
```

### Change the user agent for `cy.visit()`

To change the `User-Agent` header, see
[how to override the browser's default user agent](/app/faq#Can-I-override-or-change-the-default-user-agent-the-browser-uses).

### Intercept requests your app makes before `cy.visit()` resolves

A common need is to visit a page and stub the requests your app makes as soon as
it starts. You might expect this to work:

```javascript
// this code may not work depending on implementation
cy.visit('/#/app')
cy.intercept('GET', '/users/**', { fixture: 'users.json' })
```

If your app makes a request while it starts up, the code above can miss it.
`cy.visit()` resolves once the page fires its `load` event, and Cypress doesn't
process the [`cy.intercept()`](/api/commands/intercept) command until _after_
that.

By then, many apps have already begun routing, initializing, and sending
requests, so the route is registered too late to catch them.

Reverse the order of the commands:

```javascript
// this code is probably what you want
cy.intercept('GET', '/users/**', { fixture: 'users.json' }).as('getUsers')
cy.visit('/#/app')
cy.wait('@getUsers')
```

Cypress applies the routes to the next `cy.visit()` before any of your
application code runs.

### Visiting cross-origin sites with `cy.visit()`

After visiting a cross-origin site, interact with its content inside a
[`cy.origin()`](/api/commands/origin) block.

When visiting a cross-origin site, the `onBeforeLoad` and `onLoad` options are
not supported. Instead, register a `window:before:load` or `window:load` event
listener inside a `cy.origin()` block for that origin, then visit it:

```javascript
cy.visit('/')
cy.origin('https://auth.example.com', () => {
  cy.on('window:before:load', (win) => {
    // what you would have put in onBeforeLoad
    win.localStorage.setItem('returnTo', '/dashboard')
  })
})
cy.visit('https://auth.example.com/login')
```

## Rules

<HeaderRequirements />

- `cy.visit()` requires being chained off of `cy`.
- `cy.visit()` requires the response to be `content-type: text/html` or
  `application/xhtml+xml`. When the response has no `content-type` header,
  Cypress checks whether the body is HTML.
- `cy.visit()` requires the response code to be `2xx` or `3xx` after following
  redirects, unless `failOnStatusCode` is `false`.
- `cy.visit()` requires the `load` event to eventually fire, unless the visit
  changes only the URL's hash.

<HeaderAssertions />

- `cy.visit()` automatically waits for assertions you have chained to pass.

<HeaderTimeouts />

- `cy.visit()` can time out waiting for the page to fire its `load` event.
- `cy.visit()` can time out waiting for assertions you've added to pass.
- `cy.visit()` fails with a network error if the server doesn't respond within
  [`responseTimeout`](/app/references/configuration#Timeouts), even when
  `pageLoadTimeout` is longer.
