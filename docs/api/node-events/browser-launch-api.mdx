# Browser Launch Event

Before Cypress launches a browser, it gives you the opportunity to modify the
browser preferences, install extensions, add and remove command-line arguments,
and modify other options from the
[setupNodeEvents](/app/plugins/plugins-guide#Using-a-plugin) function.

## Syntax

<WarningSetupNodeEvents />

:::cypress-config-plugin-example

```ts
on('before:browser:launch', (browser = {}, launchOptions) => {
  /* ... */
})
```

:::

<Icon name="angle-right" /> **browser _(object)_**

An object describing the browser being launched, with the following properties:

| Property       | Type      | Description                                                                                 |
| -------------- | --------- | ------------------------------------------------------------------------------------------- |
| `name`         | `string`  | Machine-friendly name, like `chrome`, `edge`, `firefox`, or `electron`.                     |
| `family`       | `string`  | Rendering engine being used. `chromium` or `firefox`.                                       |
| `channel`      | `string`  | Release channel of the browser, such as `stable`, `dev`, or `canary`.                       |
| `displayName`  | `string`  | Human-readable display name for the browser.                                                |
| `version`      | `string`  | Full version.                                                                               |
| `path`         | `string`  | Path to the browser on disk. Blank for Electron.                                            |
| `info`         | `string`  | _(Optional)_ Extra information about the browser (used for display in the browser selector) |
| `majorVersion` | `number`  | The major version number of the browser.                                                    |
| `isHeadless`   | `boolean` | Whether the browser is running headlessly.                                                  |
| `isHeaded`     | `boolean` | Whether the browser displays headed.                                                        |

<Icon name="angle-right" /> **launchOptions _(object)_**

Options you can modify to control how Cypress launches the browser, with the
following properties:

| Property      | Type       | Description                                                                                                                                                                                                |
| ------------- | ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `preferences` | `object`   | An object describing browser preferences. Differs between browsers. See [Change browser preferences](#Change-browser-preferences) for details.                                                             |
| `args`        | `string[]` | An array of strings that Cypress passes as command-line args when it launches the browser. Has no effect on Electron. See [Modify browser launch arguments](#Modify-browser-launch-arguments) for details. |
| `extensions`  | `string[]` | An array of paths to folders containing unpacked WebExtensions for Cypress to load before the browser starts. See [Add browser extensions](#Add-browser-extensions) for details.                           |
| `env`         | `object`   | An object of system environment variables to pass to the launched browser. See [Configure browser environment](#Configure-browser-environment) for details.                                                |

## Usage

Using the [setupNodeEvents](/app/plugins/plugins-guide#Using-a-plugin)
function you can tap into the `before:browser:launch` event and modify how
Cypress launches the browser (e.g. modify arguments, user preferences, and
extensions).

This event yields you the `browser` object, which gives you information
about the browser, and the `launchOptions` object, which controls how
Cypress launches the browser.

The returned `launchOptions` object becomes the new launch options for the
browser.

### Modify browser launch arguments

Here are args available for the currently supported browsers:

- [Chromium-based browsers](https://peter.sh/experiments/chromium-command-line-switches/)
- [Firefox](https://developer.mozilla.org/docs/Mozilla/Command_Line_Options)

#### Open devtools by default

:::cypress-config-plugin-example

```ts
on('before:browser:launch', (browser = {}, launchOptions) => {
  // `args` is an array of all the arguments that will
  // be passed to browsers when it launches
  console.log(launchOptions.args) // print all current args

  if (browser.family === 'chromium' && browser.name !== 'electron') {
    // auto open devtools
    launchOptions.args.push('--auto-open-devtools-for-tabs')
  }

  if (browser.family === 'firefox') {
    // auto open devtools
    launchOptions.args.push('-devtools')
  }

  if (browser.name === 'electron') {
    // auto open devtools
    launchOptions.preferences.devTools = true
  }

  // whatever you return here becomes the launchOptions
  return launchOptions
})
```

:::

### Add browser extensions

**Limitations:**

- Headless Chrome does not support loading extensions.
- Chrome-branded browsers (e.g., standard Chrome) version 137 and above no longer support extension loading via this API, due to the removal of the `--load-extension` flag by Chrome. We recommend using [Chrome for Testing](/app/references/launching-browsers#Chrome-Browsers) or Chromium instead. See Cypress Docker image examples for [Chrome for Testing](https://github.com/cypress-io/cypress-docker-images/tree/master/examples/chrome-for-testing) and [Chromium](https://github.com/cypress-io/cypress-docker-images/tree/master/examples/chromium).
- Electron currently supports only Chrome DevTools extensions.

:::cypress-config-plugin-example

```ts
on('before:browser:launch', (browser, launchOptions) => {
  // supply the absolute path to an unpacked extension's folder
  launchOptions.extensions.push('Users/jane/path/to/extension')

  return launchOptions
})
```

:::

### Change browser preferences

Here are preferences available for the currently supported browsers:

- [Chromium-based browsers](https://src.chromium.org/viewvc/chrome/trunk/src/chrome/common/pref_names.cc?view=markup)
- [Electron](https://github.com/electron/electron/blob/master/docs/api/browser-window.md#new-browserwindowoptions)
- Firefox: visit `about:config` URL within your Firefox browser to see all
  available preferences

:::info

If you want to ignore Chrome preferences altogether, you can set `IGNORE_CHROME_PREFERENCES` as a system environment variable when running Cypress.

:::

:::cypress-config-plugin-example

```js
on('before:browser:launch', (browser, launchOptions) => {
  if (browser.family === 'chromium' && browser.name !== 'electron') {
    // in Chromium, preferences can exist in Local State, Preferences, or Secure Preferences
    // via launchOptions.preferences, these can be acccssed as `localState`, `default`, and `secureDefault`

    // for example, to set `somePreference: true` in Preferences:
    launchOptions.preferences.default['preference'] = true

    return launchOptions
  }

  if (browser.family === 'firefox') {
    // launchOptions.preferences is a map of preference names to values
    launchOptions.preferences['some.preference'] = true

    return launchOptions
  }

  if (browser.name === 'electron') {
    // launchOptions.preferences is a `BrowserWindow` `options` object
    launchOptions.preferences.darkTheme = true

    return launchOptions
  }
})
```

:::

### Modify Electron app switches

The Cypress Launchpad is an Electron application, and you can customize its
behavior (and the behavior of the bundled-in Electron browser) using command
line switches. The supported switches depend on the Electron version, see
[Electron documentation](https://www.electronjs.org/docs/api/command-line-switches).

You can pass Electron-specific launch arguments using the
`ELECTRON_EXTRA_LAUNCH_ARGS` system environment variable. For example, to disable HTTP
browser cache and ignore certificate errors, you can set the environment
variables before running Cypress like below:

#### Linux/OSX

```shell
export ELECTRON_EXTRA_LAUNCH_ARGS=--disable-http-cache --lang=es
```

#### Windows

```shell
set ELECTRON_EXTRA_LAUNCH_ARGS=--disable-http-cache --lang=es
```

Cypress already sets some the Electron command line switches internally. See
file
[packages/server/lib/environment.js](https://github.com/cypress-io/cypress/blob/develop/packages/server/lib/environment.js).
There is no way to see all currently set switches after Electron's launch.

### See all Chrome browser switches

If you are running Cypress tests using a Chromium-based browser, you can see ALL
currently set command line switches and the browser version information by
opening a new tab and typing `chrome://version` url.

<DocsImage src="/img/api/chrome-switches.png" alt="See all Chrome switches" />

## Examples

### Set screen size when running headless

When a browser runs headless, there is no physical display. You can override the
default screen size of 1280x720 when running headless as shown below. The screen size
affects the size of screenshots and videos taken during the run.

:::caution

This setting changes the display size of the screen and does not affect the
`viewportWidth` and `viewportHeight` set in the
[Cypress configuration](/app/references/configuration). The `viewportWidth`
and `viewportHeight` only affect the size of the application under test
displayed inside the Cypress Test Runner. Read the blog post
[Generate High-Resolution Videos and Screenshots](https://www.cypress.io/blog/2021/03/01/generate-high-resolution-videos-and-screenshots/?utm_source=docs.cypress.io&utm_medium=browser-launch-api)
for details.

:::

:::cypress-config-plugin-example

```ts
on('before:browser:launch', (browser, launchOptions) => {
  if (browser.name === 'chrome' && browser.isHeadless) {
    // fullPage screenshot size is 1400x1200 on non-retina screens
    // and 2800x2400 on retina screens
    launchOptions.args.push('--window-size=1400,1200')

    // force screen to be non-retina (1400x1200 size)
    launchOptions.args.push('--force-device-scale-factor=1')

    // force screen to be retina (2800x2400 size)
    // launchOptions.args.push('--force-device-scale-factor=2')
  }

  if (browser.name === 'electron' && browser.isHeadless) {
    // fullPage screenshot size is 1400x1200
    launchOptions.preferences.width = 1400
    launchOptions.preferences.height = 1200
  }

  if (browser.name === 'firefox' && browser.isHeadless) {
    // menubars take up height on the screen
    // so fullPage screenshot size is 1400x1126
    launchOptions.args.push('--width=1400')
    launchOptions.args.push('--height=1200')
  }

  return launchOptions
})
```

:::

### Use fake video for webcam testing

By default, Cypress launches Chromium-based browsers with the
`--use-fake-device-for-media-stream` and `--use-fake-ui-for-media-stream`
switches. The switches replace the camera with a fake video and accept the
camera permission prompt, so webcam tests run without a camera.

<DocsImage
  src="/img/api/browser-launch-fake-video.gif"
  alt="Enable fake video for testing"
/>

You can however send your own video file for testing by passing a Chrome command
line switch pointing to a video file.

:::cypress-config-plugin-example

```ts
on('before:browser:launch', (browser = {}, launchOptions) => {
  if (browser.family === 'chromium' && browser.name !== 'electron') {
    // Mac/Linux
    launchOptions.args.push(
      '--use-file-for-fake-video-capture=cypress/fixtures/my-video.y4m'
    )

    // Windows
    // launchOptions.args.push('--use-file-for-fake-video-capture=c:\\path\\to\\video\\my-video.y4m')
  }

  return launchOptions
})
```

:::

#### Change the fake webcam video between tests

Testing how an app handles different camera input, such as a valid and an
expired QR code, needs a different video in each test. Changing the
`--use-file-for-fake-video-capture` argument per test or per spec has no effect.
Chrome reads the switch once, when the browser starts, and Cypress fires
`before:browser:launch` only when it launches a browser. Cypress keeps the same
browser open from spec to spec: in `cypress run`, each spec after the first
opens in a new tab.

What you can change is the file the switch points to. Chrome reads that file
again each time the app starts the camera with `getUserMedia()`. Point the
switch at a placeholder file, and copy the video each test needs over the
placeholder with [`cy.task()`](/api/commands/task):

:::cypress-config-plugin-example

```ts
import fs from 'fs'
import path from 'path'
```

```ts
const fixtures = path.join(config.projectRoot, 'cypress', 'fixtures')
// The file Chrome reads the fake camera video from. The task
// overwrites it, so don't point it at one of your source videos.
const fakeWebcam = path.join(fixtures, 'fake-webcam.y4m')

// Start each run from the same video
fs.copyFileSync(path.join(fixtures, 'webcam-default.y4m'), fakeWebcam)

on('before:browser:launch', (browser, launchOptions) => {
  if (browser.family === 'chromium' && browser.name !== 'electron') {
    launchOptions.args.push(`--use-file-for-fake-video-capture=${fakeWebcam}`)
  }

  return launchOptions
})

on('task', {
  setFakeWebcamVideo(fileName: string) {
    fs.copyFileSync(path.join(fixtures, fileName), fakeWebcam)

    return null
  },
})
```

:::

In the spec, swap the video before the app starts the camera:

```js title="cypress/e2e/scan.cy.js"
it('accepts a valid QR code', () => {
  cy.task('setFakeWebcamVideo', 'valid-qr.y4m')
  // The scan page starts the camera when it loads
  cy.visit('/scan')
  cy.contains('Code accepted')
})

it('rejects an expired QR code', () => {
  cy.task('setFakeWebcamVideo', 'expired-qr.y4m')
  cy.visit('/scan')
  cy.contains('Code expired')
})
```

When the camera is already on before the swap, start it again after the swap.
Reload the page with [`cy.reload()`](/api/commands/reload), or use the app's
own control that stops the stream's tracks and calls `getUserMedia()` again.

Keep these behaviors in mind:

- The task overwrites the placeholder, so give the placeholder its own file
  name. Because the config recreates the placeholder on each run, you can add
  it to `.gitignore`.
- The placeholder keeps the last video a test copied in, for the rest of the
  run and across specs. Set the video in every test that uses the camera, or
  reset it in a `beforeEach()` with
  `cy.task('setFakeWebcamVideo', 'webcam-default.y4m')`.
- A stream that's already open can pick up the overwritten file partway
  through, or keep playing the previous video, depending on the browser
  version, the platform, and the video format. Swapping before the camera starts
  gives each test a predictable video.
- The switch belongs to Chromium, so this approach doesn't apply to Firefox or
  WebKit. Electron ignores `launchOptions.args`, so the approach doesn't apply
  to Electron either.
- The approach relies on how Chrome reads the fake capture file, not on a
  Cypress API, so a browser update can change how it behaves. If the video
  stops changing between tests in your browser,
  [stub `getUserMedia()`](#Stub-getUserMedia-with-a-fixture-video) instead.

#### Stub getUserMedia() with a fixture video

Stubbing `navigator.mediaDevices.getUserMedia()` hands the app a stream the
test controls, without Chrome's fake capture switches, so the stub also works
in Electron. Load the video with [`cy.fixture()`](/api/commands/fixture), play
it in a `<video>` element the test creates, and return the element's
`captureStream()`:

```js title="cypress/e2e/scan.cy.js"
it('accepts a valid QR code', () => {
  cy.fixture('valid-qr.webm', null).then((videoFile) => {
    cy.visit('/scan', {
      onBeforeLoad(win) {
        const player = win.document.createElement('video')
        player.muted = true
        player.loop = true
        player.src = win.URL.createObjectURL(
          new win.Blob([videoFile], { type: 'video/webm' })
        )

        cy.stub(win.navigator.mediaDevices, 'getUserMedia').callsFake(
          async () => {
            await player.play()

            return player.captureStream()
          }
        )
      },
    })
  })

  cy.contains('Code accepted')
})
```

Chromium-based browsers, including Electron, support `captureStream()` on a
`<video>` element. Firefox names the method `mozCaptureStream()`. TypeScript's
DOM types don't declare `captureStream()` on video elements, so a `.ts` spec
needs a type assertion for the call. To stream a still image, such
as a single QR code, draw the image on a `<canvas>` and return the canvas's
`captureStream()`, which Chrome and Firefox both support.

### Support unique file download mime types

Cypress supports a myriad of mime types when testing file downloads, but in case
you have a unique one, you can add support for it.

:::cypress-config-plugin-example

```ts
on('before:browser:launch', (browser, options) => {
  // only Firefox requires all mime types to be listed
  if (browser.family === 'firefox') {
    const existingMimeTypes =
      options.preferences['browser.helperApps.neverAsk.saveToDisk']
    const myMimeType = 'my/mimetype'

    // prevents the browser download prompt
    options.preferences['browser.helperApps.neverAsk.saveToDisk'] =
      `${existingMimeTypes},${myMimeType}`

    return options
  }
})
```

### Download PDFs instead of opening them in Chrome

Chrome, Chromium, and Edge include a built-in PDF viewer, in
[headless mode](/app/references/launching-browsers#Headless-mode) as well as
headed. When your app opens a PDF, for example with `window.open()` or a link
with `target="_blank"`, the browser displays the PDF in the viewer and doesn't
save it to the [`downloadsFolder`](/app/references/configuration#Downloads).
Each `cypress run` also starts from a fresh browser profile, so a PDF setting
you changed in the browser during `cypress open` doesn't carry over.

To save PDFs to the `downloadsFolder` instead, set the
`always_open_pdf_externally` preference:

:::cypress-config-plugin-example

```ts
on('before:browser:launch', (browser, launchOptions) => {
  if (browser.family === 'chromium' && browser.name !== 'electron') {
    launchOptions.preferences.default.plugins = {
      always_open_pdf_externally: true,
    }
  }

  return launchOptions
})
```

:::

The preference also turns off the PDF viewer for PDFs that your app shows in an
`<iframe>` or `<embed>`. The browser shows an "Open" button in their place
instead of the rendered PDF.

The preference applies to Chrome, Chromium, and Edge. Electron doesn't save
these PDFs to the `downloadsFolder` either, so run specs that check a PDF
download in one of those browsers.

### Set a Firefox flag

If we need to set a particular Firefox flag, like `browser.send_pings` we can do
it via preferences

:::cypress-config-plugin-example

```ts
on('before:browser:launch', (browser = {}, launchOptions) => {
  if (browser.family === 'firefox') {
    launchOptions.preferences['browser.send_pings'] = true
  }

  return launchOptions
})
```
