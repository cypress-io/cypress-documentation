# Cypress.stop

Stop the Cypress App on the current machine while tests are running. `Cypress.stop` can be useful for stopping test execution upon failures or other predefined conditions.

:::tip

**Auto Cancellation**: If you're looking to automatically stop _all tests_ across _multiple machines_ when a test fails, consider using the [Auto Cancellation feature](/cloud/features/smart-orchestration/run-cancellation) in Cypress Cloud.

<AutoCancellationBenefits />

:::

## Syntax

```javascript
Cypress.stop()
```

## Examples

### Stop tests when a test fails

To stop tests after a failure in any spec file, add the following snippet to your [support file](/app/core-concepts/writing-and-organizing-tests#Support-file), such as `cypress/support/e2e.js`:

```javascript title="cypress/support/e2e.js"
afterEach(function () {
  const test = this.currentTest
  const isLastAttempt = test.currentRetry() === test.retries()

  if (test.state === 'failed' && isLastAttempt) {
    Cypress.stop()
  }
})
```

The `isLastAttempt` check waits for the final attempt when [test retries](/app/guides/test-retries) are on, so a test that passes on a retry doesn't stop the run.

To skip only the remaining tests in one `describe` block and let the rest of the spec run, see [Skip dependent Cypress tests after a failure](/app/core-concepts/writing-and-organizing-tests#Skip-dependent-Cypress-tests-after-a-failure).

### Abort tests when a condition is met

```javascript
beforeEach(() => {
  if (env !== 'expected-condition') {
    cy.log('Stop tests - environment is not setup correctly')
    Cypress.stop()
    return
  }
})
```

## Notes

Calling `Cypress.stop()` stops the execution of remaining tests, but any code after `Cypress.stop()` in the same container block (such as `beforeEach` or `afterEach`) still runs. To prevent additional logic from executing after `Cypress.stop()`, add a `return` statement immediately after it:

```javascript
if (someCondition) {
  Cypress.stop()
  return // Prevents further code execution in this block
}
```

### `cypress run` vs `cypress open` behavior

Calling `Cypress.stop()` during `cypress run` skips any remaining tests in the current specfile. If recording to Cypress Cloud, all screenshots, videos, and [Test Replay](/cloud/features/test-replay) still successfully upload.

![Terminal output of a Cypress run displays running an `example.cy.ts` file with 1 test passing in green and 1 test passing in red with an error message. The Results table shows 4 tests, 1 passing, 1 failing, and 2 skipped.](/img/api/stop/cypress-stop-during-run-mode.png)

Calling `Cypress.stop()` during `cypress open` stops execution of the Cypress App, which remains open for inspection. The remaining tests do not run.

### Why choose Auto Cancellation?

[Auto Cancellation](/cloud/features/smart-orchestration/run-cancellation) is available with Cypress Cloud's Business+ plan. Auto Cancellation offers several advantages over `Cypress.stop` for stopping tests on **failure**:

1. **Scope of Cancellation:** `Cypress.stop` halts only the current spec file, skipping remaining tests within it. Auto Cancellation, however, stops all tests across all machines and marks the entire run as **cancelled** in Cypress Cloud for better visibility.
2. **Configurable Thresholds:** Auto Cancellation triggers on failure thresholds you define. `Cypress.stop` executes immediately when the specified condition is met.
3. **Simplified Configuration**: You manage Auto Cancellation settings in Cypress Cloud, whereas `Cypress.stop` requires manual code changes.
4. **Optimization with Spec Prioritization**: Combined with [Spec Prioritization](/cloud/features/smart-orchestration/spec-prioritization) (another Business+ feature), Auto Cancellation helps efficiently allocate resources by running previously failing specs first in a new run.
