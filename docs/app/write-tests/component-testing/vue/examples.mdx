# Vue Examples

To mount a component with `cy.mount()`, import the component and pass it to the
method:

```ts
import { Stepper } from './Stepper.vue'

it('mounts', () => {
  cy.mount(Stepper)
})
```

## Passing Data to a Component

You can pass props and events to a component by setting `props` in the options:

```js
cy.mount(Stepper, {
  props: {
    initial: 100,
  },
})
```

## Testing Event Handlers

Pass a Cypress [spy](/app/guides/stubs-spies-and-clocks#Spies) to an event
prop and validate it was called:

```js
it('clicking + fires a change event with the incremented value', () => {
  const onChangeSpy = cy.spy().as('onChangeSpy')
  cy.mount(Stepper, { props: { onChange: onChangeSpy } })
  cy.get('[data-cy=increment]').click()
  cy.get('@onChangeSpy').should('have.been.calledWith', 1)
})
```

## Using JSX

The mount command also supports JSX syntax (provided that you've configured your
bundler to support transpiling JSX or TSX files). Some might find using JSX
syntax beneficial when writing tests.

Sample with JSX:

```jsx
it('clicking + fires a change event with the incremented value', () => {
  const onChangeSpy = cy.spy().as('onChangeSpy')
  cy.mount(<Stepper initial={100} onChange={onChangeSpy} />)
  cy.get('[data-cy=increment]').click()
  cy.get('@onChangeSpy').should('have.been.calledWith', 101)
})
```

## Testing Error States

<ComponentTestingErrorStates />

```js
import UserProfile from './UserProfile.vue'

it('surfaces a render error', () => {
  cy.on('uncaught:exception', (err) => {
    // Assert on the error thrown during render...
    expect(err.message).to.include('user is required')

    // ...and return false so Cypress does not fail the test.
    return false
  })

  cy.mount(UserProfile)
})
```

### Testing with `onErrorCaptured`

The recommended way to render fallback UI in Vue is a wrapper component that uses
the [`onErrorCaptured`](https://vuejs.org/api/composition-api-lifecycle#onerrorcaptured)
lifecycle hook to catch errors from its descendants. You can mount a component
inside such a wrapper and assert that the wrapper displays the fallback UI:

```js
// ErrorBoundary.cy.js
import { h } from 'vue'
import ErrorBoundary from './ErrorBoundary.vue'
import ChildWithError from './ChildWithError.vue'

it('displays the fallback UI on error', () => {
  // onErrorCaptured renders fallback UI, but it does NOT stop the error from
  // propagating to Cypress as an uncaught exception. Cypress fails on uncaught
  // exceptions by default, so we must still suppress that behavior.
  cy.on('uncaught:exception', (err) => {
    // Only suppress the specific error we expect.
    expect(err.message).to.include('I crashed!')

    return false
  })

  cy.mount(() => h(ErrorBoundary, () => h(ChildWithError)))

  cy.get('[data-cy=fallback]').should('contain', 'Something went wrong.')
})
```

Where `ErrorBoundary` captures the error with `onErrorCaptured` and renders
fallback UI:

```html
<!-- ErrorBoundary.vue -->
<template>
  <div v-if="error" data-cy="fallback">Something went wrong.</div>
  <slot v-else />
</template>

<script setup>
  import { ref, onErrorCaptured } from 'vue'

  const error = ref(null)

  onErrorCaptured((err) => {
    error.value = err

    // Returning false stops the error from propagating further up the Vue tree,
    // but it still reaches Cypress as an uncaught exception.
    return false
  })
</script>
```

## Using Vue Test Utils

Cypress supports the Vue Test Utils API, so your existing component tests can
keep using it. `cy.mount()` yields the Vue Test Utils `wrapper` and the
component instance:

```js
cy.mount(Stepper).then(({ wrapper, component }) => {
  // `wrapper` is the Vue Test Utils wrapper
  // `component` is the component instance itself
})
```

{/* TODO: Custom mount command docs */}

If your tests use the `wrapper` often, we recommend a
[custom mount command](/api/commands/mount) that saves it as a Cypress alias:

<Tabs>
<TabItem value="cypress/support/component.js">

```js
import { mount } from 'cypress/vue'

Cypress.Commands.add('mount', (...args) => {
  return mount(...args).then(({ wrapper }) => {
    return cy.wrap(wrapper).as('vue')
  })
})
```

</TabItem>
<TabItem value="cypress/support/component.ts">

```ts
import { mount, type CyMountOptions } from 'cypress/vue'

declare global {
  namespace Cypress {
    interface Chainable {
      /**
       * Mounts a Vue component and aliases the Vue Test Utils wrapper as `@vue`
       * @param component Vue Component or JSX Element to mount
       * @param options Options passed to Vue Test Utils
       */
      mount(component: any, options?: CyMountOptions<any>): Chainable<any>
    }
  }
}

Cypress.Commands.add('mount', (component, options) => {
  return mount(component, options).then(({ wrapper }) => {
    return cy.wrap(wrapper).as('vue')
  })
})
```

</TabItem>
</Tabs>

```js
// After you mount a component, the "@vue" alias works anywhere in the test
cy.mount(Stepper)
cy.get('@vue') // The subject is the Vue Test Utils wrapper
```

The `@vue` alias yields the `wrapper` that `cy.mount()` created. Call
`wrapper.emitted()` on it to read the native DOM events that fired and the
custom events your component emitted.

`wrapper.emitted()` returns plain data rather than spies, so unpack its results
to write assertions. Failure messages are less helpful as well, because the
Sinon-Chai assertions that Cypress ships, such as `to.have.been.called` and
`to.have.been.calledWith`, don't apply to plain data.

The examples below pass a function to `.should()`, so the assertion gets
Cypress's [retry-ability](/app/core-concepts/retry-ability). With `.then()` in
place of `.should()`, a test runs into the same timing problems as a Vue Test
Utils test, where you `await` often to make sure the DOM updated or reactive
events fired.

<Tabs>
<TabItem value="With emitted">

```js
cy.mount(Stepper, { props: { initial: 100 } })
cy.get(incrementSelector).click()
cy.get('@vue').should((wrapper) => {
  expect(wrapper.emitted('change')).to.have.length
  expect(wrapper.emitted('change')[0][0]).to.equal('101')
})
```

</TabItem>
<TabItem value="With spies">

```js
const onChangeSpy = cy.spy().as('onChangeSpy')

cy.mount(Stepper, { props: { initial: 100, onChange: onChangeSpy } })

cy.get(incrementSelector).click()
cy.get('@onChangeSpy').should('have.been.calledWith', '101')
```

</TabItem>
</Tabs>

We recommend spies, but `wrapper.emitted()` records every event a component
emits without a spy for each one, which helps with components that emit many
custom events.

## Mount Storybook stories in Vue component tests

Component tests can reuse the [Storybook](https://storybook.js.org/) stories you
already write. A story sets up the component with the args and decorators that
make it render, so the test starts from a working state and goes straight to the
assertions.

Storybook's portable stories API does the work, so Cypress needs no plugin.
`composeStories()` from `@storybook/vue3` turns each story in a CSF file into a
component with the story's args and decorators applied, and `cy.mount()`
accepts that component like any other.

Given this component and its stories:

```vue title="src/components/Button.vue"
<script setup>
defineProps({ label: String, primary: Boolean, theme: String })
defineEmits(['click'])
</script>

<template>
  <button :class="{ primary }" :data-theme="theme" @click="$emit('click')">
    {{ label }}
  </button>
</template>
```

```js title="src/components/Button.stories.js"
import Button from './Button.vue'

export default {
  component: Button,
  args: { label: 'Button' },
  decorators: [() => ({ template: '<div class="padded"><story /></div>' })],
}

export const Primary = {
  args: { primary: true, label: 'Primary' },
}

export const Secondary = {
  args: { label: 'Secondary' },
}
```

Compose the stories once at the top of the spec, then mount each one. Props
passed to `cy.mount()` override the story's args:

```js title="src/components/Button.cy.js"
import { composeStories } from '@storybook/vue3'
import * as stories from './Button.stories'

const { Primary, Secondary } = composeStories(stories)

it('renders the Primary story', () => {
  cy.mount(Primary)
  cy.get('.padded button')
    .should('have.text', 'Primary')
    .and('have.class', 'primary')
})

it('overrides story args with props', () => {
  cy.mount(Secondary, { props: { label: 'Save' } })
  cy.get('button').should('have.text', 'Save')
})
```

### Apply Storybook preview settings in component tests

Global decorators and args in `.storybook/preview` apply only when you pass them
to `setProjectAnnotations()`. Call it once in the component support file, next
to the code that registers `cy.mount()`, and every composed story picks them up:

```js title="cypress/support/component.js"
import { setProjectAnnotations } from '@storybook/vue3'
import { mount } from 'cypress/vue'
import * as previewAnnotations from '../../.storybook/preview'

setProjectAnnotations(previewAnnotations)

Cypress.Commands.add('mount', mount)
```

### Compile Storybook template decorators in Cypress

A decorator written as a `template` string, like the one in
`Button.stories.js`, needs the build of Vue that includes the template compiler.
Without it, the story renders nothing and Vue logs
`Component provided template option but runtime compilation is not supported in this build of Vue`.
Alias `vue` to `vue/dist/vue.esm-bundler.js` in the Vite config Cypress uses, so
the alias applies to your tests and not to your production build.

When `viteConfig` is set, Cypress uses it in place of your project's
`vite.config`, which drops that file's plugins and aliases. Set `configFile`
inside `viteConfig` to your config's filename, such as `vite.config.ts`, so Vite
loads it and merges the alias on top:

:::cypress-config-example

```ts
{
  component: {
    devServer: {
      framework: 'vue',
      bundler: 'vite',
      viteConfig: {
        configFile: 'vite.config.js',
        resolve: {
          alias: {
            vue: 'vue/dist/vue.esm-bundler.js',
          },
        },
      },
    },
  },
}
```

:::

Decorators written as render functions, such as
`(story) => () => h('div', { class: 'padded' }, [h(story())])`, don't need the
alias.

### Spy on events from a decorated Storybook story

Storybook passes the props you give `cy.mount()` to the story's component as
args. A composed story is also a functional component, so Vue passes the event
listeners among those props to the outermost element the story renders too. With
a decorator, that element is the decorator's wrapper, so a
single click on the component reaches the spy twice: once from the component's
emitted event and once from the native click on the wrapper. Set
`inheritAttrs: false` on the composed story so the listener reaches only the
component.

The setting changes the composed story itself, so every test in the spec that
mounts the story gets it. Set it once, right after `composeStories()`, so the
scope is clear at a glance:

```js title="src/components/ButtonEvents.cy.js"
import { composeStories } from '@storybook/vue3'
import * as stories from './Button.stories'

const { Primary } = composeStories(stories)
Object.assign(Primary, { inheritAttrs: false })

it('emits click', () => {
  const onClick = cy.spy().as('onClick')
  cy.mount(Primary, { props: { onClick } })
  cy.get('button').click()
  cy.get('@onClick').should('have.been.calledOnce')
})
```

## Custom Mount Commands

### Register `cy.mount()` in the component support file

You can call the [`mount()`](/app/component-testing/vue/api#mount) function in
your tests directly, but we recommend [`cy.mount()`](/api/commands/mount), a
[custom command](/api/cypress-api/custom-commands) that you define in
`cypress/support/component.js`:

<Tabs>
<TabItem value="cypress/support/component.js">

```js
import { mount } from 'cypress/vue'

Cypress.Commands.add('mount', mount)
```

</TabItem>
<TabItem value="cypress/support/component.ts">

```ts
import { mount } from 'cypress/vue'

declare global {
  namespace Cypress {
    interface Chainable {
      mount: typeof mount
    }
  }
}

Cypress.Commands.add('mount', mount)
```

</TabItem>
</Tabs>

The support file registers `cy.mount()` for every test, so no spec file has to
import `mount()`.

As registered above, `cy.mount()` passes its arguments straight to `mount()`.
Customize the command to set up what your app sets up globally, such as Vue
plugins, global components, or a component that wraps every other component.
The sections below cover common setups, starting with how to type a custom
command in TypeScript. The same patterns carry over to most other plugins and
providers.

### Type custom `cy.mount()` options in Vue

A custom command that only adds global setup keeps `mount: typeof mount`, as the
[Vue plugins example](#Install-Vue-plugins-such-as-Pinia-in-cymount) and the
[global components example](#Register-global-Vue-components-in-cymount) do. A command that accepts options of its own, mounts a
wrapper around your component, or yields something other than what `mount()`
yields needs its own signature. Type that command's options with
`CyMountOptions<any>`, which `cypress/vue` exports, and add your own options
with `&`, such as `CyMountOptions<any> & { router?: Router }`.

Avoid `Parameters<typeof mount>[1]` for Vue. `mount()` from `cypress/vue` has a
separate signature for each way to declare a component, and `Parameters<>`
reads only the last one, the signature for components that declare `props` as
an object. The `props` type from that signature includes array members such as
`toString` and `forEach`, so a spec such as
`cy.mount(HelloWorld, { props: { msg: 'Hello Cypress' } })` fails type-checking
with `TS2322`.

### Install Vue plugins such as Pinia in `cy.mount()`

Most Vue apps install plugins for state management, routing, or translations.
Install the same plugins in `cy.mount()`, so components that depend on them
render in tests:

<Tabs>
<TabItem value="cypress/support/component.js">

```js
import { createPinia } from 'pinia' // or Vuex
import { createI18n } from 'vue-i18n'
import { mount } from 'cypress/vue'

// We recommend that you pull this out
// into a constants file that you share with
// your main.js file.
const i18nOptions = {
  locale: 'en',
  messages: {
    en: {
      hello: 'hello!',
    },
    ja: {
      hello: 'こんにちは！',
    },
  },
}

Cypress.Commands.add('mount', (component, options = {}) => {
  options.global = options.global || {}
  options.global.plugins = options.global.plugins || []
  options.global.plugins.push(createPinia())
  options.global.plugins.push(createI18n(i18nOptions))

  return mount(component, options)
})
```

### Wrap components in Vuetify's `VApp` with `cy.mount()`

Some UI libraries expect components to render inside a specific parent.
Vuetify's layout components, for example, expect to render inside a `VApp`
component, which a component mounted on its own doesn't have. Wrap every mounted
component in `VApp` from a custom `cy.mount()`, and install Vuetify the same way
your app does, following the
[Vuetify installation guide](https://vuetifyjs.com/en/getting-started/installation/).

The command takes `props` out of the options and passes them to your component,
so they don't land on the wrapper that renders `VApp`. The JSX version reads
closer to the markup it renders.

<Tabs>
<TabItem value="cypress/support/component.js">

```js
import 'vuetify/styles'
import { createVuetify } from 'vuetify'
import * as components from 'vuetify/components'
import * as directives from 'vuetify/directives'
import { VApp } from 'vuetify/components'
import { mount } from 'cypress/vue'
import { h } from 'vue'

// We recommend that you pull this out
// into a constants file that you share with
// your main.js file.
const vuetifyOptions = { components, directives }

Cypress.Commands.add('mount', (component, options = {}) => {
  // Props go to your component, not to the VApp wrapper
  const { props, ...mountOptions } = options

  mountOptions.global = mountOptions.global || {}
  mountOptions.global.plugins = mountOptions.global.plugins || []
  mountOptions.global.plugins.push(createVuetify(vuetifyOptions))

  return mount(() => {
    return h(VApp, () => h(component, props))
  }, mountOptions)
})
```

</TabItem>

### Provide a Vue Router instance to `cy.mount()`

To test components that use Vue Router, give `cy.mount()` a `router` option. The
command installs the router you pass in, or creates a new one for the test when
you don't pass one.

<Tabs>
<TabItem value="cypress/support/component.js">

```js
import { mount } from 'cypress/vue'
import { createMemoryHistory, createRouter } from 'vue-router'
import { routes } from '../../src/router'

Cypress.Commands.add('mount', (component, options = {}) => {
  // Use the router passed in from options, or create a new one
  const {
    router = createRouter({
      routes: routes,
      history: createMemoryHistory(),
    }),
    ...mountOptions
  } = options

  // Set up the options object
  mountOptions.global = mountOptions.global || {}
  mountOptions.global.plugins = mountOptions.global.plugins || []

  // Add router plugin
  mountOptions.global.plugins.push(router)

  return mount(component, mountOptions)
})
```

</TabItem>
<TabItem value="cypress/support/component.ts">

```ts
import { mount, type CyMountOptions } from 'cypress/vue'
import { createMemoryHistory, createRouter, type Router } from 'vue-router'
import { routes } from '../../src/router'

type MountOptions = CyMountOptions<any> & { router?: Router }

declare global {
  namespace Cypress {
    interface Chainable {
      /**
       * Helper mount function for Vue Components
       * @param component Vue Component or JSX Element to mount
       * @param options Options passed to Vue Test Utils, plus an optional router
       */
      mount(component: any, options?: MountOptions): Chainable<any>
    }
  }
}

Cypress.Commands.add('mount', (component, options = {}) => {
  // Use the router passed in from options, or create a new one
  const {
    router = createRouter({
      routes: routes,
      history: createMemoryHistory(),
    }),
    ...mountOptions
  } = options

  // Set up the options object
  mountOptions.global = mountOptions.global || {}
  mountOptions.global.plugins = mountOptions.global.plugins || []

  // Add router plugin
  mountOptions.global.plugins.push(router)

  return mount(component, mountOptions)
})
```

</TabItem>
<TabItem value="Spec Usage">

```jsx
import Navigation from './Navigation.vue'
import { routes } from '../router'
import { createMemoryHistory, createRouter } from 'vue-router'

it('home link should be active when url is "/"', () => {
  // No need to pass in custom router as default url is '/'
  cy.mount(<Navigation />)

  cy.get('a').contains('Home').should('have.class', 'router-link-active')
})

it('login link should be active when url is "/login"', () => {
  // Create a new router instance for each test
  const router = createRouter({
    routes: routes,
    history: createMemoryHistory(),
  })

  // Change location to `/login`,
  // and await on the promise with cy.wrap
  cy.wrap(router.push('/login'))

  // Pass the already initialized router for use
  cy.mount(<Navigation />, { router })

  cy.get('a').contains('Login').should('have.class', 'router-link-active')
})
```

:::info

`router.push()` is asynchronous in Vue Router 4. Pass its promise to
[`cy.wrap()`](/api/commands/wrap), so Cypress waits for it to resolve before it
runs the next command.

:::

### Provide a Vuex store to `cy.mount()`

To test a component that uses [Vuex](https://vuex.vuejs.org/), give `cy.mount()`
a `store` option. The command installs the store you pass in, or a new one from
your store factory when you don't pass one.

<Tabs>
<TabItem value="cypress/support/component.js">

```js
import { mount } from 'cypress/vue'
import { getStore } from '../../src/plugins/store'

Cypress.Commands.add('mount', (component, options = {}) => {
  // Use store passed in from options, or initialize a new one
  const { store = getStore(), ...mountOptions } = options

  // Set up the options object
  mountOptions.global = mountOptions.global || {}
  mountOptions.global.stubs = {
    ...mountOptions.global.stubs,
    transition: false,
  }
  mountOptions.global.components = mountOptions.global.components || {}
  mountOptions.global.plugins = mountOptions.global.plugins || []

  // Add Vuex plugin
  mountOptions.global.plugins.push(store)

  return mount(component, mountOptions)
})
```

</TabItem>
<TabItem value="cypress/support/component.ts">

```ts
import { mount, type CyMountOptions } from 'cypress/vue'
import { getStore } from '../../src/plugins/store'
import type { Store } from 'vuex'

type MountOptions = CyMountOptions<any> & { store?: Store<any> }

declare global {
  namespace Cypress {
    interface Chainable {
      /**
       * Helper mount function for Vue Components
       * @param component Vue Component or JSX Element to mount
       * @param options Options passed to Vue Test Utils, plus an optional store
       */
      mount(component: any, options?: MountOptions): Chainable<any>
    }
  }
}

Cypress.Commands.add('mount', (component, options = {}) => {
  // Use store passed in from options, or initialize a new one
  const { store = getStore(), ...mountOptions } = options

  // Set up the options object
  mountOptions.global = mountOptions.global || {}
  mountOptions.global.stubs = {
    ...mountOptions.global.stubs,
    transition: false,
  }
  mountOptions.global.components = mountOptions.global.components || {}
  mountOptions.global.plugins = mountOptions.global.plugins || []

  // Add Vuex plugin
  mountOptions.global.plugins.push(store)

  return mount(component, mountOptions)
})
```

</TabItem>
<TabItem value="Spec Usage">

```js
import { getStore } from '@/plugins/store'
import UserProfile from './UserProfile.vue'

it('User profile should display user name', () => {
  const user = { name: 'test person' }

  // getStore is a factory method that creates a new store
  const store = getStore()

  // mutate the store with user
  store.commit('setUser', user)

  cy.mount(UserProfile, {
    store,
  })

  cy.get('div.name').should('have.text', user.name)
})
```

</TabItem>
</Tabs>

:::info

`getStore()` is a factory function that creates a new Vuex store. Create a new
store for each test, so changes to the store in one test don't affect the
others.

:::

### Register global Vue components in `cy.mount()`

If your app's entry file registers components globally, register them in
`cy.mount()` too, so components that use them render in tests:

<Tabs>
<TabItem value="cypress/support/component.js">

```js
import { mount } from 'cypress/vue'
import Button from '../../src/components/Button.vue'

Cypress.Commands.add('mount', (component, options = {}) => {
  // Set up the options object
  options.global = options.global || {}
  options.global.components = options.global.components || {}

  // Register global components
  options.global.components['Button'] = Button

  return mount(component, options)
})
```

</TabItem>
<TabItem value="cypress/support/component.ts">

import { mount } from 'cypress/vue'

  return mount(component, options)
})
