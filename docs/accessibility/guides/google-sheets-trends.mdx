# Chart accessibility scores over time in Google Sheets

A Google Sheet that fills itself in after every Cypress Accessibility report
gives you a running history of your project's accessibility that anyone on the
team can open, filter, and chart. This guide builds one with a
[Cypress Cloud webhook](/cloud/integrations/webhooks) and a short
[Google Apps Script](https://developers.google.com/apps-script) that receives
each `run.accessibility.completed` delivery and writes it to the sheet. No
server to host, and no third-party automation platform in between.

The finished spreadsheet has four tabs:

- **Runs**: one row per report on every branch, with the report status, the
  [Accessibility score](/accessibility/core-concepts/accessibility-score),
  violation counts by impact, failed elements, the number of failing
  [Run Checks](/cloud/features/checks), and a link to the report
- **Checks**: one row per Run Checks assertion about accessibility, with its
  threshold, the measured value, and a Cloud CLI command to investigate a
  failure
- **Main branch**: a line chart of the Accessibility score and a stacked column
  chart of violations by impact, for runs on `main`
- **Main branch data**: the `QUERY` formulas that feed those charts

The matching guides for [test results](/cloud/guides/google-sheets-trends) and
[UI Coverage](/ui-coverage/guides/google-sheets-trends) build the same sheet
from their own webhooks, so you can run any combination of them.

## Prerequisites for the Google Sheets webhook receiver

- A Cypress Cloud project that records runs with
  [Cypress Accessibility](/accessibility/get-started/introduction). For the
  **Checks** tab, the project needs [Run Checks](/cloud/features/checks) with
  `accessibility.score.min` or `accessibility.failedElements.max` assertions.
  Without them, the tab stays empty.
- Permission to manage webhooks on the project: **Owner**, **Org Admin**, or
  **Team Admin**. See [Getting started](/cloud/integrations/webhooks#Getting-started).
- A Google account that can deploy an Apps Script web app with access set to
  **Anyone**. Some Google Workspace admins turn that setting off for their
  domain.

## How the Apps Script receiver handles Cypress Cloud deliveries

The webhook subscribes to `run.accessibility.completed`, which Cypress Cloud
sends when a run's Accessibility report finishes processing, and again if the
report is regenerated. See the
[`run.accessibility.completed` payload](/cloud/integrations/webhooks#Payload)
for every field.

## Step 1: Create the spreadsheet and add the script

1. Create a new Google Sheet. Name it after your project, for example
   "Cypress Accessibility trends".
2. Click **Extensions** > **Apps Script**. The editor opens with an empty
   `Code.gs` file bound to the spreadsheet.
3. Replace the contents of `Code.gs` with the following script and click
   **Save**.

```js title="Code.gs"
const RUNS_SHEET = 'Runs'
const CHECKS_SHEET = 'Checks'
const CHARTS_SHEET = 'Main branch'
const DATA_SHEET = 'Main branch data'
const TREND_BRANCH = 'main'

// run.accessibility.completed carries final results for the accessibility.*
// assertions in your Run Checks.
const ASSERTION_PREFIX = 'accessibility.'

const RUN_HEADERS = [
  'Completed at',
  'Project ID',
  'Run number',
  'Branch',
  'Run status',
  'Report status',
  'Accessibility score',
  'Critical',
  'Serious',
  'Moderate',
  'Minor',
  'Failed elements',
  'Partial report',
  'Failing checks',
  'Report URL',
]

const CHECK_HEADERS = [
  'Completed at',
  'Project ID',
  'Run number',
  'Branch',
  'Check',
  'Check status',
  'Assertion',
  'Assertion status',
  'Threshold',
  'Measured',
  'Matched',
  'Failed matches',
  'Scope',
  'Investigate',
]

// Cypress Cloud POSTs each run.accessibility.completed delivery here.
function doPost(e) {
  const token =
    PropertiesService.getScriptProperties().getProperty('WEBHOOK_TOKEN')
  if (!token || e.parameter.token !== token) {
    console.warn('Ignored a request with a missing or wrong token')
    return reply('ignored')
  }

  const run = JSON.parse(e.postData.contents)
  if (
    typeof run.runNumber !== 'number' ||
    !run.projectId ||
    !run.accessibility
  ) {
    console.warn(
      'Ignored a body that is not a run.accessibility.completed delivery'
    )
    return reply('ignored')
  }

  // Two deliveries can arrive at once. The lock keeps them from writing
  // the same rows twice.
  const lock = LockService.getScriptLock()
  lock.waitLock(5000)
  try {
    upsertRun(run)
    replaceChecks(run)
  } finally {
    lock.releaseLock()
  }

  return reply('ok')
}

function runRow(run) {
  const report = run.accessibility
  const impact = report.violationCountsByImpact || {}
  const elements = report.elementCountsByStatus || {}

  return [
    completedAt(run),
    run.projectId,
    run.runNumber,
    run.commitBranch || '',
    run.status,
    report.status,
    cell(report.score),
    cell(impact.critical),
    cell(impact.serious),
    cell(impact.moderate),
    cell(impact.minor),
    cell(elements.fail),
    report.isPartialReport,
    failingChecks(run),
    report.reportUrl,
  ]
}

// A command for the Cypress Cloud CLI that prints the report's score and
// failing rules. Copy it from the sheet and run it in a terminal.
function investigate(run) {
  return `cy-cloud accessibility report get --projectId ${run.projectId} --runNumber ${run.runNumber}`
}

// ---- Shared by every Cypress Cloud webhook sheet ----

// One row per run. A retry, a redelivery, or a reprocessed report for a run
// that already has a row overwrites that row instead of adding another.
function upsertRun(run) {
  const sheet = sheetNamed(RUNS_SHEET)
  const row = runRow(run)
  const index = runRowIndexes(sheet, run)[0]

  if (index === undefined) {
    sheet.appendRow(row)
  } else {
    sheet.getRange(index, 1, 1, row.length).setValues([row])
  }
}

// One row per assertion. A later delivery for the same run replaces them.
function replaceChecks(run) {
  const sheet = sheetNamed(CHECKS_SHEET)
  runRowIndexes(sheet, run)
    .reverse()
    .forEach((index) => sheet.deleteRow(index))

  const rows = checkRows(run)
  if (rows.length) {
    sheet
      .getRange(sheet.getLastRow() + 1, 1, rows.length, rows[0].length)
      .setValues(rows)
  }
}

function checkRows(run) {
  const checks = (run.checks && run.checks.checks) || []
  const rows = []

  checks.forEach((check) => {
    check.assertionResults
      .filter((assertion) => assertion.type.startsWith(ASSERTION_PREFIX))
      .forEach((assertion) => {
        const matched = assertion.matched || {}
        rows.push([
          completedAt(run),
          run.projectId,
          run.runNumber,
          run.commitBranch || '',
          check.name,
          check.status,
          assertion.type,
          assertion.status,
          assertion.threshold,
          cell(matched.measuredValue),
          cell(matched.count),
          cell(matched.failedCount),
          assertion.filter ? assertion.filter.label : 'All',
          assertion.status === 'failed' ? investigate(run, assertion) : '',
        ])
      })
  })

  return rows
}

// Checks that have already failed. `failing` means an assertion failed while
// others are still pending, and a failed assertion never passes later.
function failingChecks(run) {
  if (!run.checks || run.checks.status === 'not-configured') {
    return ''
  }
  return run.checks.checks.filter(
    (check) => check.status === 'failed' || check.status === 'failing'
  ).length
}

// Row numbers whose Project ID (column B) and Run number (column C) match.
function runRowIndexes(sheet, run) {
  const lastRow = sheet.getLastRow()
  if (lastRow < 2) {
    return []
  }

  const indexes = []
  sheet
    .getRange(2, 2, lastRow - 1, 2)
    .getValues()
    .forEach(([projectId, runNumber], i) => {
      if (projectId === run.projectId && Number(runNumber) === run.runNumber) {
        indexes.push(i + 2)
      }
    })
  return indexes
}

function completedAt(run) {
  return new Date(run.completedAt || run.createdAt)
}

// A null metric becomes an empty cell, which QUERY treats as no value
// rather than as zero.
function cell(value) {
  return value === null || value === undefined ? '' : value
}

function sheetNamed(name) {
  const spreadsheet = SpreadsheetApp.getActiveSpreadsheet()
  return spreadsheet.getSheetByName(name) || spreadsheet.insertSheet(name)
}

// HtmlService answers the request with a 200. ContentService answers with
// a 302 redirect, which Cypress Cloud records as a failed delivery.
function reply(message) {
  return HtmlService.createHtmlOutput(message)
}

// ---- Setup: run once from the editor ----

// Creates the sheets, the trend queries, and the charts. Running it again
// rebuilds the charts and their data, and leaves recorded rows alone.
function setup() {
  writeHeaders(RUNS_SHEET, RUN_HEADERS)
  writeHeaders(CHECKS_SHEET, CHECK_HEADERS)

  const data = sheetNamed(DATA_SHEET)
  data.clear()
  const where = `D = '${TREND_BRANCH}' and G is not null order by A`
  data
    .getRange('A1')
    .setFormula(`=QUERY(${RUNS_SHEET}!A:O, "select A, G where ${where}", 1)`)
  data
    .getRange('D1')
    .setFormula(
      `=QUERY(${RUNS_SHEET}!A:O, "select A, H, I, J, K where ${where}", 1)`
    )

  const charts = sheetNamed(CHARTS_SHEET)
  charts.getCharts().forEach((chart) => charts.removeChart(chart))
  addChart(charts, data.getRange('A:B'), 1, {
    type: Charts.ChartType.LINE,
    title: `Accessibility score on ${TREND_BRANCH}`,
    options: { 'vAxis.minValue': 0, 'vAxis.maxValue': 100 },
  })
  addChart(charts, data.getRange('D:H'), 20, {
    type: Charts.ChartType.COLUMN,
    title: `Accessibility violations by impact on ${TREND_BRANCH}`,
    options: { isStacked: true },
  })
  SpreadsheetApp.getActiveSpreadsheet().setActiveSheet(charts)
}

function writeHeaders(name, headers) {
  const sheet = sheetNamed(name)
  sheet.getRange(1, 1, 1, headers.length).setValues([headers])
  sheet.getRange(1, 1, 1, headers.length).setFontWeight('bold')
  sheet.setFrozenRows(1)
}

// Anchors the chart in column A, so it starts at the left edge of the sheet.
function addChart(sheet, range, row, { type, title, options = {} }) {
  let builder = sheet
    .newChart()
    .setChartType(type)
    .addRange(range)
    .setNumHeaders(1)
    .setPosition(row, 1, 0, 0)
    .setOption('title', title)
    .setOption('width', 900)
    .setOption('height', 360)
  Object.entries(options).forEach(([key, value]) => {
    builder = builder.setOption(key, value)
  })
  sheet.insertChart(builder.build())
}
```

If your default branch has another name, such as `master` or `develop`, change
`TREND_BRANCH` before the next step.

## Step 2: Run the setup function to build the sheets and charts

1. In the editor toolbar, choose `setup` from the function menu and click
   **Run**.
2. Google asks you to authorize the script to edit your spreadsheets. Review
   the request and allow it.

The spreadsheet now has **Runs** and **Checks** tabs with frozen headers, a
**Main branch data** tab with two `QUERY` formulas, and a **Main branch** tab
with two empty charts anchored at its left edge. The queries select the `main`
runs that have an Accessibility score, in date order:

- Columns A and B: the completion time and the Accessibility score, which feed
  the line chart
- Columns D to H: the completion time and the critical, serious, moderate, and
  minor violation counts, which feed the stacked column chart

The charts fill in as rows arrive. Running `setup` again rebuilds both charts
and their data, so make lasting style changes in the script's `addChart` calls,
or stop running `setup` once the charts look the way you want.

## Step 6: Send a test delivery to the spreadsheet

1. On the webhook row, click **Send test** and choose
   `run.accessibility.completed`.
2. Open **Recent deliveries** from the webhook's **Options (⋯)** menu. The test
   delivery shows **Delivered**.
3. In the spreadsheet, the **Runs** tab has a row for run `42` of project
   `abc123`, and the **Main branch** charts show one point. When the sample
   includes Run Checks results, the **Checks** tab has a row for each
   `accessibility.*` assertion in them.

The test uses sample data recorded against `main`. Delete its rows from **Runs**
and **Checks** once you've confirmed they arrived, so they don't sit in your
trend.

If no row appears, open **Executions** in the Apps Script editor's sidebar to
see the request and any error the script logged. A
`Ignored a request with a missing or wrong token` warning means the `token` in
the Payload URL doesn't match the `WEBHOOK_TOKEN` property.

From here, every Accessibility report adds a row, and every `main` report with
a score adds a point to the charts.

## Investigate a failed Run Check from the sheet

Apps Script runs in Google's cloud, with no terminal and no Node.js, so it can't
run the [Cypress Cloud CLI](/cloud/integrations/cloud-cli). Instead, for each
failed assertion, the script writes the CLI command that prints the report's
score and every failing rule in the **Investigate** column:

```shell
cy-cloud accessibility report get --projectId <id> --runNumber <n>
```

Copy the command from the cell and run it in a terminal where the CLI is
[authenticated](/cloud/integrations/cloud-cli#Authenticate). To list the failing
elements for one of those rules, follow up with
[`cy-cloud accessibility element list`](/cloud/integrations/cloud-cli#cy-cloud-accessibility-element-list)
and its `--ruleId` option. To hand the report to an AI assistant instead, give
it the report URL from the **Runs** tab and use
[Cloud MCP](/cloud/integrations/cloud-mcp).

## Keep these behaviors in mind

<GoogleSheetsWebhookBehaviors />

- **Reports that couldn't be processed leave empty cells.** When the report's
  `status` is `processing_failed`, its metrics are `null`, the row's metric
  cells stay empty, and the trend queries skip the row instead of charting it
  as zero.
- **Partial reports can dip.** When **Partial report** is `TRUE`, the report is
  missing data for some specs, and the score covers only what was captured.
  Add `and M = false` to the trend queries to leave those runs out.
- **A regenerated report replaces the original.** Its delivery carries the same
  run number, so its row and its **Checks** rows overwrite the earlier ones.

## Extend the Google Sheets dashboard

The **Runs** tab is plain data, so most extensions need only a formula:

- **Add a seven-run moving average.** Next to the first score on **Main branch
  data**, average the current and previous six scores, fill the formula down,
  and add the column to the line chart.
- **Highlight a drop.** Add a conditional-format rule to the Accessibility score
  column that colors a cell when it is lower than the cell above it.
- **Compare branches.** Build a pivot table on **Runs** with **Branch** as rows
  and the average **Accessibility score** as values.
- **Chart your threshold.** Query the **Threshold** of your
  `accessibility.score.min` assertion from **Checks** next to the score, and
  add it to the line chart as a second series.
