# Chart UI Coverage over time in Google Sheets

A Google Sheet that fills itself in after every UI Coverage report gives you a
running history of how much of your app your tests exercise, which anyone on the
team can open, filter, and chart. This guide builds one with a
[Cypress Cloud webhook](/cloud/integrations/webhooks) and a short
[Google Apps Script](https://developers.google.com/apps-script) that receives
each `run.uiCoverage.completed` delivery and writes it to the sheet. No server
to host, and no third-party automation platform in between.

The finished spreadsheet has four tabs:

- **Runs**: one row per report on every branch, with the report status, the UI
  Coverage score, tested and untested elements and links, the number of views,
  whether the run passed its [Run Checks](/cloud/features/checks) on UI
  Coverage and which checks failed, and a link to the report
- **Checks**: one row per Run Checks assertion about UI Coverage, with its
  threshold, the measured value, and a link to investigate a failure
- **Main branch**: a line chart of the UI Coverage score that marks each run
  that failed a UI Coverage check, a line chart of untested elements and links,
  and a table of the latest runs, for runs on `main`
- **Main branch data**: the `QUERY` formulas that feed those charts

The matching guides for [test results](/cloud/guides/google-sheets-trends) and
[Cypress Accessibility](/accessibility/guides/google-sheets-trends) build the
same sheet from their own webhooks, so you can run any combination of them.

## Prerequisites for the Google Sheets webhook receiver

- A Cypress Cloud project that records runs with
  [UI Coverage](/ui-coverage/get-started/introduction). For the **Checks** tab,
  the project needs [Run Checks](/cloud/features/checks) with
  `uiCoverage.score.min` or `uiCoverage.untestedElements.max` assertions.
  Without them, the tab stays empty.
- Permission to manage webhooks on the project: **Owner**, **Org Admin**, or
  **Team Admin**. See [Getting started](/cloud/integrations/webhooks#Getting-started).
- A Google account that can deploy an Apps Script web app with access set to
  **Anyone**. Some Google Workspace admins turn that setting off for their
  domain.

## How the Apps Script receiver handles Cypress Cloud deliveries

The webhook subscribes to `run.uiCoverage.completed`, which Cypress Cloud sends
when a run's UI Coverage report finishes processing, and again if the report is
regenerated. See the
[`run.uiCoverage.completed` payload](/cloud/integrations/webhooks#Payload) for
every field.

## Step 1: Create the spreadsheet and add the script

1. Create a new Google Sheet. Name it after your project, for example
   "UI Coverage trends".
2. Click **Extensions** > **Apps Script**. The editor opens with an empty
   `Code.gs` file bound to the spreadsheet.
3. Replace the contents of `Code.gs` with the following script and click
   **Save**.

```js title="Code.gs"
const RUNS_SHEET = 'Runs'
const CHECKS_SHEET = 'Checks'
const CHARTS_SHEET = 'Main branch'
const DATA_SHEET = 'Main branch data'
const TREND_BRANCH = 'main'

// run.uiCoverage.completed carries final results for the uiCoverage.*
// assertions in your Run Checks.
const ASSERTION_PREFIX = 'uiCoverage.'

const RUN_HEADERS = [
  'Completed at',
  'Project ID',
  'Run number',
  'Branch',
  'Run status',
  'Report status',
  'UI Coverage',
  'Untested elements',
  'Untested links',
  'Tested elements',
  'Tested links',
  'Views',
  'Partial report',
  'UI Coverage checks',
  'Failed checks',
  'Report URL',
]

const CHECK_HEADERS = [
  'Completed at',
  'Project ID',
  'Run number',
  'Branch',
  'Check',
  'Check status',
  'Assertion',
  'Assertion status',
  'Threshold',
  'Measured',
  'Matched',
  'Failed matches',
  'Scope',
  'Investigate',
]

// Cypress Cloud POSTs each run.uiCoverage.completed delivery here.
function doPost(e) {
  const token =
    PropertiesService.getScriptProperties().getProperty('WEBHOOK_TOKEN')
  if (!token || e.parameter.token !== token) {
    console.warn('Ignored a request with a missing or wrong token')
    return reply('ignored')
  }

  const run = JSON.parse(e.postData.contents)
  if (typeof run.runNumber !== 'number' || !run.projectId || !run.uiCoverage) {
    console.warn(
      'Ignored a body that is not a run.uiCoverage.completed delivery'
    )
    return reply('ignored')
  }

  // Two deliveries can arrive at once. The lock keeps them from writing
  // the same rows twice.
  const lock = LockService.getScriptLock()
  lock.waitLock(5000)
  try {
    upsertRun(run)
    replaceChecks(run)
  } finally {
    lock.releaseLock()
  }

  return reply('ok')
}

function runRow(run) {
  const report = run.uiCoverage

  return [
    completedAt(run),
    run.projectId,
    run.runNumber,
    run.commitBranch || '',
    run.status,
    report.status,
    cell(report.coverage),
    cell(report.untestedElementsCount),
    cell(report.untestedLinksCount),
    cell(report.testedElementsCount),
    cell(report.testedLinksCount),
    cell(report.viewCount),
    report.isPartialReport,
    ...checkSummary(run),
    report.reportUrl,
  ]
}

// The Cypress Cloud CLI has no UI Coverage command, so link to the report.
// Cloud MCP can also read the report for an AI assistant.
function investigate(run) {
  return run.uiCoverage.reportUrl
}

// ---- Shared by every Cypress Cloud webhook sheet ----

// One row per run. A retry, a redelivery, or a reprocessed report for a run
// that already has a row overwrites that row instead of adding another.
function upsertRun(run) {
  const sheet = sheetNamed(RUNS_SHEET)
  const row = runRow(run)
  const index = runRowIndexes(sheet, run)[0]

  if (index === undefined) {
    sheet.appendRow(row)
  } else {
    sheet.getRange(index, 1, 1, row.length).setValues([row])
  }
}

// One row per assertion. A later delivery for the same run replaces them.
function replaceChecks(run) {
  const sheet = sheetNamed(CHECKS_SHEET)
  runRowIndexes(sheet, run)
    .reverse()
    .forEach((index) => sheet.deleteRow(index))

  const rows = checkRows(run)
  if (rows.length) {
    sheet
      .getRange(sheet.getLastRow() + 1, 1, rows.length, rows[0].length)
      .setValues(rows)
  }
}

function checkRows(run) {
  return sheetAssertions(run).map(({ check, assertion }) => {
    const matched = assertion.matched || {}
    return [
      completedAt(run),
      run.projectId,
      run.runNumber,
      run.commitBranch || '',
      check.name,
      check.status,
      assertion.type,
      assertion.status,
      assertion.threshold,
      cell(matched.measuredValue),
      cell(matched.count),
      cell(matched.failedCount),
      assertion.filter ? assertion.filter.label : 'All',
      assertion.status === 'failed' ? investigate(run, assertion) : '',
    ]
  })
}

// Every assertion this sheet records, paired with the check it belongs to.
function sheetAssertions(run) {
  const checks = (run.checks && run.checks.checks) || []
  return checks.flatMap((check) =>
    check.assertionResults
      .filter((assertion) => assertion.type.startsWith(ASSERTION_PREFIX))
      .map((assertion) => ({ check, assertion }))
  )
}

// The run's result on this sheet's assertions, whatever the score, and the
// checks that failed one. Checks that don't apply to the run are left out.
function checkSummary(run) {
  const results = sheetAssertions(run).filter(
    ({ check }) => check.status !== 'not-applicable'
  )
  if (!results.length) {
    return ['', '']
  }

  const statuses = results.map(({ assertion }) => assertion.status)
  const result =
    ['failed', 'errored', 'unavailable', 'pending'].find((status) =>
      statuses.includes(status)
    ) || 'passed'
  const failedChecks = results
    .filter(({ assertion }) => assertion.status === 'failed')
    .map(({ check }) => check.name)

  return [result, [...new Set(failedChecks)].join(', ')]
}

// Row numbers whose Project ID (column B) and Run number (column C) match.
function runRowIndexes(sheet, run) {
  const lastRow = sheet.getLastRow()
  if (lastRow < 2) {
    return []
  }

  const indexes = []
  sheet
    .getRange(2, 2, lastRow - 1, 2)
    .getValues()
    .forEach(([projectId, runNumber], i) => {
      if (projectId === run.projectId && Number(runNumber) === run.runNumber) {
        indexes.push(i + 2)
      }
    })
  return indexes
}

function completedAt(run) {
  return new Date(run.completedAt || run.createdAt)
}

// A null metric becomes an empty cell, which QUERY treats as no value
// rather than as zero.
function cell(value) {
  return value === null || value === undefined ? '' : value
}

function sheetNamed(name) {
  const spreadsheet = SpreadsheetApp.getActiveSpreadsheet()
  return spreadsheet.getSheetByName(name) || spreadsheet.insertSheet(name)
}

// HtmlService answers the request with a 200. ContentService answers with
// a 302 redirect, which Cypress Cloud records as a failed delivery.
function reply(message) {
  return HtmlService.createHtmlOutput(message)
}

// ---- Setup: run once from the editor ----

// Creates the sheets, the trend queries, and the charts. Running it again
// rebuilds the charts and their data, and leaves recorded rows alone.
function setup() {
  writeHeaders(RUNS_SHEET, RUN_HEADERS)
  writeHeaders(CHECKS_SHEET, CHECK_HEADERS)

  // A and B: UI Coverage. C: UI Coverage again, only where the run failed a
  // UI Coverage check. D: the check result. F to H: untested elements and links.
  const data = sheetNamed(DATA_SHEET)
  data.clear()
  const where = `D = '${TREND_BRANCH}' and G is not null order by A`
  data
    .getRange('A1')
    .setFormula(`=QUERY(${runsRange()}, "select A, G where ${where}", 1)`)
  data.getRange('C1').setValue('Failed a UI Coverage check')
  data
    .getRange('C2')
    .setFormula(
      '=ARRAYFORMULA(IF(A2:A = "", , IF(D2:D = "failed", B2:B, NA())))'
    )
  data
    .getRange('D1')
    .setFormula(`=QUERY(${runsRange()}, "select N where ${where}", 1)`)
  data
    .getRange('F1')
    .setFormula(`=QUERY(${runsRange()}, "select A, H, I where ${where}", 1)`)

  const charts = sheetNamed(CHARTS_SHEET)
  charts.getCharts().forEach((chart) => charts.removeChart(chart))
  addChart(charts, data.getRange('A:C'), 1, {
    title: `UI Coverage and failed checks on ${TREND_BRANCH}`,
    vAxisTitle: 'UI Coverage',
    series: [{}, FAILED_CHECK_MARKER],
    options: { vAxis: { minValue: 0, maxValue: 100 } },
  })
  addChart(charts, data.getRange('F:H'), 20, {
    title: `Untested elements and links on ${TREND_BRANCH}`,
    vAxisTitle: 'Untested',
    series: [{}, {}],
  })
  addLatestRuns(charts, 39, 'A, C, G, H, I, N, O')
  SpreadsheetApp.getActiveSpreadsheet().setActiveSheet(charts)
}

function writeHeaders(name, headers) {
  const sheet = sheetNamed(name)
  sheet.getRange(1, 1, 1, headers.length).setValues([headers])
  sheet.getRange(1, 1, 1, headers.length).setFontWeight('bold')
  sheet.setFrozenRows(1)
}

// Anchors the chart in column A, so it starts at the left edge of the sheet.
// Each series gets its own marker shape and line style as well as a color,
// so the chart reads without color.
function addChart(
  sheet,
  range,
  row,
  { title, vAxisTitle, series, options = {} }
) {
  const builder = sheet
    .newChart()
    .setChartType(Charts.ChartType.LINE)
    .addRange(range)
    .setNumHeaders(1)
    .setPosition(row, 1, 0, 0)
    .setOption('title', title)
    .setOption('width', 900)
    .setOption('height', 360)
    .setOption('legend', { position: 'top' })
    .setOption('hAxis', { title: 'Run completed' })
    .setOption('vAxis', { title: vAxisTitle, ...options.vAxis })
    .setOption(
      'series',
      Object.fromEntries(
        series.map((style, i) => [i, { ...SERIES_STYLES[i], ...style }])
      )
    )
  sheet.insertChart(builder.build())
}

// Each color reaches at least 3:1 contrast against the white chart
// background. The marker shapes and dash patterns differ too.
const SERIES_STYLES = [
  { color: '#0072B2', pointShape: 'circle', pointSize: 6 },
  {
    color: '#D55E00',
    pointShape: 'triangle',
    pointSize: 7,
    lineDashStyle: [8, 4],
  },
  {
    color: '#007A5A',
    pointShape: 'square',
    pointSize: 6,
    lineDashStyle: [2, 3],
  },
  {
    color: '#A8326E',
    pointShape: 'diamond',
    pointSize: 7,
    lineDashStyle: [8, 3, 2, 3],
  },
]

// Marks each run that failed one of this sheet's Run Checks assertions: a
// large dark triangle with no line, plotted at the run's score.
const FAILED_CHECK_MARKER = {
  color: '#202124',
  pointShape: 'triangle',
  pointSize: 12,
  lineWidth: 0,
}

// The latest runs as plain text under the charts, so every result, including
// the Run Checks outcome, can be read without the charts.
function addLatestRuns(sheet, row, columns) {
  sheet
    .getRange(`A${row}`)
    .setValue(`Latest runs on ${TREND_BRANCH}`)
    .setFontWeight('bold')
  sheet
    .getRange(`A${row + 1}`)
    .setFormula(
      `=QUERY(${runsRange()}, "select ${columns} where D = '${TREND_BRANCH}' order by A desc limit 20", 1)`
    )
}

// Runs!A:<last column>, from the number of headers.
function runsRange() {
  return `${RUNS_SHEET}!A:${String.fromCharCode(64 + RUN_HEADERS.length)}`
}
```

If your default branch has another name, such as `master` or `develop`, change
`TREND_BRANCH` before the next step.

## Step 2: Run the setup function to build the sheets and charts

1. In the editor toolbar, choose `setup` from the function menu and click
   **Run**.
2. Google asks you to authorize the script to edit your spreadsheets. Review
   the request and allow it.

The spreadsheet now has **Runs** and **Checks** tabs with frozen headers, a
**Main branch data** tab, and a **Main branch** tab with two empty charts
anchored at its left edge. The data tab selects the `main` runs that have a UI
Coverage score, in date order:

- Columns A to C: the completion time, the UI Coverage score, and the score
  again for each run that failed a UI Coverage check, which the first chart
  draws as a line with a large triangle on each failed run
- Column D: each run's **UI Coverage checks** result, which column C reads
- Columns F to H: the completion time and the untested element and link
  counts, which feed the second chart

<GoogleSheetsChartAccessibility />

The charts fill in as rows arrive. Running `setup` again rebuilds both charts
and their data, so make lasting style changes in the script's `addChart` calls,
or stop running `setup` once the charts look the way you want.

## Step 6: Send a test delivery to the spreadsheet

1. On the webhook row, click **Send test** and choose
   `run.uiCoverage.completed`.
2. Open **Recent deliveries** from the webhook's **Options (⋯)** menu. The test
   delivery shows **Delivered**.
3. In the spreadsheet, the **Runs** tab has a row for run `42` of project
   `abc123`, and the **Main branch** charts show one point. When the sample
   includes Run Checks results with `uiCoverage.*` assertions, the **Checks**
   tab has a row for each.

Every test delivery carries the same sample run, recorded against `main`, so
sending another test updates that row instead of adding one. New rows arrive
with real runs, each under its own run number. Delete the test rows from
**Runs** and **Checks** once you've confirmed they arrived, so they don't sit in
your trend.

If no row appears, open **Executions** in the Apps Script editor's sidebar to
see the request and any error the script logged. A
`Ignored a request with a missing or wrong token` warning means the `token` in
the Payload URL doesn't match the `WEBHOOK_TOKEN` property.

From here, every UI Coverage report adds a row, and every `main` report with a
score adds a point to the charts.

## Investigate a failed Run Check from the sheet

The [Cypress Cloud CLI](/cloud/integrations/cloud-cli) has no UI Coverage
command, and Apps Script can't run the CLI in any case: it runs in Google's
cloud, with no terminal and no Node.js. For each failed assertion, the script
writes the UI Coverage report URL in the **Investigate** column instead. Open it
to see the untested elements in each view.

To hand the report to an AI assistant, give it that URL and use
[Cloud MCP](/cloud/integrations/cloud-mcp), which reads UI Coverage reports.

## Keep these behaviors in mind

<GoogleSheetsWebhookBehaviors />

- **Reports that couldn't be processed leave empty cells.** When the report's
  `status` is `processing_failed`, its metrics are `null`, the row's metric
  cells stay empty, and the trend queries skip the row instead of charting it
  as zero.
- **Partial reports can dip.** When **Partial report** is `TRUE`, the report is
  missing data for some specs, and the score covers only what was captured.
  Add `and M = false` to the trend queries to leave those runs out.
- **A regenerated report replaces the original.** Its delivery carries the same
  run number, so its row and its **Checks** rows overwrite the earlier ones.

## Google Sheets trends and Enterprise Reporting

The sheet records one project as each report arrives, along with the Run Checks
results that Enterprise Reporting doesn't show. On an Enterprise plan,
[Enterprise Reporting](/cloud/features/analytics/enterprise-reporting#UI-Coverage)
covers what a webhook payload can't:

- UI Coverage for every project in your organization, compared side by side
  and filtered by project and branch
- History for your whole data retention period, including runs from before you
  added the webhook
- No script, deployment, or token to maintain

To fill in the sheet's history, the
[Data Extract API](/cloud/integrations/data-extract-api#UI-Coverage)
`ui-coverage-details` report returns the UI Coverage of every earlier run, with
its run number and branch. Enterprise Reporting includes runs through the end
of the previous day (UTC), so the sheet is where today's reports show up first.

## Extend the Google Sheets dashboard

The **Runs** tab is plain data, so most extensions need only a formula:

- **Chart link coverage.** Add a column that divides **Tested links** by the sum
  of **Tested links** and **Untested links**, query it on **Main branch data**,
  and add it to the first chart.
- **Highlight a drop.** Add a conditional-format rule to the **UI Coverage**
  column that colors a cell when it is lower than the cell above it.
- **Compare branches.** Build a pivot table on **Runs** with **Branch** as rows
  and the average **UI Coverage** as values.
- **Watch app growth.** Chart **Views** next to **UI Coverage** to tell new,
  untested pages apart from tests that stopped covering existing ones.
